Brand Essence

Boundary-aware mobility.

Crosswake is the clean trail left by a Phoenix app crossing into mobile runtimes without pretending the boundary disappeared. Every element of the brand communicates: explicit, honest, durable, technically controlled.

Personality Traits

Explicit
Everything is named

Routes, runtimes, capabilities, policies — nothing is implicit.

Calm
No hype, no magic

No "seamless," no "magic bridge," no "write once." Calm confidence.

Technical
Designed for maintainers

For Phoenix engineers who read source code and care about correctness.

Honest
Failure modes first

Failure modes are documented before features. Native work still requires native work.

OSS-generous
Maintainer judgment

The maintainer shares judgment, not just syntax.

Precise
Measurements, contracts

Verdicts, not approximations. Contracts, not suggestions.

Anti-Traits

Trait to avoid Why
Salesy No "powerful," "seamless," "next-generation."
Evasive Never hide that native development still requires native work.
Trend-chasing No chasing visual fashions that won't survive two OSS cycles.
Omniscient Never claim "offline just works" or "all screens are one runtime."

Design Principles

  1. The diagram is the product. Runtime boundaries made visible are the core value.
  2. Contrast as contract. Accessible color is not a feature; it is the brand.
  3. Technical quiet. Docs should be quieter than marketing; marketing should be honest enough to belong next to docs.
  4. One color family per runtime. The palette gives each runtime a distinct signal without competing.

Misuse Examples

Each of these uses is rejected. Crossing one out signals it must never appear in production.

REJECTED
Cyan recolor

Contradicts React Native avoidance. Crosswake never uses bright cyan as a hero accent.

REJECTED
Mark inside a blob

Never place the mark inside a bounding shape, drop-shadow card, or gradient blob.

REJECTED
Stretched / rotated

The crossing angle is the brand geometry. Never stretch or rotate off the 20° wake angle.

REJECTED
Subtitle as main lockup

The subtitle variant carries the tagline — use only in brand introduction contexts. Not as the primary mark.

Design Tokens

The Crosswake token system uses two tiers. No component tier — deliberate to prevent naming churn and keep the public contract stable.

Tier 1
Primitive tokens

Internal only. Raw hex values. Never reference in component CSS. Named --cw-primitive-{family}-{weight}.

17 total (16 palette + Stone 600)

Tier 2
Semantic tokens

Public contract. Named --cw-{role}-{variant}. These are the only tokens component CSS should reference.

27 total (surface/text/action/border/status/runtime)

Source Files

tokens/crosswake.tokens.json tokens/tokens.css
Edit policy: Always edit crosswake.tokens.json and run node brandbook/tools/compile-tokens.js. The tokens.css file is generated — its header reads "GENERATED — do not edit."

Worked Examples

/* 1. Body text on light background */ color: var(--cw-text-default); /* resolves → --cw-primitive-current-950 (#09141A) */ background: var(--cw-surface-default); /* resolves → --cw-primitive-foam-50 (#F7F1E6) */
/* 2. Primary button (light mode) */ background: var(--cw-action-bg); /* resolves → wake-700 (#2B756A) */ color: var(--cw-action-fg); /* resolves → white (#FFFFFF) */ outline: 2px solid var(--cw-action-focus-ring); /* focus: brass-500 */
/* 3. Runtime badge — offline island */ background: var(--cw-runtime-offline); /* resolves → kelp-800 (#123B36) */ color: var(--cw-text-inverse); /* resolves → foam-50 (#F7F1E6) */

Only semantic tokens flip in dark mode; primitives never change. System dark mode uses @media (prefers-color-scheme: dark); explicit toggle uses [data-theme="dark"].

Motifs

The Crosswake visual language uses three motifs. Restraint is the point — these appear sparse, never decorative for decoration's sake.

Wake Seams

Diagonal or gently curved line groups implying movement through a runtime boundary. 2–4 parallel lines, rounded caps, 1.5–3px stroke. Used in hero backgrounds, diagram dividers, and section accents.

Used in hero backgrounds, section dividers, empty states. Never behind dense text.

Runtime Lanes

Horizontal or vertical lanes showing which runtime owns each route. These diagrams should feel like technical maps, not marketing infographics.

Used in architecture diagrams, runtime ladder, docs. Route lines cross lane boundaries explicitly.

Usage rule: Motifs appear sparse. A wake seam in a hero does not need to be accompanied by runtime lanes. Sounding lines (thin contour-like background lines, opacity <12%) may complement but never compete with content. Never use motifs as watermarks behind dense text.

Voice & Microcopy

Write like a careful maintainer: precise, short, helpful, candid. Prefer operational truth over hype. Explain the boundary. Use metaphor sparingly.

Write This / Not This

Write this Do not write this
"This route requires a native screen in app runtime >= 0.3.0." "Native mobile with no native work."
"Cached read-only means the user can view stale data, not submit changes." "Everything works offline."
"Use an offline island when the interaction loop must continue without the server." "Just add Crosswake."
"The camera capability is requested at point of use." "Magic bridge."
"The bridge message is semantic; progress events stay native." "One codebase for every app."
"This action needs the server before it can be committed. The draft was saved locally." "Never write Swift or Kotlin again."

Runtime mismatch
This route requires native runtime 0.3.0 or newer. Update the app or choose another route.
Capability unavailable

This action needs the server before it can be committed. The draft was saved locally.

Bridge payload rejected
Crosswake rejected this bridge message because it does not match the registered contract.
