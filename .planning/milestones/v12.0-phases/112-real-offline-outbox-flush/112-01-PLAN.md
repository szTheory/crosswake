<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser /offline island → POST /study/sync | Untrusted client-emitted sync events cross into the server; the server (Study.sync_events/1 + ReviewEvent.changeset) is the sole validation authority |
| Client-generated client_mutation_id | An idempotency key (dedup handle), NOT an auth token — it carries no authorization meaning |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-112-01 | Tampering | client_mutation_id / card_id / rating in POST body | accept (client) / mitigate (server, out of scope) | Client does NOT validate on the server's behalf (PITFALLS.md: no offline-validation-pretending-to-be-server-validation). The server's ReviewEvent.changeset validates rating ∈ {good,hard}, integer card_id, unique client_mutation_id — unchanged and authoritative. Client only emits well-formed values; a tampered value is rejected server-side and surfaces in data.rejected. |
| T-112-02 | Spoofing | client_mutation_id as identity | accept | The id is an idempotency key only. on_conflict:nothing means a replayed id is a no-op insert, not an auth bypass. No mitigation needed; documented so no one later treats it as a credential. |
| T-112-03 | Denial of Service | repeated/duplicate flush POSTs from the three triggers | mitigate | Single-flight `flushing` guard prevents overlapping flushes; server idempotency makes any double-POST a no-op. Failed batches stay queued (bounded by user review actions), not retried in a tight loop. |
| T-112-04 | Information Disclosure | sync status surfaced in #status live-region | accept | Status text is non-sensitive (counts + state words); aria-live="polite" announces routine sync, no PII. |
| T-112-SC | Tampering | npm/pip/cargo installs | n/a | No package installs in this plan — zero new dependencies; crypto.randomUUID and IndexedDB are browser built-ins. No legitimacy gate required. |
</threat_model>
