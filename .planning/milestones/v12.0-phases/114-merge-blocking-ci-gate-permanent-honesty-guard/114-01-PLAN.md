<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| future PR → main CI | An untrusted future code change crosses into the merge gate; the gate's job structure is the only thing forcing it to run the honest checks |
| MIX_ENV=test build → MIX_ENV=prod build | A shared `_build`/cache key would let a :test-compiled router beam leak into the prod-absence proof, making GUARD-02 pass vacuously |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-114-01 | Tampering | aggregator `needs:`/`if: always()` | mitigate | re-actors/alls-green fails on any skipped/failed voting job; a plain `needs:` + path filter would let a skipped required job report success — alls-green closes that |
| T-114-02 | Information Disclosure | shared `_build`/cache across MIX_ENV | mitigate | env-scoped cache keys build-test-* / build-prod-* + `rm -rf _build/prod` force a clean prod compile so a :test router beam cannot make GUARD-02 lie |
| T-114-03 | Elevation of Privilege | workflow `permissions:` | mitigate | `permissions: { contents: read }` — the gate needs no write scope |
| T-114-SC | Tampering | npm/pip/cargo installs | mitigate | No new package installs in this plan; setup-beam + actions are SHA/version-pinned; honesty/route guards (plans 02/03) are the structural backstop |
</threat_model>
