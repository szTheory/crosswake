## Native capture findings (2026-06-23 — local execution of the new pipeline)

Attempting the local capture on this Mac (full Xcode 26.5, Docker up) closed
**COLL-02** and surfaced real defects that block **COLL-01**. Three bugs were
found *by actually running things* — none were catchable by the static drift
tests:

1. **`bin/see-it-run.sh` printf `--` bug (FIXED, commit ca90306).** The four
   dash-divider lines used `printf "----\n"`; `printf` reads the leading `--` as
   a flag (`printf: --: invalid option`), truncating the banner after the route
   list. Fixed to `printf '%s\n' "----"`. Surfaced by rendering the GIF.

2. **iOS Dev scheme did not build on Xcode 26 — FIXED (commit 1bc4680).**
   `xcodebuild -scheme Dev -configuration Debug-Dev` failed: *"Multiple commands
   produce `…/CrosswakeShell.app/route_activation.json`"* — the prod Resources
   copy and the Phase-126 "Copy Dev Fixture" Run Script both produced that bundle
   path, which Xcode 26's strict build system rejects. Phase 126 only ran
   `xcodebuild -list` (structure), never built the scheme. **Fix (additive,
   prod-untouched):** dropped the Run Script's declared `outputPaths` (prod
   Resources copy is the sole declared producer; the Debug-Dev-only script still
   overwrites post-Resources) + `alwaysOutOfDate=1`. Verified: error gone; the Dev
   scheme now builds to **parity with the prod CrosswakeShell scheme**. Phase-126
   `native_dev_wiring` + `contract_drift` guards still green; pbxproj lints.
   **Newly-exposed environmental blocker (affects BOTH schemes, not Dev-specific):**
   the published `crosswake-shell-core-ios@0.1.2` Swift module is incompatible
   with the local Xcode 26 / Swift 6 toolchain (`cannot find type
   'TransferCoordinator'` …) — confirmed identical on the prod scheme. So local
   iOS capture is blocked on a toolchain/published-package mismatch, not on the
   Dev wiring. CI's pinned toolchain / clean-room-proof builds the package
   successfully, so CI capture is unaffected.

3. **Capture builds the PROD shell, not the Dev shell.**
   `capture-native-collateral.mjs` drives the verify scripts' prod scheme/flavor
   (`CrosswakeShell` / connected prod tests), not the Dev variants that point at
   `localhost:4700` / `10.0.2.2:4700`. Even once (2) is fixed, the capture must
   be taught to build `Debug-Dev` / `installDevDebug` or it screenshots the wrong
   (`example.crosswake.invalid`) shell. Flagged inline in
   `see-it-run-collateral.yml`.

Also noted: the banner's example device `name=iPhone 16` is stale on Xcode 26
(this Mac has the iPhone 17 family) — doc-only, copy-paste users adjust it.
Android could not be attempted locally: the entire Android SDK/`adb`/emulator
toolchain is absent (only `openjdk@17` present); `verify_generated_android_shell.sh`
auto-provisions it in CI, but locally that is a multi-GB install + AVD boot.
