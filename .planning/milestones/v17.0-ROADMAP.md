## Overview

Finished the companion family: extracted the three remaining in-tree companions — `sigra` (auth), `chimeway` (notifications), `threadline` (audit observer) — into standalone independently-versioned `crosswake_*` Hex packages, module names preserved throughout (`Crosswake.Companions.Sigra.*` / `.Chimeway.*`, `Crosswake.Threadline.*`) so extraction is non-breaking. Two reframings drove the design: (a) sigra/chimeway were **compile-coupled** into core at four sites (telemetry / route_gate / support_matrix / doctor) → Phase 136 inverted all four onto a runtime `:companions` registry seam (optional `@behaviour` callbacks + `function_exported?/3`), so core now compiles `--warnings-as-errors` with **no** companion present; (b) the "chimeway → sigra AuthContext" dependency was a **myth** (chimeway uses `auth_context: map()`) → the compatibility matrix stays O(N), companions depend only on core, and each versions independently. The family publishes to Hex in strict dependency order — **core `0.2.0` first** (the decoupling API companions compile against), then sequential `sigra → chimeway → threadline`.

## Milestone Summary

**Delivered:** The Crosswake companion family is now four independently-versioned first-party Hex packages plus the audit observer, all LIVE on Hex:

| Package | Version | Role |
|---|---|---|
| `crosswake` | **0.2.0** | core (the v17.0 decoupling API) — Hex + hexdocs + Android Maven |
| `crosswake_sigra` | **0.1.1** | auth companion |
| `crosswake_chimeway` | **0.1.0** | notification companion |
| `crosswake_threadline` | **0.1.0** | audit observer (telemetry-by-name) |

**Key accomplishments:**

- **Core decoupling via runtime registry inversion (DECOUPLE):** All four compile-time core→companion coupling sites (telemetry, route_gate, support_matrix, doctor) inverted onto a `:companions` registry seam using optional `@behaviour` callbacks + `function_exported?/3`. Core compiles `--warnings-as-errors` with no companion present; auth-predicated routes fail **closed** (`:dependency_missing`) when no `auth_authority?/0` companion is registered; a companion that raises is rescued and denies. A curated universal PII floor (auth-token/session/identity) is always applied, layered above per-companion runtime aggregation.
- **Three standalone extractions, non-breaking (SIGRA/CHIME/THREAD):** sigra, chimeway, threadline each moved to `packages/crosswake_*/` with own `mix.exs`/`@version`, module names preserved. sigra emits `Crosswake.Compatibility.Finding` at its boundary (`Crosswake.Shell.Denial` stays core-private); chimeway proven sigra-free by a vacuity-safe clean-room lane (the sigra dep was a myth — `auth_context: map()`); threadline observes purely via `:telemetry.attach_many` by event-name with a crash-isolated (`try/rescue`) append-only PII-free ledger.
- **Family discipline (FAMILY):** O(N) compat-matrix rows (single `Requires crosswake >= X` column, no inter-companion columns) with drift guards; per-package Side-A "declared ⇔ emitted" telemetry contract tests (core's hardcoded `>= 24` count assertion replaced by a shape assertion); extraction recipe gained a "Step 0: core decoupling" prerequisite + all-`lib/` stale-reference grep guard; COMPANION-PUBLISH-RUNBOOK authored.
- **Core-first ordered publish (FAMILY-05):** Discovered mid-flight — companions compile against unpublished v17.0 core (`KeyError :code`). Resolved by publishing **core `0.2.0` first** (a `release-as: "0.2.0"` pin forced the intended minor over release-please's pre-major `0.1.3` patch-bump), bumping every companion floor `~> 0.1` → `~> 0.2`, then publishing companions sequentially (one Release PR each, never batched) so each resolves against published core 0.2.0 — the real version-mismatch check the path-dep dress rehearsal could not catch.
