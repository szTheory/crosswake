<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| evidence input -> backend authority contract | Untrusted maps or client/native payloads attempt to cross into backend-owned session authority. |
| backend denial facts -> shell denial envelope | Internal auth evaluation details cross into a user-visible denial payload. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-54-01 | Spoofing | `Crosswake.Companions.Sigra.Contracts` | mitigate | Reject authority-setting attrs from evidence inputs and require backend-owned `SessionAuthorityLane` construction per D-01 and D-05. |
| T-54-02 | Tampering | `SessionAuthorityLane` timestamps/version fields | mitigate | Normalize timestamps and keep closed vocab/field validation so stale, malformed, or forged authority state cannot silently pass downstream evaluators per D-02/D-03/D-06. |
| T-54-03 | Information Disclosure | `Crosswake.Companions.Sigra.DenialCodes` + `Crosswake.Shell.Denial` | mitigate | Allowlist detail keys, keep user messages generic, and forbid session ids, actor ids, provider payloads, passkey ids, and tokens per D-09/D-10. |
| T-54-04 | Elevation of Privilege | Phase scope boundary | mitigate | Fail the plan if any contract work introduces handoff, step-up ceremony, OAuth return, passkey return, or token-rotation authority logic reserved for Phases 55-57. |
</threat_model>
