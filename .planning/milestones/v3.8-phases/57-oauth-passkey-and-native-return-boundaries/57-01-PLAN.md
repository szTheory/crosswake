Passkey must require `:challenge`, `:origin`, `:rp_id`, `:user_verification`, `:expiry`, and `:replay`, with `:link_verification` required for verified-link transports. Native auth must require `:callback_binding`, `:link_verification`, `:expiry`, and `:replay`. Auth-return routes must default to `security: :sensitive` and `auth_posture: :strict_recent` unless already stricter. Sensitive auth-return routes must reject `:custom_scheme`. Serialize route-local `auth_return` into manifest route entries as `RouteAuthReturn` with only `kind`, `transport`, `return_route_id`, and sorted or stable `validates` values. Add manifest-known return-route binding proof: when the compiled manifest or manifest builder receives an auth-return route whose `return_route_id` does not match a route id in the same route set, the route must fail closed through validation or a deterministic proof assertion instead of treating the unknown id as a decorative string.</action>

| T-57-01 | Spoofing | Route policy | Provider-specific terms imply first-party provider support or route authority. | Closed provider-neutral `kind` vocabulary and explicit provider-term rejection. |
| T-57-02 | Tampering | Return target | Raw `return_to` or callback URL is treated as Crosswake route authority. | Require `return_route_id` and manifest-visible route-local serialization. |

| T-57-04 | Repudiation | Manifest truth | Shell/operator cannot inspect auth-return boundary requirements. | Serialize the seam into manifest entries with explicit validation requirements. |
