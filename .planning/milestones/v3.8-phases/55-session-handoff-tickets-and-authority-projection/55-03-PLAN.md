<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internal auth/audit truth -> public docs and diagnostics | Backend support data crosses into human-readable docs, readiness, and operator output. |
| proof fixtures -> release/support claims | Stored JSON and rendered guide text cross into shipped truth assertions. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55-10 | Information Disclosure | doctor/operator/support/docs surfaces | mitigate | Surface only canonical denial codes, safe detail keys, and high-level audit field names; do not expose raw ticket refs, digests, session refs, actor/org/device identifiers, or audit payloads per D-22/D-23. |
| T-55-11 | Repudiation | support matrix / proof fixtures | mitigate | Keep support truth, renderer output, guides, and fixtures sourced from canonical accessors and enforce parity in merge-blocking tests so shipped claims have durable evidence. |
| T-55-12 | Misrepresentation | docs and readiness wording | mitigate | Make non-claims explicit for Phase 56 ceremony, Phase 57 returns, refresh-token helpers, provider/device proof, and native auth UI so public truth cannot overclaim later work. |
| T-55-13 | Spoofing | shell/runtime authority wording | mitigate | State plainly that the bridge and shell are not auth authorities and that handoff only upgrades authority through backend redemption and projected `SessionAuthorityLane`. |
| T-55-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs are part of this plan. |
</threat_model>
