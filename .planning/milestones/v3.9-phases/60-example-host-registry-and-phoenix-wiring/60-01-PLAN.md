<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bridge/provider evidence -> example-host persistence | Raw token and provider metadata arrive from untrusted runtime/provider sources and must be redacted before storage. |
| backend context -> binding schema | Auth/session scope is backend-owned and must not be inferred from token possession. |
| mutable binding rows -> append-only audit rows | Lifecycle state changes must preserve audit truth instead of overwriting or deleting it. |
| example-host persistence -> proof lane | The proof must detect schema/index drift before later lifecycle code relies on it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-60-01A | Information Disclosure | `token_binding.ex`, `metadata_sanitizer.ex`, binding migration | mitigate | Store only `token_ref`/`token_fingerprint`, drop forbidden metadata keys, and prove no raw-token columns or metadata survive. |
| T-60-01B | Spoofing | `token_binding.ex` scope validation | mitigate | Require backend-owned `subject_scope` rules so token evidence cannot smuggle subject/session identity. |
| T-60-01C | Tampering | binding migration partial unique indexes | mitigate | Use explicit active fingerprint/session/install partial unique indexes and matching changeset constraints to stop silent multi-authority active rows. |
| T-60-01D | Repudiation | `token_binding_event.ex`, audit migration | mitigate | Create append-only event rows with no cascade-delete path and assert their presence in proof scaffolding. |
| T-60-01E | Information Disclosure | phase proof scaffold | mitigate | Seed raw-token strings in proof inputs and fail if they appear in persisted metadata, inspected structs, or migration schema. |
| T-60-01F | Elevation of Privilege | Phase 60 schema scope | accept with proof | Keep workers/delivery orchestration out of this plan and assert the schema layer only models backend-owned lifecycle state, not provider delivery authority. |
</threat_model>
