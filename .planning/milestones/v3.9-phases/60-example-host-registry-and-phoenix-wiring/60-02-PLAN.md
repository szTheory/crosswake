<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| backend auth/session context -> registry API | Backend-owned identity/session scope must not be replaced by token possession. |
| registry transaction -> mutable/audit tables | Lifecycle writes must stay atomic so state and audit truth cannot diverge. |
| provider feedback -> public lifecycle state | Provider-native facts must normalize into Chimeway reasons without widening support claims. |
| committed transaction -> telemetry | Success telemetry must reflect committed state only and stay redacted. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-60-02A | Spoofing | `registry.ex` context normalization | mitigate | Separate backend context validation from token evidence so tokens cannot choose `subject_ref`, `org_ref`, or `session_ref`. |
| T-60-02B | Tampering | `bind_or_rotate/3` and revocation/pruning flows | mitigate | Use named `Ecto.Multi` steps plus guarded `update_all` checks and same-transaction audit inserts for every lifecycle change. |
| T-60-02C | Repudiation | audit event creation | mitigate | Write append-only `TokenBindingEvent` rows inside the same transaction as every lifecycle change and prove they remain after revocation/pruning. |
| T-60-02D | Information Disclosure | returned result maps and telemetry metadata | mitigate | Build results and telemetry from committed rows only, sanitize metadata, and fail proof if raw token or unsafe identifiers appear. |
| T-60-02E | Information Disclosure | provider feedback mapping | mitigate | Normalize APNs/FCM feedback into canonical Chimeway reasons and prevent provider-native enums from becoming public lifecycle state. |
| T-60-02F | Elevation of Privilege | registry API surface | accept with proof | Keep the registry synchronous and host-owned in Phase 60; background workers remain out of compiled code and are checked in Plan 03. |
</threat_model>
