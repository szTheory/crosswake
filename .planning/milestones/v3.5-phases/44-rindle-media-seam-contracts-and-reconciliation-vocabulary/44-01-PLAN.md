<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Device capture evidence -> Phoenix contracts | Device-reported upload success must remain evidence, not authority |
| Backend verification -> MediaObject availability | Only backend-owned verification may produce `state: :available` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-01 | Elevation of privilege | `CaptureEvidence` fields | mitigate | Validators reject direct `authority_state` or `availability_state` in evidence metadata; tests prove evidence-only shape |
| T-44-02 | Tampering | `MediaObject.state` | mitigate | Closed state vocabulary plus validation rejects unknown states and unavailable backend verification fields |
| T-44-03 | Repudiation | idempotency identity | mitigate | `UploadGrant` and `CaptureEvidence` require `grant_id` plus `idempotency_key`; correlation ids are optional trace metadata only |
| T-44-SC | Tampering | package installs | n/a | No new package manager dependencies in this plan |
</threat_model>
