<objective>
Create the backend-owned Rindle reconciliation vocabulary and evidence ingestion fence,
mirroring `Crosswake.Commerce.Reconciliation` while making availability non-authoritative
from device evidence.

Purpose: MEDIA-02 requires the Rindle seam to prove that device-reported upload success
does not advance media to `:available`; only backend verification can. This plan adds the
reconciliation module and tests that make that invariant mechanical.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Device evidence -> reconciliation | Device success can only create evidence results |
| Reconciliation -> projection | Reconciliation outcomes report workflow state, not media availability |
| Backend verification -> availability | Explicit backend verification is required for `MediaObject.state == :available` |

| T-44-05 | Tampering | replay/idempotency | mitigate | Stable `IdempotencyKey` excludes `correlation_id`; tests prove changed correlation ids still replay |
| T-44-06 | Repudiation | availability transition | mitigate | `verified_media_object/2` requires explicit backend `verification_ref` and `authoritative_at` |
