<critical_correction>
The gap brief / VERIFICATION "Recommended minimal fix set" item 4 describes the discriminating capability vector as "session provides 1.1.0, request demands 1.0.0". That direction is INVERTED for the capability axis. The canonical Elixir semantics at `lib/crosswake/compatibility/compatibility.ex:585` are `compatible_version?(available_version = request.capabilities[cap], required_version = registry[cap].version)` — i.e. the value the REQUEST carries is "provides" and the manifest/session registry value is "demands". Native must mirror this: `SemVer.compatible(provides: request.capabilities[cap], demands: session.capabilities[cap])`. Therefore the discriminating ALLOW vector is **request capability = "1.1.0", session capability = "1.0.0"** (request provides newer than the floor the session demands → allow under `>=`, deny under old `==`). Tasks below use the corrected direction. This is exactly the per-site provides/demands nuance D-03 warns against blind-copying.
</critical_correction>
