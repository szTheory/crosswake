<objective>
Move every CI job that does not need an Apple toolchain off macOS, and put a timeout on every
workflow so one hang cannot starve the macOS pool.

Purpose: this is the single largest and lowest-risk cost reduction available. 20 workflows run on
`macos-*`; the great majority are `mix deps.get` + `compile` + `test` with a `DEVELOPER_DIR` env
that nothing reads. They are not slow — they are **queued**, behind a pool serving roughly five
concurrent macOS jobs while 18 fire at once.

Output: macOS reserved for jobs that genuinely build or sign Apple artifacts, and a structural test
that keeps it that way.
</objective>

## Task 1 — Audit every macOS job, per job, by following its scripts

For each of the 20 workflows with `runs-on: macos-*`, and for **each job** within them, determine
whether it invokes an Apple toolchain: `xcodebuild`, `xcrun`, `simctl`, `swift build`, `swiftc`,
`codesign`, `altool`, `notarytool`.

**Follow every `run:` into the script it calls.** A workflow-level grep is invalid — this is proven
in-repo: `phase18-proof.yml` and `phase79-proof.yml` contain no Apple-toolchain token, and both call
`script/verify_generated_ios_shell.sh`, which exits non-zero without `xcodebuild` at line 14.

Record the result as a table in the summary: workflow, job, verdict, and the **specific line of
evidence** — the file and line that invokes the tool, or the confirmation that no invocation exists
anywhere in the job's transitive script calls.

Known starting points, all requiring confirmation rather than trust:
- **Stays on macOS:** `phase18` (xcodebuild via verify script), `phase79` (same), `release-please`
  (signs/builds Apple artifacts — and is security-sensitive; see constraints).
- **Candidate to move:** `phase5` (explicitly sets `CROSSWAKE_PHASE5_NATIVE_PROOFS: "0"`),
  `phase10`, `phase23`, `phase34`, `phase41`, `phase43`, `phase45`, `phase48`, `phase52`,
  `phase58`, `phase70`, `phase71`, `phase73`, and the `native-behavioral-proof-gate` /
  `native-collateral-advisory` / `see-it-run-collateral` lanes.
- **Special case:** `phase68` runs an Android emulator on macOS. Android emulation belongs on
  **ubuntu with KVM** (`ReactiveCircus/android-emulator-runner` documents this as the supported
  configuration and it is substantially faster). Treat as a move, but verify the emulator actually
  boots on the ubuntu runner before claiming it.

## Task 2 — Move the confirmed-non-Apple jobs to ubuntu

For each job that passed the audit:
- switch `runs-on` to the ubuntu runner already used elsewhere in this repo (match the existing
  pinned label — do not introduce a new runner label),
- delete the `DEVELOPER_DIR` env **only on jobs that moved**. On a job that stays on macOS, leave it
  alone; it may be load-bearing there.
- leave the job `name:` **byte-identical**. Several of these are registered required contexts and
  branch protection matches by string — a rename here silently un-protects the branch.

Move them in reviewable batches, not one 20-file commit. If any job fails on ubuntu, that job stays
on macOS with the failure reason recorded in the summary; **do not** force a move by weakening the
job. A move that changes what a proof asserts is a regression regardless of what it saves.

## Task 3 — Add `timeout-minutes` to the 14 workflows lacking it

`aggregator-negative-control`, `collateral-guard`, `contract-drift-gate`, `hex-publish`,
`ios-mirror-backfill`, `native-behavioral-proof-gate`, `native-collateral-advisory`,
`offline-sync-e2e-gate`, `phase67-proof`, `phase69-proof`, `phase79-proof`,
`release-as-staleness-gate`, `release-please`, `required-checks-audit`.

Do `phase79-proof` first — unbounded `xcodebuild` on a scarce runner is the worst case.

Set each timeout from that workflow's **observed** duration with real headroom (roughly 2-3x
observed maximum), not a uniform guess. A timeout tighter than the natural runtime converts a slow
run into a red required check, which is worse than the hang it prevents. Record observed-vs-chosen
per workflow.

**`release-please.yml` needs care.** It is security-sensitive (REL-05 SHA pinning, two previously
armed fuses). Add a generous timeout; change **nothing** else — in particular its concurrency
(`cancel-in-progress: false`, `queue: max`) is correct as written.

## Task 4 — Lock it in with a structural test

Add `test/crosswake/proof/phase153_1_runner_class_test.exs` asserting:
- every job with `runs-on: macos-*` is on an explicit allowlist, and the allowlist entry carries a
  written justification naming the Apple tool it needs;
- every workflow declares `timeout-minutes`;
- no job outside the allowlist sets `DEVELOPER_DIR`.

Include a negative control proving the assertions fail when violated. This is what stops the next
copy-pasted `phase*-proof.yml` from silently landing back on macOS.
