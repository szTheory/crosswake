## Honest attribution — read this before quoting the wall-clock number

**The 34.9 → 7.1 min figure is real but confounded, and must not be reported as
80 % attributable to this change.**

macOS mean queue fell from 1,071 s to 31 s per job. Nothing in this phase made a
macOS runner start faster — that is ambient GitHub runner availability, and it
differed enormously between the two samples. The baseline run happened to land in
a bad macOS window; the after run landed in a good one.

Decomposing what *is* attributable:

- **Attributable, durable:** billable-equivalent minutes 550 → 259 (**−53 %**).
  This is execution time × runner multiplier and does not depend on queue
  conditions at all. Moving 13 jobs off a 10×-billed runner is the whole of it.
- **Attributable, structural:** 13 jobs are permanently off the macOS queue. The
  real value is not that the pipeline is faster on a good day — it is that
  wall-clock is now **robust to macOS queue spikes**. Had this run hit the
  baseline's 1,071 s mean, the 7 remaining macOS jobs would have contributed
  ~7,500 s of queue instead of the 20 jobs' ~21,400 s.
- **Not attributable:** the specific 7.1 min. Treat it as a best case. A
  defensible expected range under baseline-grade macOS contention is roughly
  12–18 min, still inside the Success Criterion 7 target of **under 15 minutes**,
  but not comfortably. CACHE (153.1-03) is what should make that margin safe.

**Risk checked and cleared:** total execution time did *not* regress on ubuntu
(5,627 → 5,182 s). The concern that ubuntu runners would be slower per-job for
Elixir compile did not materialise.

### Two false positives the audit tool produced

Both were caught by hand-verifying tool output against the workflow files, and
both would have turned a working proof red. This is why the plan forbids
verdict-by-grep.

1. **`phase79 / merge-blocking-v5-proof`** — the script-reference regex missed the
   leading `./` in `run: ./script/verify_generated_ios_shell.sh` (that script
   hard-requires `xcodebuild` at line 14). Fixed the regex to accept `./` and
   `${GITHUB_WORKSPACE}/` prefixes, then re-ran.
2. **`native-behavioral-proof-gate / android-generated-shell-unit`** — a different
   failure mode entirely: no Apple *toolchain*, but a macOS *host* assumption. The
   verify script downloads a JDK from adoptium `.../ga/mac/$(arch)/...` and falls
   back to Homebrew. The pre-existing `# REVIEW FIX finding 2` comment on that
   `runs-on:` line was correct.

**Lesson for 153.1-03 and SEED-007:** "needs macOS" has (at least) two independent
causes — Apple toolchain and macOS host environment. An audit that only greps for
`xcodebuild`/`swift` finds the first and silently misses the second.
