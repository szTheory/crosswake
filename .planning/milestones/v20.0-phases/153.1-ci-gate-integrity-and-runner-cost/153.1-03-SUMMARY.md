# Phase 153.1 · Plan 03 — Summary

**Requirements:** CACHE-01, CACHE-02
**Status:** Complete. Shipped as PRs #94 (repair + composite action, `85158689`) and #95
(adoption across 19 lanes, `cfc25005`). Measurements in `153.1-RESULTS.md`.

## Headline: a 93 % hit rate that bought 2 %

Measured on the first run to read `main`-populated caches: **28 of 30 lookups hit across 16
lanes**, and total execution moved **5,182 s -> 5,080 s**.

Reporting the 93 % without the 2 % would be the flattering number and the less true one.
Three reasons, largest first:

1. **The double compile.** Every lane compiles in dev (`mix compile --warnings-as-errors`)
   then again in test (`mix test`). Only the test tree is cached.
2. **The artifacts are small** — `build-*` ~4.1 MiB, `deps-*` ~1.6 MiB. Restoring 6 MiB
   saves seconds.
3. **Queue, not compute, was always the dominant term.** RUNNER removed 20,900 s of queue;
   CACHE was aimed at 5,600 s of execution.

**CACHE's real value turned out to be correctness, not throughput.**

## What shipped

### Correctness repairs (the substantive half)

Five `_build` caches were keyed on nothing but a `mix.lock` hash — no os, arch, OTP or
Elixir dimension. The toolchain comes from `.tool-versions`, so an OTP bump would silently
restore BEAM files built by a different compiler. **A green CI run is not evidence a cache
is safe**, which is why this survived.

Two further findings not in the plan:

- **`offline-sync-e2e-gate` guard-02** cached `_build/prod` and then opened its only run
  step with `rm -rf _build/prod`. It downloaded a cache and deleted it microseconds later.
  **Removed rather than re-keyed** — the guard is only meaningful against a clean prod
  compile, so the correct cache here is none.
- **The SPM cache** was keyed on a `Package.swift` hash with no platform dimension, on a
  directory of compiled object files. Found by the new guard test on its first run.

The **Gradle cache** pointed at the project-local `.gradle` (build state) rather than
`~/.gradle/caches` (downloaded deps), so it stored almost nothing. Replaced with
`gradle/actions/setup-gradle`, which `phase67-proof.yml` already used.

`actions/cache@v3` appears nowhere — dependabot #51 (`b26225d4`) had already handled it, so
that plan bullet was **stale**.

### `.github/actions/setup-elixir-cache` (new composite action)

Key carries `os|arch|otp|elixir|mix-env|hash(mix.lock)`, sourcing the toolchain from
`.tool-versions` via `version-file` rather than hardcoded strings — hardcoding would drift,
and since the key is built from setup-beam's **outputs**, drift would also mean restoring a
`_build` from a different compiler. `restore-keys` differs from `key` by exactly the lock
hash. `deps/` and `_build/<env>` are separate entries.

Adopted across **19 job-level lanes in 14 workflows**.

## The design decision the plan did not anticipate

The plan's six dimensions are necessary but **not sufficient**. These caches are not safe
to share repo-wide.

`phase43` is a hermetic proof that **rulestead is absent**; `phase45` the same for rindle.
Other lanes install exactly those optional deps. Under a shared key a dep-*present* lane
could populate a `_build` that a dep-*absent* lane restores — so a fail-closed proof would
evaluate a tree containing the very thing it claims is missing, **and still report green**.

Keys therefore carry a scope segment (`workflow-job`). Cost measured: **1.90 GiB of the
10 GiB cap (19 %)**, no eviction pressure. Affordable.

## The two misses — cause established, not guessed

`phase71` and `phase73` took a `build-` miss on every run and had no `build-*` entry on
`main` at all.

**Cause:** both run their `mix test` inside `packages/crosswake_chimeway` and
`packages/crosswake_sigra` via `working-directory:`. The repo-root `_build/test` is
therefore never created, so `actions/cache` had nothing to save and skipped the entry — a
**permanent, silent miss that looked exactly like a cold cache**, on lanes that were green
throughout.

Fixed by switching both to `mix-env: dev`, the only root-level compile they perform.
Verified post-fix: both now emit `Cache saved with key: build-Phase-7x-...`.

This is the argument for measuring hit rate rather than assuming it. Nothing in CI would
ever have reported this.

## Proof

`test/crosswake/proof/phase153_1_cache_integrity_test.exs` — 8 tests: six dimensions on
every Elixir cache key, `os`/`arch` on every cache key of any kind, `restore-keys`
differing by exactly the lock hash, `.tool-versions` sourcing, and an **asserted-exact**
exemption list.

Two negative controls: one rejecting a key with no OTP dimension, one confirming the
checker *accepts* the shape the composite action emits. A checker that passed everything
would make the real assertions meaningless — and it was wrong in both directions before it
was right.

## Deviations from plan

1. **Task 1's `actions/cache@v3` bullet was stale** — already fixed by dependabot.
2. **Cache scope added** beyond the plan's key spec (above), for hermetic-proof safety.
3. **The dev half of the double compile was left uncached, deliberately.** Pinning
   `MIX_ENV=test` on the compile step would remove a full redundant compile per lane and is
   likely the single biggest remaining win — but it changes which `Mix.env()` the
   warnings-as-errors check runs under, across 11 merge-blocking gates, in a codebase that
   generates code conditionally. That earns its own change with its own verification rather
   than being smuggled into a caching commit.

## Follow-ups recorded

- The double compile (above) — largest remaining single win.
- `release-please.yml` / `hex-publish.yml` keys carry no OTP dimension, so an OTP bump can
  restore a stale `_build` into a **publish** job. Scoped out by the plan as
  security-sensitive; recorded in the guard test's exemption comment.
- Package-level `deps`/`_build` for chimeway/sigra still uncached; needs a
  `setup-beam: false` input so the action can be invoked twice.
- SPM cache is ~1,000 MiB, **54 % of all cache usage**, duplicated across 10 refs.
- `CONSOL-*` untouched — 39 workflow files are still 39 workflow files.
