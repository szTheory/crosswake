## Security Gate

- standard: ASVS L1

## Trust Boundaries

- Evidence enters from device/storefront/webhook/support edges into backend-owned inbox processing.
- Projection updates cross from reconciliation outcomes into authoritative entitlement snapshot state.
- Example-host code is a teaching surface and must not imply provider-adapter or framework mandates.

## STRIDE Threat Register

| threat_id | category | component | disposition | mitigation_plan |
| --- | --- | --- | --- | --- |
| P21-01-T01 | spoofing | Evidence identity keys | mitigated | Use provider-aware `event_key` and `subject_key`; reject transient correlation IDs as authority identity. |
| P21-01-T02 | tampering | Snapshot projection ordering | mitigated | Enforce monotonic `as_of` guard so older evidence cannot overwrite fresher authoritative snapshots. |
| P21-01-T03 | repudiation | Replay handling | mitigated | Return explicit `replay?` metadata and deterministic non-failing replay outcomes in proof tests. |
| P21-01-T04 | elevation_of_privilege | Evidence-to-authority path | mitigated | Keep ingestion outputs non-authoritative and only permit authority changes in projection logic after verified flow markers. |
| P21-01-T05 | information_disclosure | Provider-specific leakage into normalized contracts | mitigated | Add proof checks rejecting provider-specific vocabulary in normalized example modules and keep provider-neutral keys/states. |
</threat_model>
