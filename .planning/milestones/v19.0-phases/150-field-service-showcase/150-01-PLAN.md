## Security Gate

Phase 150 uses ASVS L1 as the security baseline with a high-severity blocking threshold. Any implementation that introduces a high-severity ASVS L1 issue in access control, route policy, input validation, evidence state integrity, session/test helper boundaries, data protection, or support-truth disclosure must stop execution and revise before the plan can be marked complete.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-150-01 | Tampering | `diagnostics_test.exs` expectations | mitigate | Tests must require route facts from compiled router metadata, not duplicated prose. |
| T-150-02 | Spoofing | capture/scanner support assertions | mitigate | Tests require native-screen/future-gap labels and reject camera/scanner bridge command support. |
| T-150-03 | Repudiation | evidence status expectations | mitigate | Tests require backend-verification states before media availability. |
| T-150-04 | Spoofing | permission support copy | mitigate | Tests keep camera/scanner/location permission truth inside native-screen or future-gap surfaces. |
| T-150-05 | Tampering | offline posture assertions | mitigate | Tests reject shipped local mutation claims unless a route-local offline island proof ships with storage, replay, conflict, and reconciliation behavior. |
| T-150-06 | Denial of Service | dense Fieldserv UI contracts | mitigate | Component and route-tour contracts require no horizontal overflow, visible focus, and unclipped status/action text. |
| T-150-07 | Elevation of Privilege | test/e2e reset usage | mitigate | This plan uses the existing gated reset endpoint only; no new production auth or session helper is introduced. |
</threat_model>
