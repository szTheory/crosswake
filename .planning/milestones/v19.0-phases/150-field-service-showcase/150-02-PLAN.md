<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fixture data -> LiveView rendering | Deterministic Fieldserv strings will be rendered in HEEx by later plans. |
| Fixture route posture -> diagnostics/UI | Static posture data can drift from compiled router metadata if treated as authoritative. |
| Offline copy -> user interpretation | Cached/degraded fixture copy can be mistaken for local mutation support if written loosely. |

## Security Gate

Phase 150 uses ASVS L1 as the security baseline with a high-severity blocking threshold. Any implementation that introduces a high-severity ASVS L1 issue in route policy, evidence state integrity, data protection, or support-truth disclosure must stop execution and revise before the plan can be marked complete.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-150-08 | Information Disclosure | `FieldService.Fixtures` | accept | Fixture data is fictional and must avoid real addresses, phone numbers, tokens, session refs, and provider payloads. |
| T-150-09 | Tampering | `digest_components/0` | mitigate | Digest components must be sorted and built from stable IDs/titles/statuses so reset tests catch drift. |
| T-150-10 | Repudiation | route/support posture fixture rows | mitigate | Keep fixture posture supplementary; Plan 03 derives authoritative route facts from compiled router metadata. |
| T-150-11 | Tampering | offline/degraded copy | mitigate | Context helpers must expose cached read-only state and future requirements, not shipped local mutation behavior. |
</threat_model>
