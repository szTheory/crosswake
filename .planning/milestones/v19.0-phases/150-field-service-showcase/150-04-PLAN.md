<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LiveView/context calls -> evidence context | Browser actions request server-side evidence state transitions. |
| Evidence context -> database | Ecto writes persisted evidence events and technician state. |
| Reset orchestration -> database | Showcase reset deletes/reseeds Fieldserv-owned mutable rows. |

## Security Gate

Phase 150 uses ASVS L1 as the security baseline with a high-severity blocking threshold. Any implementation that introduces a high-severity ASVS L1 issue in input validation, evidence state integrity, data protection, or auditability must stop execution and revise before the plan can be marked complete.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-150-17 | Tampering | `Evidence` context writes | mitigate | Use Ecto changesets, closed vocabularies, and `Ecto.Multi`; no raw SQL or user-controlled status promotion. |
| T-150-18 | Repudiation | `field_service_evidence_events` | mitigate | Persist stable event ID, actor/technician ID, route ID, support ref, outcome/status, and occurred_at. |
| T-150-19 | Information Disclosure | evidence metadata | mitigate | Store safe support metadata only and strip token/session/provider payload keys. |
| T-150-20 | Tampering | `Showcase.Reset.reset!/0` | mitigate | Delete/reseed Fieldserv rows idempotently and include stable digest components to catch drift. |
| T-150-21 | Spoofing | evidence availability | mitigate | Device evidence status cannot promote to backend verified without explicit backend verification context functions. |
</threat_model>
