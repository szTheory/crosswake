<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Router metadata -> diagnostics UI | Compiled route policy crosses into product-facing support truth. |
| Catalog/hub metadata -> first impression | Showcase card copy can overclaim support if it drifts from route facts. |
| Capability evidence -> Phase 152 handoff | Pressure rows can be mistaken for shipped support if labels are wrong. |

## Security Gate

Phase 150 uses ASVS L1 as the security baseline with a high-severity blocking threshold. Any implementation that introduces a high-severity ASVS L1 issue in route policy, support-truth disclosure, data protection, or test-only route exposure must stop execution and revise before the plan can be marked complete.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-150-12 | Tampering | `FieldService.Diagnostics.route_policy_rows/1` | mitigate | Derive route facts from `RouterMetadata.fetch/1`; tests compare route ids/paths/capabilities against compiled router data. |
| T-150-13 | Spoofing | capture route metadata | mitigate | Declare capture route as `runtime: :native_screen` with camera/media/transfer metadata and test it. |
| T-150-14 | Spoofing | scanner/permission support labels | mitigate | Labels must be `Future gap`, `Next-pack candidate`, `Requires native runtime`, or `Permission needed` as appropriate, not shipped support. |
| T-150-15 | Information Disclosure | diagnostics rough-edge text | mitigate | Render route posture and support refs only; avoid raw payloads, tokens, session refs, or real-world jobsite data. |
| T-150-16 | Repudiation | support labels | mitigate | Keep labels allowlisted and mechanically tested so support truth remains auditable. |
</threat_model>
