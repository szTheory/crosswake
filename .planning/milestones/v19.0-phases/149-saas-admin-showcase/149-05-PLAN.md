<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fixture/context data -> HEEx | Fictional account/admin data becomes browser-visible UI. |
| Diagnostics data -> HEEx | Route policy/support truth becomes browser-visible UI. |
| Session assigns -> admin-pressure UI | Current user/role posture is displayed to the user. |

## Security Gate

Phase 149 uses ASVS L1 as the security baseline with a high-severity blocking threshold. Any implementation that introduces a high-severity ASVS L1 issue in authentication, session management, authorization, validation, business logic, error handling, or support-truth disclosure must stop execution and revise before the plan can be marked complete.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-149-15 | Information Disclosure | AdminPilot pages | mitigate | Render only fictional fixture data and support refs; avoid raw denial details, tokens, session refs, or provider payloads. |
| T-149-16 | Spoofing | posture badges | mitigate | Badges reflect backend/router truth from current assigns and diagnostics rows, not client-provided route labels. |
| T-149-17 | Elevation of Privilege | `AdminAccessLive` | mitigate | Keep the page as a denial/proof state and do not add UI controls that grant admin access. |
| T-149-18 | Denial of Service | responsive diagnostics table | mitigate | Use stacked mobile layout and overflow-safe CSS so route matrix content does not create horizontal overflow. |
</threat_model>
