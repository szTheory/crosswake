<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| emitted telemetry metadata → host Logger | Event metadata may carry PII or oversized/high-cardinality values; the logger must scrub before writing. |
| host → attach_default_logger/1 | Attachment is host-initiated only; core must never call it (privilege/opt-in boundary). |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-133-08 | Information Disclosure | default logger writing PII metadata | high | mitigate | Metadata scrubbed through `all_forbidden_keys/0` (union of subsystem denylists, D-15) before logging; unit test asserts `:access_token` never reaches output. |
| T-133-09 | Elevation of Privilege | core auto-attaching the logger | high | mitigate | No application-start/supervision call to attach_default_logger (D-13/TELEM-03); acceptance grep enforces; attachment is host-explicit only. |
| T-133-10 | Tampering | silent double-attach masking a config bug | low | accept | Rely on :telemetry's `{:error, :already_exists}` return (D-13); no custom guard that swallows it — surfaced to the caller. |
| T-133-11 | Denial of Service | unbounded log volume / cardinality | medium | mitigate | Logger attaches only to :active events (a small fixed set from events/0); metadata keys are the low-cardinality allowlist; :exception forced to :error keeps failures visible without info-flooding. |
</threat_model>
