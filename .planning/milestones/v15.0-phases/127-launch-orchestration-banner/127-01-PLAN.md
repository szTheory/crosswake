<objective>
Create `bin/see-it-run.sh` — the canonical, zero-Elixir, one-command launcher for the
Crosswake "See It Run" first-run experience. It probes port 4700 for an
already-running server, otherwise boots the Phase-125 Dockerized backend detached,
polls curl readiness, prints a plain-ASCII brand-voiced banner (served URL, the three
honest routes, a proven/needs-build block, and verbatim per-runtime next commands),
and advisorily boots the iOS simulator / Android emulator when the toolchain is present.

Purpose: A newcomer with only Docker installed runs ONE command and immediately sees
what is running and exactly what to do next, with honest caveats about native support.

Output: `bin/see-it-run.sh` (executable, `set -euo pipefail`).
</objective>

1. Reuse probe FIRST (D-09): `if curl -sf "$BACKEND_URL/" >/dev/null 2>&1; then` -> print `[crosswake] Port 4700 is already serving — reusing it`, skip boot, jump to banner. This transparently covers a hand-started native `mix phx.server`.
2. If not serving, check Docker (D-11): `command -v docker` AND `docker info >/dev/null 2>&1`. If either fails -> FATAL: print the 4-line calm-guidance block (what's wrong / why / exact remediation `cd examples/phoenix_host && PORT=4700 mix phx.server` + the Docker install URL https://docs.docker.com/get-docker/ / reassurance) then `exit 1`. 3. Inspect `docker compose -f "$COMPOSE_FILE" ps` (guarded `|| true`) to message first-boot vs crashed/exited before booting.
4. Detached boot (D-07): `docker compose -f "$COMPOSE_FILE" up -d`. Print a one-line "[crosswake] First boot compiles deps (~1-2 min)..." notice (discretion — recommended) plus `[crosswake] Waiting for backend on http://localhost:4700 ...`.
5. Readiness poll (D-08): loop `curl -sf "$BACKEND_URL/" >/dev/null 2>&1` with `sleep 2` and a hard cap of 60 iterations (~120s). Emit a dot per iteration for progress. On success -> proceed. On timeout -> print `[crosswake]` calm message and the exact `docker compose -f examples/phoenix_host/docker-compose.yml logs` command, then `exit 1` (D-08/D-17).

Every expected-non-zero probe (`curl`, `command -v`, `docker info`, `docker compose ps`) is `|| true`-guarded or `if`-wrapped so `set -e` never aborts on an expected non-zero (D-03). Leave a clearly-marked placeholder where Task 2 inserts the banner emission and Task 3 inserts native launch (e.g. a `print_banner` and `maybe_launch_native` function call site), so the two follow-on tasks have an explicit insertion point.

Two exit codes only (D-17): 0 = backend serving + banner printed; 1 = backend boot failure (Docker absent/daemon down, foreign process holding 4700 such that curl never succeeds, or compose up / readiness timeout). Native outcomes never change the exit code.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| environment -> shell | env vars (PORT-adjacent, JAVA_HOME, CI, NO_COLOR, NO_OPEN) and CLI args flow into a script running with the developer's local privileges |
| shell -> docker daemon | `docker compose` shell-out to the local daemon |
| shell -> localhost network | `curl` to a hardcoded `http://localhost:4700` |
| shell -> toolchain | advisory `xcodebuild`/`gradlew`/`adb`/`simctl`/`open`/`xdg-open` invocations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-127-01 | Tampering/Elevation | flag parser + interpolation | mitigate | `set -euo pipefail`; never `eval`; never interpolate untrusted toolchain output into a command; the only network target is the hardcoded `http://localhost:4700` literal — never a user-supplied URL (no --backend-url) |
| T-127-02 | Denial of Service | readiness poll | mitigate | hard ~120s cap (60×sleep 2) on the curl loop; timeout exits 1 with the logs command — cannot hang indefinitely |
| T-127-03 | Information Disclosure | Docker daemon stderr | mitigate | intercept the opaque "Cannot connect to the Docker daemon" stderr and replace with a calm `[crosswake]` message (D-11); no secrets printed |
| T-127-04 | Denial of Service | native toolchain shell-out | mitigate | suppress native launch under CI / non-TTY (D-14) to avoid Gradle/RN license-prompt hangs; every native step `|| true`-guarded so it cannot mask a fatal boot failure |
| T-127-05 | Tampering | JAVA_HOME / env-derived paths | accept | JAVA_HOME path is only used to locate a local JDK the developer already controls; treated as developer-trusted local config, low value, local-only tooling |
| T-127-SC | Tampering | npm/pip/cargo installs | n/a | no package-manager installs in this plan (shell + invoke-only); no legitimacy gate required |
</threat_model>
