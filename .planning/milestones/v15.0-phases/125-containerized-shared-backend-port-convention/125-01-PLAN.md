<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host → Phoenix HTTP listener | The endpoint's bind address (ip) decides who can reach the dev server; `0.0.0.0` exposes it on all host interfaces |
| committed repo → image/runtime | `.env` is committed to git; anything in it is public |
| test runner → runtime.exs | runtime.exs executes under `:test`; an over-broad bind would expose the test server |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-125-01 | Information Disclosure | examples/phoenix_host/.env (committed) | mitigate | .env carries ONLY COMPOSE_PROJECT_NAME and PORT — no secret_key_base, keys, tokens, or passwords; Task 2 verify negative-greps for secret-like keys |
| T-125-02 | Elevation of Privilege / Exposure | runtime.exs ip binding | mitigate | ip = 0.0.0.0 ONLY when BIND_ALL=true (set solely by docker-compose); default and :test stay 127.0.0.1 loopback — container-only exposure cannot leak into test or native runs |
| T-125-03 | Spoofing | dev.exs check_origin:false | accept | check_origin:false lives in dev.exs and applies under :dev only; it is a local-dev demo convenience, not a prod-like path; documented as dev/container-only |
| T-125-04 | Tampering | secret_key_base in config.exs | accept | The placeholder `String.duplicate("a", 64)` is an intentional non-secret demo value; no real secret is committed. Acceptable for a local-dev demo backend (no real sessions of value) |
</threat_model>
