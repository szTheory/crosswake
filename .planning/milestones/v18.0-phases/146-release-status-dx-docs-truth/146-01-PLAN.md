<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| maintainer/CI -> Mix task | CLI args are untrusted input, parsed by `OptionParser` in the public task. |
| Mix task -> repository files | Status reads manifests, release config, workflow YAML text, package files, and scanner output from the current checkout. |
| Mix task -> local scanner process | Scanner execution is read-only but its output must be parsed defensively. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-146-01 | Tampering | `Crosswake.ReleaseStatus` command boundary | mitigate | Enforce D-06: status code may read files and run scanner only; it must not invoke publish, push, backfill, delete, tag movement, `gh pr`, or `gh issue` commands. |
| T-146-02 | Information Disclosure | scanner/status output | mitigate | Print scanner IDs and concise details only; no token values, raw registry payloads, or secret mechanics enter status output. |
| T-146-03 | Repudiation | workflow guard status | mitigate | Use stable scanner IDs as evidence so operators can rerun `elixir script/check_release_workflow_integrity.exs` and reproduce each check. |
| T-146-04 | Tampering | local source files | accept | The command reports the state of the current checkout; repository integrity remains a git/CI concern outside the read-only task. |
| T-146-SC | Tampering | npm/pip/cargo installs | mitigate | No new package-manager installs are planned; keep `Package Legitimacy Audit` disposition as no install. |
</threat_model>
