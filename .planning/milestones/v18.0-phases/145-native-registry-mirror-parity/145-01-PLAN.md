## Trust Boundaries

| Boundary | Description |
|---|---|
| GitHub Actions secret -> shell step | `MIRROR_PUSH_TOKEN` enters workflow shell as a secret and must not be echoed. |
| Release workflow -> mirror repository | `publish-ios-core` attempts to write refs in `szTheory/crosswake-shell-core-ios`. |
| Workflow text -> scanner/test | Static scanner treats release policy as product surface and must not accept comment-only decoys. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-145-01 | Spoofing / Elevation of Privilege | `publish-ios-core` mirror auth | mitigate | Require `git push --dry-run --porcelain mirror` with branch and tag refspecs after read check and before mutation. |
| T-145-02 | Information Disclosure | `MIRROR_PUSH_TOKEN` logs | mitigate | Failure copy names repo, tag, permission, and next action, never token value or raw credential URL. |
| T-145-03 | Tampering | SwiftPM mirror tag refs | mitigate | Exact existing tag identity is OK; mismatch fails closed with no automatic delete or move. |
| T-145-04 | Repudiation | Release workflow policy drift | mitigate | Add stable scanner ID and adversarial ExUnit fixture for the MIRR-01 write preflight. |
| T-145-05 | Denial of Service | Routine scratch-ref preflight | mitigate | Do not create/delete scratch refs in the normal preflight path. |
| T-145-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install task is planned; no package legitimacy gate required. |
</threat_model>
