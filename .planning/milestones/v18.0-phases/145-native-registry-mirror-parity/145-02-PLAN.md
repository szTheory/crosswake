## Trust Boundaries

| Boundary | Description |
|---|---|
| GitHub Actions DAG -> native proof jobs | Job dependencies decide whether a platform proof can run after sibling platform failure. |
| Native publish/proof jobs -> rollup job | `needs.*.result` crosses into release reporting and must not hide partial state. |
| Rollup JSON artifact -> Phase 146 | Narrow CI evidence may be consumed later by status tooling; it must not overclaim registry truth. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-145-06 | Denial of Service | native proof DAG | mitigate | Keep iOS and Android proof jobs independent so one registry path cannot prevent the other proof from running. |
| T-145-07 | Repudiation | native-release-rollup | mitigate | Use `always()` and `needs.*.result` to report skipped, failed, canceled, and successful platform states. |
| T-145-08 | Information Disclosure | rollup summary / JSON | mitigate | Summary and JSON include package/version/ref/proof state/next action, not raw secret or registry payload details. |
| T-145-09 | Tampering | rollup aggregate state | mitigate | Scanner/test fixtures fail if partial native state is flattened into a complete state. |
| T-145-10 | Spoofing | Phase 146 evidence handoff | mitigate | JSON artifact uses explicit per-platform fields and aggregate `native_core` state; it is release evidence, not a registry oracle. |
| T-145-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install task is planned; no package legitimacy gate required. |
</threat_model>
