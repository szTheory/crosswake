# Milestone v2.0: Adopter Stress Profiles

**Status:** ✅ SHIPPED 2026-05-19
**Phases:** 6-10
**Total Plans:** 16

## Overview

Crosswake used `v2.0` to pressure-test the proven `v1` route-policy substrate against three realistic adopter shapes instead of widening into generic templates or a broader plugin surface. The milestone validated that the runtime-ownership thesis still holds for a Phoenix SaaS lane, a selective-native capture corridor, and a local-first study flow, then hardened diagnostics, proof, and support guidance around the rough edges those lanes exposed.

## Milestone Summary

**Decimal Phases:**

- None.

**Key Decisions:**

- Keep the exemplar program anchored to one shared example-host artifact class rather than multiple starter apps.
- Treat the exemplars as proof artifacts that validate architectural fit, not product templates.
- Keep native ownership route-local and low-frequency: one bounded haptics seam for SaaS and one `:native_screen` capture corridor for the selective-native lane.
- Keep local-first claims explicit by separating offline-island mutation, cached read-only history, sync, and replay outcomes.
- Publish profile-specific rough-edge truth through localized guidance and diagnostics instead of a single catch-all rough-edges surface.

**Issues Resolved:**

- Locked a public adopter-profile matrix and shared-host contract for the first realistic Crosswake app shapes.
- Proved a Phoenix-owned SaaS shell lane with host-owned auth and one bounded shell affordance.
- Proved a selective-native claims-evidence corridor with explicit pack and transfer seams.
- Proved a local-first study flow with an append-only journal, sync endpoint, cached history, and verification lane.
- Fixed dynamic deep-link matching in checked-in shell proofs so manifest-backed routes with path parameters activate correctly.

**Issues Deferred:**

- Broader native capability families and commerce surfaces remain deferred to the next milestone family.
- Example-host and native proof remain environment-sensitive enough that future capability expansion should keep simulator and emulator drift visible as product-surface risk.

**Technical Debt Incurred:**

- `08-VALIDATION.md` remains more planning-oriented than execution-oriented even though Phase 8 verification is now explicit elsewhere.
- The profile verification scripts regenerate checked-in manifests before testing, so future route changes must keep generation and fixtures aligned.
