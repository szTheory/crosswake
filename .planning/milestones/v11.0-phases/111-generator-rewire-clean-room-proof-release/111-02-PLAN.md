<objective>
Add a permanent merge-blocking parity guard that statically proves the generator templates point at published, version-matched coordinates and never regress back to monorepo/local/broken coordinates.

Purpose: The clean-room CI lane (Plan 04) only runs post-release, so it cannot catch a template regression on a per-PR basis. This static `ReadinessCheck` is the cheap deterministic per-merge layer (~100ms `EEx.eval_file`, no network, no BEAM-subprocess) that keeps the eject-trap thesis honest — the structural sibling to the v10.0 `brand-structural` drift gate.

Output: A new `generator_coordinate_parity_check/1` in `Crosswake.Doctor.PublishReadiness` wired into `build_checks/4`, with `blocking: true` / `proof_class: :merge_blocking`, plus the same assertions mirrored in the test file (dual surface per D-02b).

Depends on 111-01 (asserts against the rewired templates) and 111-03 (shares `publish_readiness.ex`; 111-03 lands the `@allowed_docs` whitelist edit first — append the new check after that edit to avoid a merge conflict).
</objective>
