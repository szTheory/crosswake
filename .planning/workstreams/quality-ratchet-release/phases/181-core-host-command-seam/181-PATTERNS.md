## Pattern Assignments

### `lib/crosswake/router.ex` (macro, compile-time)

**Analog:** same file. Note that `__using__/1` ignores its options (line 11), and the example router and installer use `import Crosswake.Router`, not `use` (RESEARCH F2). The registry macro must therefore be importable by both styles.

**Macro and eval pattern to copy** (lines 38-45, 123-133). Evaluate the AST against the caller and reject a bad shape with a clear error:
```elixir
defmacro crosswake_defaults(defaults, do: block) do
  evaluated_defaults = __eval_keyword!(defaults, __CALLER__)
  rewritten_block = ScopeDefaults.apply(block, evaluated_defaults, __CALLER__)
  quote do
    unquote(rewritten_block)
  end
end

def __eval_keyword!(ast, caller) do
  {value, _binding} = __eval_keyword__(ast, caller)
  if Keyword.keyword?(value), do: value,
    else: raise ArgumentError, "expected a keyword list for Crosswake router options, got: #{inspect(value)}"
end
```
**`use` sugar.** `__using__(_opts)` (line 11) becomes `__using__(opts)`. When `opts[:host_commands]` is present, the quote ends by emitting the same `crosswake_host_commands(...)` call as the macro form. Both paths must share one code path. Raise `CompileError` with `file: caller.file, line: caller.line` for malformed grammar, reserved prefix, duplicate id, or non-strict SemVer (use `Version.parse/1` and reject short forms; D-03).

**Error wording** (D-05) follows `raise_undeclared_capability!/3` in `lib/crosswake/bridge.ex` (599-624). It has a stable bracketed code, the route and what is declared now, the location, a copy-paste fix line, and a short why-paragraph:
```elixir
message = """
[crosswake.bridge.undeclared_capability] route #{inspect(state.route_id)} never \
declared the #{inspect(capability_family)} capability family.

Currently declared on this route: #{inspect(declared)}
Router location: #{router_file}#{router_line}

Add the family to this route's declaration:

    #{fix_line}
"""
```
Use the `String.jaro_distance/2` did-you-mean over declared ids (stdlib).

### `lib/crosswake/policy/validator.ex` (validator, transform)

**Analog:** same file.

**Core pattern to extend** (lines 26-35 and 120-136). `validate/2` zips routes with managed routes, and each check is a `defp validate_x(errors, route)` that prepends `%{key:, message:, hint:}` maps. `build_error/3` (247-261) attaches `file`/`line` from `managed_route.source`:
```elixir
@spec validate([Route.t()], [map()]) :: [Error.t()]
def validate(routes, managed_routes) do
  routes |> Enum.zip(managed_routes) |> Enum.flat_map(fn {route, managed_route} ->
    route |> route_errors() |> Enum.map(&build_error(managed_route, route, &1))
  end)
end

defp validate_capabilities(errors, %Route{capabilities: capabilities}) do
  Enum.reduce(capabilities, errors, fn capability, acc ->
    if MapSet.member?(@known_capabilities, capability), do: acc,
      else: [%{key: :capabilities, message: "unknown capability #{inspect(capability)}", hint: "declare semantic ..."} | acc]
  end)
end
```
**Change.**
- Add `validate/3` with `opts[:host_commands]`, and keep `validate/2` as the no-registry call (R1/D-27).
- In `validate_capabilities`, split out capabilities that start with `host.`. They skip `@known_capabilities`, which stays closed. They are checked for grammar, reserved prefix, and runtime in `[:live_view, :offline_island]`. Membership is checked only when the registry option is present.
- Put `[crosswake.route.unknown_host_command]` and `[crosswake.route.host_command_runtime]` at the start of `message`, with `key: :capabilities`.
- Document the arity-2 contract in `@moduledoc`.
- `validate_runtime_offline`, `validate_entry`, and `validate_security` are untouched. `security_required?/1` already treats a non-empty `capabilities` list as requiring `security`.

### `lib/crosswake/manifest/builder.ex` (service, transform)

**Analog:** same file.

**Registry pattern** (156-181). Builds public entries, then derives entries for route-referenced ids through `Types.new_capability/1`:
```elixir
compatibility_registry =
  routes |> Enum.flat_map(& &1.capabilities) |> Enum.uniq()
  |> Enum.reject(&Map.has_key?(public_registry, &1))
  |> Enum.map(fn capability_id ->
    capability = family_capability_for(capability_id) |> compatibility_capability_attrs(capability_id) |> Types.new_capability()
    {capability_id, capability}
  end) |> Map.new()
```
**Change.** `host.*` ids must not go through `family_capability_for`. Add a separate host-command branch producing `Types.new_capability(id: cmd, family: "host_command", owner: :host, version: <registry version>, rebuild: ...)`.
- **`family` must differ from `id`.** `new_capability/1` defaults `family` to `id`, and `SupportMatrix.capability_family_entries/1` (support_matrix.ex ~1076) emits a row for every capability where `id == family`. Without the override, every host command becomes a support-matrix family row (RESEARCH pitfall 3).
- Emit only referenced commands.

**Route entry pattern** (194-207). `route_entries/3` builds `Types.new_route_entry(id:, ..., capabilities: route.capabilities, ...)`. Add `host_commands: host_commands_for(route, registry)` as one named function. IOSHostGeneration must call that same function (D-07). The entry value is a sorted `%{name => version}`, and `%{}` when none.

## Shared Patterns

### Fail-closed explicit denial, with a stable code and a fix line
**Source:** `lib/crosswake/bridge.ex` 599-624, `lib/crosswake/policy/validator.ex` 120-136.
**Apply to:** the router macro, validator, compiler, generation gate, doctor, and Swift denial messages. Name the route id and command, give one fix, and use no new wire reason codes (D-18).

### Policy error struct with source location
**Source:** `Validator.build_error/3` (247-261). The `Crosswake.Policy.Error` fields are `key`, `route_id`, `message`, `hint`, `path`, `helper`, `verb`, `file`, `line`.
**Apply to:** every new policy error.

### Single source of the schema version
**Source:** `Crosswake.Manifest.Types.manifest_schema_version/0`.
**Apply to:** manifest, doctor, docs snippet. Only `crosswake.contract.gen.ex`'s Android vector literal (line ~193) stays `"1.1.0"` (D-19). `docs_snippet/1` (~494) reads the function. After `mix crosswake.contract.gen`, run `git diff --exit-code` on the Android and vector paths.

### Additive wire fields with lenient decode
**Source:** the `Route` / `Compatibility` `Codable` structs in `ActivationCoordinator.swift`.
**Apply to:** `host_commands` and `compatibility.host_command_seam_version`. Absent gives nil (legacy path), `null` and `{}` give empty, and a malformed value throws, which surfaces as the existing "Shell boot blocked" denial in `handleIncomingURL` (~559-569).

### Privacy-safe diagnostics
**Apply to:** the D-09 session-build record and the doctor, inspect and generation outputs. Carry only route id, command name and reason. Test that no other field appears.

### Pinned guards to respect
- `lib/crosswake/bridge/catalog_guard.ex` and `test/crosswake/proof/phase154_catalog_guard_test.exs`: `BridgeChannel.swift` lines 128, 133, 286, 292 and the closed denial vocabulary.
- `NavigationShellAdvisory` digests of `NavigationCoordinator.swift`, `capability_map.ex` and `support_matrix.ex`: check before editing `support_matrix.ex`.
- `script/assert_manifest_contract_unchanged.sh` (doctor `manifest_compile_check`).
- Android byte-freeze: `git diff --exit-code 96e5a63efab657f89f3ac84d5b1d84ff5da5d822 -- examples/android_shell_host packages/crosswake-shell-core-android test/fixtures/bridge_contract_vectors.json packages/crosswake-shell-core-ios/Tests/CrosswakeShellCoreTests/Resources/bridge_contract_vectors.json`, with no pipe.
