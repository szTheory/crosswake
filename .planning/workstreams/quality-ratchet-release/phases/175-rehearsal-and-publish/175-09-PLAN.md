<scope_boundary>
This plan observes and records. It publishes nothing, merges no release pull request, and changes no
workflow. The one merge it may perform is the release-ledger pull request the proof lane opens, so the
ledger row becomes durable rather than sitting unmerged.

If the proof job is absent or skipped, do not repair the workflow here and do not re-dispatch a proof
against a different ref to manufacture a passing run. Record the outcome and stop.
</scope_boundary>

<objective>

for the version just published — and that the ledger says the same thing durably.

Purpose: this milestone exists because checks were green while asserting nothing, and the proof lane's

been distinguishable from its success. REL-14's wording is deliberate — executed, not skipped, and
passed, confirmed by a linked run identifier for that exact version.

Output: a linked run identifier with a recorded status and conclusion, a merged ledger row, and a rollup
verdict with its six children enumerated.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| A CI job's absence -> the claim that a proof passed | A job that never ran and a job that passed are indistinguishable unless status is read separately from conclusion |
| An open ledger pull request -> "the evidence is recorded" | A row that exists only in an unmerged branch is not durable evidence |
| The rollup's aggregate verdict -> the claim that six things succeeded | An aggregate is only meaningful if its members are visible |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-175-49 | Spoofing | A skipped proof job read as a passing one | high | mitigate | Task 1 records `status` and `conclusion` as two separate fields, defines a skip and an absence as REL-14 unsatisfied, and the automated check fails when the job is missing, skipped, or non-successful. |
| T-175-50 | Repudiation | A proof run for a different version accepted as evidence for this one | high | mitigate | Task 1 records the attested version and requires it to equal the version confirmed live in the previous plan; a prohibition forbids cross-version evidence. |
| T-175-51 | Repudiation | Ledger evidence left as an unmerged pull request | medium | mitigate | Task 1 requires the ledger row to be durable, merging the recording job's pull request through the normal path and recording the merge commit. |
| T-175-52 | Tampering | Manufacturing a passing proof run by re-dispatching against a different ref | high | mitigate | The scope boundary forbids it explicitly and Task 1 requires the run's head SHA and attested version to be recorded and matched. |
| T-175-53 | Tampering | Widening the rollup to include companion state so COMPLETE becomes easier to reach | high | mitigate | A prohibition forbids it, Task 2 records D-31's reasoning, and a verification asserts the rollup's source file is unmodified. |
| T-175-54 | Spoofing | A one-word rollup verdict standing in for six unexamined children | high | mitigate | Task 2 requires all six children enumerated with individual states and zero blanks. |
| T-175-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable to this plan — it adds no package-manager install step. |
</threat_model>
