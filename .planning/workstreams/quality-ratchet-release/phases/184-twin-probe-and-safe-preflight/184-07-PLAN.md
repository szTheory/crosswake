- CR-01, pin only, no refusal (amends D-05, which had cut core.hooksPath as redundant before the hook path was reproduced). Add the pair "-c" "core.hooksPath=/dev/null" to @git_pins. A command-line -c beats every config file, including local config and include.path files, and GIT_CONFIG_PARAMETERS/GIT_CONFIG_COUNT are already scrubbed, so a local core.hooksPath cannot undo the pin. A refusal would add a false-block for repositories that use a hooks directory for ordinary tooling without adding safety. The test for a local core.hooksPath proves the pin is enough. 184-08 Task 3 records this as D-34 in 184-CONTEXT.md and in the CR-01 row of 184-REVIEW-DISPOSITION.md. The version call (bare mode, git --version) runs no hook and stays unpinned per D-30.
- WR-01, count rather than document. Each ignored untracked entry whose deciding ignore rule does not come from a .gitignore tracked in HEAD counts as one modified finding (the existing M clause "changed or untracked files"; no new clause, cause or schema field). Rules from .git/info/exclude are skipped here because the X count already covers them. Ignored files matched by a committed .gitignore stay uncounted: that is the deferred, disclosed limit in 184-CONTEXT.md and TWIN-08, and it is not changed.
- WR-02, fix both levels: lock_digests and file_digest return errors instead of raising or hashing a prefix (file_digest/2 gains a :read_chunk reader seam so the mid-stream error branch has a named test and a mutation control on every OS, since macOS refuses to open a directory before any read), and the mix task wraps the check in rescue/catch that maps to a fixed blocked result. The task-level guard is the backstop for the "never exits 1, never raises" contract (D-14).
- WR-03, correct the wording and prove the snapshot is meaningful. - IN-02, scope: (a) prefix scrub of every inherited GIT_* name at spawn time, with the fixed env and the per-call GIT_INDEX_FILE applied afterwards; (b) the spawn task body catches every raise, throw and exit and returns :unavailable. Deferred, recorded: (c) an orphaned OS git child after a timeout. Task.shutdown(:brutal_kill) ends the Elixir task, and the port closes, but a git that is hung without writing may outlive it. There is no portable timeout utility on macOS and the bound is 60 s per call. Reopen trigger: a hung or leftover git process observed during a preflight or twin run.
