<gap_decisions>
Task 3 records these as D-37 and D-38 in 184-CONTEXT.md, under "### Gap-closure amendments (2026-10-15)", after the D-36 bullet.

- D-37: literal paths for check-ignore (amends D-35 (b) and (c), closes GAP2-CR-01).
  (a) Each listed entry is written to check-ignore.in as the text ./ followed by the entry, then NUL. A leading ./ makes git skip pathspec magic parsing for that line. Checked during planning on git 2.41.0 in scratch repos: for an untracked folder :deps beside a committed /deps/ rule, the bare path is credited to .gitignore line 1 /deps/, while ./:deps/evil.ex is credited to :deps/.gitignore (untracked, so counted). The same held for :(top)deps and for a folder : holding deps/. For :!deps, :^deps, :(exclude)deps, :(glob)deps, :(icase)DEPS and :(attr:x)deps, the bare path made check-ignore exit 128 (fail-closed, but every such candidate unavailable) and ./ gave the true untracked source. Names with [ ] * ? or a backslash were already judged literally, and stay so with ./. A nested repository root entry such as nested/ is echoed as ./nested/.
  (b) The path-binding check compares each record's path with the exact sent text, "./" <> entry, byte for byte. The framing check and the binding check stay separate (D-35 (c)).
  (c) Rejected alternatives, both checked during planning on git 2.41.0: the --literal-pathspecs option and the GIT_LITERAL_PATHSPECS=1 environment both make check-ignore fail with "pathspec magic not supported by this command: 'literal'" and exit 128, so every candidate would be unavailable. The scrubbed env already unsets every GIT_* name. The reviewer's extra suggestion (also count any entry starting with a colon) is not added: behind the ./ prefix no test could show it load-bearing, and an unprovable guard is noise.
- D-38: info/exclude is counted, never trusted; lines are read as git reads them; IN-01 and IN-02 (amends D-35 (d)(i) and D-03's line rule, closes GAP2-CR-02, GAP2-IN-01, GAP2-IN-02, GAP2-IN-03).
  (a) Fail-closed choice, taken as the reviewer's simpler alternative: a hidden path whose deciding source is .git/info/exclude is no longer trusted. It counts as one modified finding like any other non-committed rule, so a hidden file blocks whatever the line parser concludes. The only trusted source left is a .gitignore that is an exact entry of the fresh HEAD index. The rev-parse --git-path info/exclude call made only for that trust is removed.
  (b) D-03 still requires the excludes count to be the number of active rules (the X clause says "N local ignore rules"), so the line parser is also corrected rather than dropped. For info/exclude, a line is inactive only when, after removing one trailing CR, it is empty, its first byte is #, or it is made only of spaces. Leading spaces, tabs and other whitespace are significant. Checked during planning on git 2.41.0: two spaces then #* hides a file named two spaces then #evil.ex; a tab-only line hides a folder named by a tab; a three-space line hides nothing; a backslash-# line is a rule; a line of a space, a tab and a space is a rule. A UTF-8 BOM before # on the first line is a comment to git but is counted here, which over-blocks and is accepted (fail-closed). info/attributes keeps its existing trimming test, because git's attribute reader skips leading blanks.
  (c) Counting effect, disclosed: a file hidden by an info/exclude rule now gives one modified finding and the rule gives one excludes finding, so line 4 names both clauses. Clauses count findings, not distinct files (D-10). No new cause, clause, receipt field or line-4 wording (D-07, D-14).
  (d) IN-02: check-ignore.in is set to mode 0600 right after it is written and before git reads it; a chmod error is :unavailable. It still lives only in the 0700 private index directory and is removed with it; if the VM is killed, it can be left behind like the temporary index itself, and it holds path names only, never contents. The moduledoc says so next to the temporary index.
  (e) IN-01: the git_invocation comment names all three forms, and the dirty_counts doc describes the D-35/D-38 counting.
</gap_decisions>
