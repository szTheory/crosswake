Content requirements:

1. **Scope** — the convention applies to the phase-close VERIFICATION.md of Phases 169, 171, 172,
   173, 174 and 175, naming each. Phase 170's own record is produced by plan 170-05.

2. **The frontmatter field** — `vacuity_taxonomy:`, a list of objects modeled directly on
   `169-VERIFICATION.md`'s `deferred:` list-of-objects shape. Each object carries exactly three
   keys: `check_id:` (the check's own ID as it appears in its emitter), `shape:` (one of `A`, `B`,
   `C`, `D`, `E`, `F`, or the literal escape form `matches none of A-F, because <reason>`), and
   `non_vacuity_evidence:` (a measured fact — the count the check actually found on a real run, or
   the mutation it was demonstrated going red against). Document that where a check maps to more
   than one shape, `shape:` records one primary letter and an `also_shapes:` key lists the
   additional letters; a check may never be recorded without at least one shape letter or the
   explicit escape form.

3. **The body section** — `## Vacuity Taxonomy`, one row per entry, listed in check-ID lexical order
   so the section diffs stably and two authors produce the same ordering.

4. **The null statement (D-16)** — a phase that landed no new checks MUST write the section with the
   explicit sentence "This phase landed no new checks." plus one sentence of justification, exactly
   as `169-VERIFICATION.md`'s "Human Verification Required" section states `None.` and says why.
   Omitting the section is defined here as non-compliant. State the reason in the document:
   completeness is a positive assertion, never an inference from absence, so "there was nothing to
   check" and "we forgot" must never be indistinguishable to an auditor grepping for the section.

5. **Never a bare tick (D-15)** — state that a yes/no checkbox is rejected. A boolean asserted
   without inspecting what is inside it is Shape A restated at the process layer, which would make
   this milestone ship an instance of its own target defect.

6. **Who applies it (D-17)** — the phase-close verifier, at phase close. Not the executor at plan
   time (a check's shape can still change during execution) and not a PR reviewer (nothing durably
   records a PR-time judgment across six phases, one of which is already merged). Note that
   VERIFICATION.md's frontmatter contract already gates phase closure, so the field cannot be
   skipped silently.

7. **Single-sourcing (D-18)** — the six shapes themselves live at `.planning/research/v23/PITFALLS.md`
   §"Pitfall 4". Link to that file by relative path. Do NOT restate the shapes' definitions,
   detection recipes or fix recipes in this document; a second copy that can silently diverge is
   exactly what Phase 169's D-16 link-never-copy rule forbids. Referring to a shape by its letter is
   fine; defining it here is not.

8. **Lifetime (D-21)** — record that the field outlives milestone v23.0. When VACG-01 lands as a
   merge-blocking guard it mechanically supersedes Shape A only; Shapes B-F have no proposed
   automated guard at all. At that point narrow the field to the five remaining shapes; do not
   retire it.

9. **Boundary (D-20)** — state that this is a `.planning/` convention only: no change to `lib/`,
   `script/` or `.github/workflows/` is made for VAC-03. Record that a PR template or CONTRIBUTING
   checklist item was considered and rejected as the primary surface — this repository has no PR
   template convention today, such an item cannot reach the already-merged Phase 169, and an
   un-required checkbox carries no evidentiary weight. It remains acceptable later as a
   supplementary reminder.

Write in the project's brand voice per `brandbook/BRAND-SPEC.md`: calm, specific, actionable, no
drama.
