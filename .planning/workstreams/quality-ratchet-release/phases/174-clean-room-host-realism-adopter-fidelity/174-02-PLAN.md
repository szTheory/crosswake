**1b. Write `script/assert_manifest_contract_unchanged.sh`.**
The guard takes an optional `--source` path defaulting to `lib/crosswake/doctor/doctor.ex` and an
optional `--baseline` path defaulting to the committed fixture, extracts the same two regions from
the source by the same method, and compares them byte-for-byte against the baseline.

Three assertions, in this order, each with its own named result token and its own message:

1. **Extraction non-empty.** Region DEF and Region CALL must each be non-empty, and the count of
   definition lines matching the guarded function name must be exactly 1, as must the count of
   capture-syntax call sites. An extraction that finds nothing must be a loud failure naming what it
   looked for. Comparing an empty extraction to an empty baseline is precisely the empty-collection
   vacuity shape this milestone exists to remove, and it is the failure mode a renamed or deleted
   function would otherwise produce.
2. **Region DEF identity.** Byte-for-byte equality against the baseline, reported as a drift result
   token naming the first differing line when it fails.
3. **Region CALL identity.** The same, separately — so disconnecting the check (deleting the call
   while leaving the function intact) is caught as its own named result rather than passing.

The guard contains no construct that converts a failure into success: no default-on-error branch, no
swallowed exit code, and its comparisons never take their status from the tail of a pipeline.

The failure message states plainly that the correct response is to revert the change to `doctor`,
not to update the baseline — the baseline is pinned to a commit and updating it to match a changed
implementation would make the guard self-confirming.
