## Decisions Made

- **Controller in its own file.** `mix crosswake.install`'s `infer_router_module!/1` raises
  `could not infer one router module ... ensure --router names a file containing exactly one
  top-level defmodule` when a file has two top-level modules. The first real run hit exactly
  this. Fix: moved `CleanRoomHost.PageController` into `lib/clean_room_host/page_controller.ex`,
  leaving `router.ex` with only `CleanRoomHost.Router`.
- **`use Phoenix.Controller, formats: [:html]`** rather than bare `use Phoenix.Controller`, to
  avoid the "must receive the :formats option" compile warning surfaced on the first real run
  (harmless under normal `mix compile`, but avoided since `mix compile --warnings-as-errors`
  runs earlier in the harness and a stray warning anywhere is worth naming explicitly rather
  than leaving unexplained).
- **Reordered the Done-section's two final log lines.** The pre-existing script always printed
  `log "Next safe command: ..."` after the `state=passed` completion line — meaning the true
  final line of every run was the hint, not the completion marker. This predates this plan and
  is not itself part of TODO-011's diagnosed defect, but it directly contradicts this plan's own
  acceptance criterion ("the committed log's final line is the script's `state=passed`
  completion line"). Fixed by printing the hint first: `state=passed` is now genuinely the log's
  last line. Verified by re-running the harness after the change and inspecting `tail -1`.
- **New Step 6.5, not a renumbered Step 7.** Chosen and stated per the plan's instruction to
  "pick one and be consistent, and say which in the SUMMARY." Step 7 (doctor) is untouched in
  invocation, flags, and exit-0 assertion.
- **Matrix path's own `mix crosswake.install` extension is deferred**, per the plan's scope
  boundary: ROADMAP SC#2 names the legacy path alone, and the matrix path sits on the
  pull-request critical path (10 invocations) while the legacy path runs post-publish only.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] `infer_router_module!/1` rejected the two-module router.ex file**
- **Found during:** Task 1, first real run of the harness
- **Issue:** `CleanRoomHost.PageController` and `CleanRoomHost.Router` were both defined in
  `lib/clean_room_host/router.ex`. `mix crosswake.install`'s `infer_router_module!/1` parses the
  `--router` file and requires exactly one top-level `defmodule`; two modules made it raise.
- **Fix:** Split the controller into a new `lib/clean_room_host/page_controller.ex` heredoc,
  leaving `router.ex` single-module.
- **Files modified:** `script/verify_companion_cleanroom.sh`
- **Verification:** Re-ran the full harness; installer completed, doctor reached green.
- **Committed in:** `d04397a4` (part of the single Task 1 commit — the defect was caught and
  fixed before that commit was made, not as a follow-up).

**2. [Rule 1 - Bug] Committed log's final line was the "Next safe command" hint, not
`state=passed`**
- **Found during:** Task 1, verifying acceptance criteria against the first successful run's log
- **Issue:** The pre-existing (unedited-by-this-plan) Done section printed the completion `ok`
  line, then a `log "Next safe command: ..."` hint after it — so the log's true final line was
  never the completion marker.
- **Fix:** Swapped the order of the two `log`/`ok` calls in the Done section.
- **Files modified:** `script/verify_companion_cleanroom.sh`
- **Verification:** Re-ran the harness; `tail -1` of the resulting log is the `state=passed`
  line.
- **Committed in:** `d04397a4`.
