  attestation (`ios-mirror-backfill.yml` job `attest-companion-receipt` and

  mirror has root tree `b80f3bf0…` and `refs/tags/ios-core-v0.2.11:packages/crosswake-shell-core-ios`
  is the same tree. Commit SHAs differ by design (the mirror is a split).

Write `script/check_ios_mirror_release_tag.sh` (bash, `set -euo pipefail`, executable). Interface: exactly one
argument pair `--version X.Y.Z` (digits only per field); anything else prints a usage line and exits 2. Missing
`git` exits 2 with `reason=tool_unavailable`. Test seams, read only from the environment:
`CROSSWAKE_MIRROR_TAG_REMOTE` (default `https://github.com/szTheory/crosswake-shell-core-ios.git`) and
`CROSSWAKE_MIRROR_TAG_RELEASE_REPO` (default the repository root). The script always prints the remote it
read as `mirror-tag: remote <url-or-path>` so evidence shows which mirror was checked.

Checks, in this order; the first failure decides the reason (exit 1 unless stated):
1. Release side, local reads only: `refs/tags/ios-core-v<V>` and `refs/tags/hex-v<V>` exist in the release repo
   (else `source_tag_missing`, and the message tells the operator to run `git fetch --tags origin`);
   both peel to the same commit (else `linked_tag_mismatch`); `.release-please-manifest.json` at that commit has
   `"."` and `"packages/crosswake-shell-core-ios"` both equal to V (else `manifest_version_mismatch`).
   The source tree is `git rev-parse refs/tags/ios-core-v<V>:packages/crosswake-shell-core-ios`.
2. Mirror side, unauthenticated: list tags with `git -c core.askPass= ls-remote --tags`, three attempts as in the
   parity script; exhaustion prints `verdict=UNVERIFIED reason=mirror_unreachable` and exits 3. No `v<V>` tag:
   `mirror_tag_missing`. Fetch only that tag (`--depth 1`) into a fresh bare repository under `mktemp -d`
   (never into the release repo, so no ref there changes) and read its root tree; a fetch failure is
   exit 3 `mirror_fetch_failed`. Tree differs from the source tree: `tree_mismatch`.
3. Newest-tag rule: the highest `v<semver>` tag on the mirror (numeric sort per field, `^{}` peel lines folded)
   must equal V; otherwise `newer_mirror_tag` naming the newer tag. This makes the command a post-publish check
   for the release just published; asking it about an older version fails by design.
On success print one line:
`mirror-tag: version <V> source_tag ios-core-v<V> source_tree <12hex> mirror_tag v<V> mirror_commit <12hex> mirror_tree <12hex> newest v<V> verdict=PASS`
and exit 0. Every failure prints the same leading fields known so far, then `verdict=FAIL reason=<reason>` (or
`verdict=UNVERIFIED reason=<reason>`) as the last line, plus one `[crosswake] What to do next:` line. Never print a
URL with userinfo, a token or an environment dump. No remote write of any kind exists in this script.

Write `test/crosswake/release_candidate/mirror_release_tag_test.exs` (`use ExUnit.Case, async: true`, network-free). A
helper builds, under `System.tmp_dir!/0` per test, a release repo (`packages/crosswake-shell-core-ios/Package.swift`
plus one source file, `.release-please-manifest.json` with both keys at V, tags `hex-v<V>` and `ios-core-v<V>` on the
same commit) and a bare mirror whose `v<V>` commit holds a copy of that package directory at its root (same file
bytes and modes give the same tree id). Tests, each asserting both the exit status and the exact
`verdict=` and `reason=` tokens on the last line: (1) PASS, also asserting the PASS line carries all
seven named fields with non-empty values; (2) `source_tag_missing`; (3) `linked_tag_mismatch`; (4)
`manifest_version_mismatch`; (5) `mirror_tag_missing`; (6) `tree_mismatch` (mirror copy with one byte changed); (7)
`newer_mirror_tag` (extra mirror tag at the next patch version); (8) exit 3 `mirror_unreachable` with a remote path
that does not exist; (9) exit 2 for a malformed version. Use explicit equality assertions, not collection
predicates over possibly empty lists (the Phase 196 absence guard rejects those).

Real runs, each command alone, outputs appended to the evidence file with an `rc` line after each:
`git fetch -q --tags origin`, then `bash script/check_ios_mirror_release_tag.sh --version 0.2.11` (expected PASS),

the real negative control). If 0.2.11 does not pass, stop: that is a real finding about the published mirror,
recorded in the evidence and the SUMMARY; never weaken a check to make it pass.
