<objective>
Pin the exit-code contract so it cannot silently drift from its documentation, and point the
runbook at the single canonical source.

Purpose: the phase just introduced a third exit code across two entry points while deliberately
leaving `2` reserved to three unrelated existing meanings. Without a guard, the next change to any
of these files can renumber a code and nothing notices — which is the same class of defect
(a contract that nobody re-measures) this whole milestone exists to close.

Output: a drift-catching guard test with a declared per-entry-point expectation table and a
measured non-vacuity floor, plus a runbook link.
</objective>

`script/check_release_version_truth.exs`'s `BLOCKED` from exit 2 to exit 3, along with
`test/crosswake/proof/phase168_version_truth_test.exs` and `docs/COMPANION-PUBLISH-RUNBOOK.md:216`.

add a third and fourth file to the phase's blast radius for a consistency gain whose only caller
(`.github/workflows/crosswake-ci.yml:190`) already treats any non-zero as failure. The guard test
built here declares `2` as that script's expected BLOCKED value, so the decision is recorded as a
check rather than as prose — and a future phase that takes the sweep will see this test go red,
which is the correct prompt to update the table deliberately.
