<objective>
Give the release verification command a third, honest answer: "I could not verify this."

Purpose: today `mix crosswake.release.status` can only say clean (0) or defect (1). A scanner that
never ran therefore reports the same thing as a scanner that ran and found nothing wrong — the
milestone's core "absence scored as success" defect, at the one command the maintainer actually
runs. `exit_code/1`'s catch-all `def exit_code(_status), do: 0` is the live fail-open hazard that
makes adding a new status atom dangerous unless both functions change together.

Output: `:unverifiable` as a first-class status wired through `aggregate_status/1` AND `exit_code/1`
in the same change, the two crash-shape classifications from D-03, the D-08 cascade pointer, D-17's
microcopy, and a Mix task that can actually reach OS exit 3.
</objective>
