# Phase 193 post-189 backup record

This record lists what was copied to `<backup-root>` after Phase 189 and why. Phase 189 backed up the recovery checkout, its branches, stashes and the temporary folders that existed then. Work done since then lives in places no earlier backup covers: two sibling clones, new temporary folders from Phases 190 and 191, one stray checkpoint bundle file, and plain planning files written in the recovery checkout.

What was added, all as new files (nothing was deleted, moved or overwritten):

- `integration-191-trials.bundle` holds the trial branches of the integration clone (`carry-trial`, `carry-trial-2`, `carry-trial-3`, `land/v25-v27`, `candidate-src`). It has complete history (no `^origin/main` prefix) so it restores into an empty repository; this is the intent of D-07 as settled by D-23. `carry-trial` and `carry-trial-2` are not on `main`; the others are.
- `post189-tmp.tar` holds, per temporary folder, a full file list (relative path, size, sha256) and every loose file outside the re-derivable trees (D-22). The tree folders `cut*.d`, `dryrun.d`, `sync.d`, `fin-*.d`, `npm10`, `work` and `compare-build` are listed but not archived.
- `crosswake-checkpoint-24c8389.bundle` was copied into `<backup-root>` because no 189 sums file held it.
- `post189-dirty.tar` holds the recovery-checkout files that differ from every earlier backup and from `main`; only counts appear here.
- `SHA256SUMS.193` lists a sha256 line for each new artifact; `SHA256SUMS.193.count` holds the line count.

Each artifact passed the 189 restore check (`restore <artifact>: pass`) before it was installed. The recovery checkout has had no git write. One temporary entry named in the plan (a one-line output file from the 191 locate step) no longer existed when this backup ran, so the temporary rows cover the ten entries that were present.
