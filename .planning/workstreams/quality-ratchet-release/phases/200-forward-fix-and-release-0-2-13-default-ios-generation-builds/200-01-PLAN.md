## Why this fix (Claude's Discretion, settled at planning time)

Chosen: the default path writes `CrosswakeHostSettings.xcconfig` once, rendered from the same
`CrosswakeHostSettings.xcconfig.eex` with the unconfigured defaults `app_bundle_id` `dev.crosswake.shell`,
`code_sign_style` `Automatic`, `team_id` empty. Reasons, all measured:

- The pbxproj template also sets `PRODUCT_BUNDLE_IDENTIFIER = "$(CROSSWAKE_APP_BUNDLE_ID)"` (and the tests
  target `$(CROSSWAKE_SHELL_TEST_BUNDLE_ID)`), so dropping the references alone would leave an empty bundle id;
  the 0.2.11 template's literal default was `dev.crosswake.shell` (the Android default `applicationId` is the
  same), so this restores the 0.2.11 identity honestly as a placeholder.
- No template changes: the template hash pinned by `test/crosswake/proof/phase134_template_version_drift_test.exs`
  and `@template_version 4` stay unchanged, and `IOSHostGeneration.render/2` (the declared path) is untouched,
  so `production_generation.sha256.json` holds byte for byte.
- Honest ownership: on the default path the file is a host-owned scaffold written by `ensure_file/2` (never
  overwrites a host edit), not a managed output. A default-generated target that later declares `:ios_host`
  already blocks with cause `conflict` before this fix (the default path writes `Fixtures/crosswake_manifest.json`
  with no managed metadata and `ManagedOutputs.classify_file/4` reads a present file with nil metadata as
  conflict), so this adds no new failure class.
- Planning-time checks with exactly these settings: the `--local` form built (`BUILD SUCCEEDED`, 7 s), and the
  no-flag form with its `minimumVersion` set to 0.2.12 resolved `CrosswakeShellCore @ 0.2.12` from the public
  mirror and built (`BUILD SUCCEEDED`, 8 s); without the file both failed with exit 65.
