## Flagged assumptions (edge probe)

- DOCS-01 edge row `unclassified` (status unresolved). The doc/registry version boundary has two
  forms, and `since=` alone covers only the first: (a) a step whose command or function does not
  exist in the version under test fails when executed (the run, compile or compile-warning rule
  catches it); (b) a step that executes cleanly but that the version under test never reads, such as
  a config key appended to `config/config.exs` that 0.2.11 ignores, passes execution while
  certifying nothing. `:ios_host` is a case of (b): 0.2.11 (`7273e6cf`) does not read it (it landed
  in Phase 179 after the release). Case (b) is handled by the version-conditional `:ios_host` rule
  built in 197-07 (D-04 amendment) and, for the other required steps, by the reader audit in 197-09,
  which checks the published 0.2.11 tarball for each executed step's reader. Any further boundary the
  executor finds (for example a step that works only on one Phoenix generator version) is recorded
  in the summary, never silently accepted.
