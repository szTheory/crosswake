### Visible study, installed media and lifecycle

- **D-05:** Retain the intended ownership: the ordinary visible offline-island action sends a typed, correlated host command; a reference-host adapter owns foreground acquisition, installed asset resolution, verification and AVFoundation playback. Core retains only its existing pack lifecycle/denial and bridge contracts. Do not require WebKit to decode native files, introduce a URL scheme/file bridge, or import the separate physical proof UI/driver as the tested app.
- **D-06:** Subject to D-04, the smallest host composition is a real reference media fixture fetched from the run-owned HTTP endpoint, size/hash verification, atomic installation/readback, a private asset resolver, and a strongly retained host playback delegate. Current shell fixtures are opaque installation bytes; the physical host's playable bundle is precedent, not proof of this join. A bundled copy installed while online does not establish network acquisition. Reuse a small host-owned implementation pattern before adding a dependency; no archive framework/CDN/auth product is selected.
- **D-07:** Prove the action comes from the same visible study WebView/controller: native callback/controller and `message.webView` identity, main-frame/security-origin validation, route/capability admission, correlation and reply, installed-byte identity, and player start/progress. Page-provided origin/nonce fields alone are insufficient. Host-local wrapper/observation wiring is preferable to a public observation protocol. Bind the player input to the bytes actually verified, avoiding a hash-then-open substitution. Respect provider actor and UI/player lifetime boundaries; keep hashing/acquisition from blocking UI. These are acceptance constraints, not a mandate to rewrite concurrency.
- **D-08:** Verify actual request failure at the tested target's transport boundary using an invocation-owned loopback fault boundary. Keep separate observations for WebView requests and native acquisition when each is claimed. A synthetic offline event, `navigator.onLine`, `NWPathMonitor`, Playwright toggle, backend 503, or an assumed `URLProtocol` interception of WebKit cannot substitute. Installed playback must use local verified bytes with no remote fallback. Do not disable laptop networking or create a generic proxy/networking service.
- **D-09:** Keep one installed app, primary origin and persistent WebKit data store through offline writes, true process termination/relaunch and replay. Observe the actual island's retained outbox before/after without exporting content. No reinstall, reset argument, store replacement, native journal substitution or browser page reload can satisfy T05. Reset only the fresh owned context before the journey, and after the required uninterrupted observations when preparing explicitly separate fault cases.

### Normal host mutations, authority and isolation

- **D-10:** The visible island currently offers selected rating controls and queues rating data; backend support for `free_form_answer` does not establish a visible free-form path. A bounded free-form input/action in this existing reference island, committed to its normal outbox and replay path, belongs to T03. No native/test-injected record may substitute. Preserve existing selected-answer browser tests and fixtures.
- **D-11:** T07 needs server-backed rejection and conflict, retained work, and a useful host-owned recovery action. The current controller reports recovery unavailable and has no positive saved-answers destination. If later work proceeds past D-04, provide the smallest explicit reference-host route/action that lets the active scope review retained work and return/retry only when host state allows; preserve user agency and never silently discard or overwrite work. A closed unavailable state is honest but does not complete a required positive recovery observation. Do not infer any adopter route or build generic reconciliation UI.
- **D-12:** Use the existing SQLite/Ecto/Phoenix host and real committed cross-process HTTP. Ecto Sandbox remains for in-process tests. Do not add Postgres, Testcontainers, a queue system, a second host or an external testing platform for this milestone. Duplicate delivery must yield one durable domain effect through the real transaction/constraint; the ordinary app owns replay and outbox removal. Prefer an observed lost acknowledgement followed by the normal same-mutation retry where the current path supports it; direct test HTTP alone cannot replace normal app replay.
- **D-13:** Own a fresh database under the private run root, exact Phoenix child, exclusive loopback listener and fresh app/test context. Verify resolved database path and loopback binding before migration or mutation; no fallback database, default row deletion, fixed-port server reuse or attaching to an existing process. Synthetic session/fault controls remain test-gated and limited to this run's loopback host. They prepare faults; an independent owner must observe the fault and actual denial/effect.
- **D-14:** Bind the server exclusively to the prepared candidate's exact declared primary origin, including port, and preserve it throughout the lifecycle. Occupied port means blocked with a concrete preparation action, never attach or kill. Port `0` is only viable if an already-supported explicit preparation step chooses and freezes the port before generation; the verification runner cannot silently regenerate the app or mutate its origin after expected identities are frozen. Auth and media origins remain separate from route/bridge authority.
- **D-15:** Reauthorize each replay through current session/scope/route/flag/domain owners. Observe logout/account-switch fencing before another scope acts, zero cross-scope effects, entry and replay disablement independently, and retained queued work. Fixture authority is explicitly `synthetic_test_authority`; it establishes no real adopter session, provider or identity claim. Fault controls cannot submit a canned accepted result or grant replay authority.
- **D-16:** Bound the entire run and each subprocess; track exact owned child/process-group handles, terminate and reap only those resources, and verify cleanup. Killing a BEAM task does not establish termination of `System.cmd` descendants. Do not discover a PID by port and terminate it. Preserve the first safe failure result; repairs create distinct runs instead of retry-to-green or overwriting failures. Runtime database/media/outbox content stays in its normal ephemeral owned storage and is never copied into proof attachments or diagnostic archives.

Never retain raw answers, media, transcripts, credentials, account/scope references, tokens or stable device identifiers in telemetry, logs, doctor, receipt, aggregates or proof artifacts. Retain only screened safe diagnostic projections. If a cause cannot be retained safely, explicitly say the cause was not retained; do not guess it or replace it with a later failure.
