- **Paragraphs.** A paragraph is one of: a blank-line-delimited block of prose; a single Markdown table row; or a single JSON string value (for JSON evidence and the PR body).
- **Scope.** A paragraph is in scope when it mentions SPEC-04, Muex or pilot anywhere. Every sentence in an in-scope paragraph is evaluated, including pronoun follow-ons ("It is complete.") that do not repeat the subject. Cross-paragraph rule: in the paragraph directly following an in-scope paragraph, any sentence with a completion/adoption verb and no named subject is also in scope. Controls: "It is complete.", "Passed." and "Adopted." refuse in that position, and "SPEC-01 passed." there is not swept in.
- **Sentences.** Split each in-scope paragraph into sentences on period, semicolon and newline.
- **Clauses.** Split each sentence into clauses on commas, on the pipe character | (so each Markdown table cell is its own clause), and on the conjunctions and, but, while.
- **Refusal.** An in-scope sentence refuses when one of its clauses contains a completion/adoption verb form (complete, completed, pass, passed, satisfied, adopt, adopted, drop, dropped, delivered) and that same clause has no negation or move marker (not, no, never, without, neither, nor, pending, moved).
- **Scope of markers.** A marker in another clause or another sentence does not exempt it.
- **Writer guidance.** Write SPEC-04/Muex text in its own paragraph, or its own table row. Any other requirement's pass/complete wording that shares a paragraph with it refuses; this deliberately fails closed. A subject-less completion sentence without a requirement ID (e.g. "Crosswake CI passed on the PR head.") directly after a SPEC-04 paragraph also refuses, so place CI/status prose before the SPEC-04 paragraph or name its subject explicitly.
- **Exempt files.** The byte-preserved roster files (including 196-13-SUMMARY.md and 196-14-SUMMARY.md) are exempt from the prose scan because the digest check already pins them to their anchor bytes.
