# Phase 198 Plan 09: Foreign-host proof Summary

**One command, `bash script/verify_android_foreign_host.sh`, generates a host with the published Hex generator, builds it against Maven Central in a clean HOME with no credentials, proves the run is not vacuous, and requires a wrong-coordinate control to fail for the right reason.**

## What was checked and what happened

Task 1 (tracer): the script was run for real against the live registries. It picked V = 0.2.11 (the highest
version present on both Maven Central and Hex today), generated the host from the published generator,
resolved `io.github.sztheory:crosswake-shell-core-android:0.2.11` from Maven Central, passed two host-owned
JVM tests, matched the cached AAR to Maven's published digest, and the wrong-coordinate control failed with
both required Gradle messages. Task 2: the hermetic selftest runs 21 cases in about 10 to 18 s.

This is JVM evidence of consumption of a published artifact. It was not run on an emulator or a device and
it proves the published 0.2.11 generator (template_version 3), not this checkout's generator (template
version 4). When 0.2.12 publishes, the same leg exercises template version 4 automatically.

## Accomplishments

- Seven legs with the clean-room output contract (`foreign-host: leg ...`, `FAIL <leg> <reason>`, `result`), exit 0/1/2, selftest overrides refused without `FOREIGN_HOST_SELFTEST=1` (exit 2).
- Anti-vacuity: `tests >= 1` with no failures, errors or skips and both named testcases present; the probe class must load from `<artifact>-<V>-runtime.jar` under the run's own physical GRADLE_USER_HOME caches (C1, no `transforms-4` literal); cached AAR sha256 equals Maven's; generated settings has no local repository, no core include and no `project(`.
- Control preconditions (positive leg passed, negctl `.pom` is 404, exactly one line differs, `--dry-run` exits 0 in the same clean env), then an exact two-message match; `Could not GET`, `UnknownHost`, `Read timed out` and `Connection` classify as inconclusive, never PASS.
- Build runs under `env -i` with an allowlist (PATH, HOME, GRADLE_USER_HOME, ANDROID_HOME, ANDROID_SDK_ROOT, TMPDIR, LANG, JAVA_HOME if set); the selftest proves a `GITHUB_TOKEN` and an `ORG_GRADLE_PROJECT_*` variable in the caller's environment never reach Gradle.

## Selftest reds (mutation evidence)

The selftest passed on its first run, so no RED fixture failed against the script. To check the tests can fail,
seven one-line mutations of the script were run against a scratch copy: dropping the inconclusive pattern, the
AAR digest compare, the probe-source classification, the negctl 404 precondition and the coordinate check each
turned exactly the matching case red. Two mutations survived by design or by gap: lowering `tests >= 1` (the
zero-tests case is still caught by the independent testcase-presence check, so the two guards overlap) and a
Maven-metadata transport failure (a gap; closed by adding a Maven metadata failure sub-case to case 3, after
which the suite still ran 21 tests green).
