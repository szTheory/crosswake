Create the checker (stdlib only: argparse, glob, os, re, subprocess, sys, xml.etree.ElementTree). Defaults resolve from the repository root (`Path(__file__).resolve().parent.parent`): results dir `packages/crosswake-shell-core-android/build/test-results/testDebugUnitTest`, source dir `packages/crosswake-shell-core-android/src/test`, build file `packages/crosswake-shell-core-android/build.gradle.kts`.

`--run` executes `./gradlew --no-daemon cleanTestDebugUnitTest testDebugUnitTest` with `cwd` the `--package-dir` directory (default `packages/crosswake-shell-core-android`) and `CROSSWAKE_ANDROID_CONNECTED_TESTS=0` added to the inherited environment; a non-zero Gradle exit prints the verdict with `reason=gradle_failed` and exits 1 (test failures surface here too; the XML is still evaluated and its reasons printed). The clean task is what makes the XML fresh (an unchanged task reports UP-TO-DATE).

`junit_totals` reads every `TEST-*.xml` in the results dir, sums `tests`, `failures + errors`, `skipped`, records per-suite counts and every testcase `(classname, name, passed)`, and flags a suite name seen in two files (`duplicate_suite`; this is how a debug-plus-release double count shows). `source_test_count` counts lines matching `^\s*@Test\b` in `*.kt` under the source dir, minus `@Test` annotations adjacent to an `@Ignore` line. `build_file_violations` returns `serialization_dependency_present` if the build file text contains the Kotlin serialization JSON coordinate or plugin id, and `webkit_comment_untruthful` unless the line before the `androidx.webkit` dependency mentions `addWebMessageListener`.

`LOAD_BEARING_TESTS` (classname, name) pairs, each must exist and pass: BridgeConformanceTest `all bridge contract vectors pass status and denial-reason assertions`; BridgeChannelBoundaryTest `envelope rejects non string required fields on the JVM`, `origin near misses are denied with origin_denied`, `request claimed packs never satisfy route pack authority`, `deny reply has an empty payload and never echoes a request secret`, `denial happens before side effects with a positive control`, `listener gate allows only the main frame from the exact allowed origin`; SemVerBoundaryTest `negative plus signed and overflowing components fail closed`. Use the exact names Plans 01 and 02 committed (read them from the XML; if a name differs, use the committed name and record it in the SUMMARY).

`evaluate` returns reasons in a fixed order (no_results, duplicate_suite, failures, skipped, below_floor, count_mismatch, boundary_below_min, named_test_missing, then build-file reasons); the printed verdict names the first, and every reason is printed on its own `kotlin-floor: reason <r>` line. A comment above `FLOOR` says it is a ratchet floor (raise, never lower) and that the current count is derived, never pinned.
