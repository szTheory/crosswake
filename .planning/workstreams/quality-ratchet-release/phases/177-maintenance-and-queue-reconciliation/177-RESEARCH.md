## Common Pitfalls

### Pitfall 1: Whole-file or plan-number cleanup

**What goes wrong:** Removes a useful inspector or a still-supported mode alongside a spent writer.  
**Why it happens:** Module/file names group jobs that have different lifecycle and authority.  
**How to avoid:** Review each mode and handler separately; test retained reader output against preserved archived artifacts; retain unclear candidates with owner, missing fact, and next action.  
**Warning signs:** A deletion is justified only by age/plan number, a newer helper name, or few literal `rg` hits.

### Pitfall 2: Caller grep treated as proof

**What goes wrong:** Dynamic task names, workflow stage references, shell indirection, or generated/package exposure remain unreviewed.  
**Why it happens:** Literal call sites do not cover runtime composition or distribution paths.  
**How to avoid:** Trace the D-06 ownership edges from each behavior and use mode denial tests on actual task entry points. Treat package membership as exposure; absence of matches as uncertainty.  
**Warning signs:** Only `rg` output or docs visibility is cited as unreachability.

### Pitfall 3: Fail-closed behavior is deleted with the old route

**What goes wrong:** Unexpected/retired modes can reach credential lookup, a live request, subprocess, evidence write, or consume an approval before rejection.  
**Why it happens:** Guard tests appear coupled to a retired invocation and are removed as a group.  
**How to avoid:** Keep tests for enduring invariants; assert actual return shapes and no side-effect callbacks; where a production adapter participates, use a temporary fixture that exercises real subprocess output. [CITED: `177-CONTEXT.md` D-09–D-10; tests and adapter owners in CONTEXT canonical refs]
  **Warning signs:** Test count falls and unsupported input now parses or reaches adapter setup.

### Pitfall 4: Queue completeness inferred from one bounded page

**What goes wrong:** Missing items are silently recorded as an empty or complete queue.  
**Why it happens:** A CLI default limit, incomplete cursor loop, issue connection containing PR relationships, or transient access error is mistaken for an authoritative roster.  
**How to avoid:** Keep separate issue/PR counts and cursors, unique IDs, page completeness, error state, and end-of-read roster refresh. Record observation start/end and drift.  
**Warning signs:** Counts match an earlier research snapshot or there is no explicit `hasNextPage`/cursor exhaustion evidence.

### Pitfall 5: Historical outcome rewritten by current success

**What goes wrong:** Old failed attempts, Phase175’s 8/9 completion and REL-10 breach, or validation debt are described as resolved without evidence for the same work.  
**Why it happens:** A later release success or a duplicate issue is treated as retrospective proof.  
**How to avoid:** Keep historical artifacts and verdicts immutable in meaning; a supersession disposition names a verified replacement and demonstrates that unique findings remain represented.  
**Warning signs:** Archive edits accompany active-pointer repair or issue closure is based on title/age/bot provenance.

### Pitfall 6: Local “read” command has hidden writes

**What goes wrong:** A task writes receipts/caches or touches `evidence/` while merely used for caller discovery.  
**Why it happens:** Mix compilation, `prepare` modes, or receipt-producing code is assumed read-only.  
**How to avoid:** Run checks and fixtures only in the qualified isolated surface; inspect before/after source and artifact state; never exercise spent production collector/write modes for discovery.  
**Warning signs:** New receipt files, `_build`/cache drift, or generated output changes after a supposed read.

### Known Threat Patterns

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Retired mode still accepts stale attempt/approval authority | Elevation of privilege | Remove or narrowly deny before credential, network, subprocess, evidence-write, or approval-consumption boundary; never forward the old authority. |
| Incomplete/duplicated queue pages appear complete | Tampering / repudiation | Reconcile separate object-kind counts and unique keys, fully exhaust cursors, refresh roster, and preserve incomplete/drift status. |
| Queue body/log or private archive pointer copied into committed evidence | Information disclosure | Metadata-first; allowlisted sanitized extraction; never write credentials, adopter data, private paths, or raw sensitive payloads. |
| Reader removal erases historic failure evidence | Repudiation | Validate archived receipts before deletion; preserve history and record supersession only when exact replacement coverage and unique findings are proven. |
| “Read-only” Mix check changes local artifacts | Tampering | Use the qualified isolated surface; compare source/artifact state before and after all compilation, generation, inspection, and subprocess commands. |
