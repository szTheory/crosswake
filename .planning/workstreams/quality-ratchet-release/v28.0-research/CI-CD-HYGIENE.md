# CI/CD Efficiency, Correctness and Repo Hygiene (v28.0 rolling-roadmap research)

Measured 2026-10-24 with read-only `gh` against the public repo (main at af1f4f67, #245). Sample: last 400 workflow runs (since 2026-09-24, 30 days) plus per-job reads of selected runs. Two user decisions applied: **Android is unfrozen ASAP** and **fix the release pipeline near-term, then release on a milestone cadence with a one-use allow per publish**.

## 0. Facts that change the premise

- There are **27** workflow files, not ~37: 15 `phaseNN-proof*.yml`, 1 main CI (1762 lines, ~49 jobs), release/publish (release-please, hex-publish, ios-mirror-backfill, ios-tag-recovery, maven-publish-fire-drill, clean-room-proof-rehearsal, exact-public-proof), plus audit/collateral/cancel controllers.
- The repo is **public**, so Actions minutes (including macOS) are free. The cost of CI is **wall clock and signal quality**, not money. Do not optimize "macOS minutes"; optimize time-to-green and trust.
- Branch protection requires exactly one context, `Crosswake CI` (strict/up-to-date on). That context is the aggregator job `merge-blocking-crosswake-ci`. Repo allows merge commit, squash, and auto-merge; `delete_branch_on_merge` is already true.
- All `uses:` references in workflows and composite actions are SHA-pinned (grep for non-hex refs: zero hits). Several carry mismatched version comments (see 2.4).

## 2. Correctness findings

### 2.1 The release PR is structurally red (highest-value finding)
PR #236 (0.2.11 to 0.2.12) fails 9 required jobs. In every one of the 8 test jobs the failures are the same three tests:
`HostCommandSeamFixtureTest` (committed Swift seam fixture vs fresh Elixir render) and `Gen.ShellOriginModeTest` (Info.plist golden says `Generated by crosswake 0.2.11`, generator now emits `0.2.12`). release-please's `extra-files` bumps `mix.exs`, README, manifests, gradle files, but **not these goldens**, so every release PR will fail until a human fixes it by hand, and the fix lands on a bot branch. This is also why every `release-please--*` run is a failure pattern (4 of 5 on the main component).
Fix (S): make the goldens/fixture comparison version-independent (normalize the `Generated by crosswake X.Y.Z` line in the test, one copy-paste regex) or add the goldens to `extra-files` with `x-release-please-version` markers. Prefer normalization: it removes a coupling instead of adding another file to keep in sync.

### 2.2 Dependabot PRs fail because tests assert exact SHA pins
#210 (checkout), #211 (setup-beam) fail the same 8 jobs: `Phase153IosMirrorUnblockTest` asserts the literal string `actions/checkout@9c091bb... # v6.0.2` in the parity workflow. Any Dependabot bump of a pinned action makes the repo's own test red. #239/#240/#241 pass only because their action is not asserted. Meanwhile the checkout SHA in the same file (`3d3c42e5...`) differs from the test's expected one, which means the test currently also encodes a stale expectation for a different job. Fix (S): assert "is a 40-hex SHA with a version comment" rather than a specific SHA (this is also what SEED-022 wants).

### 2.3 Gates that pass while asserting nothing
- Aggregator `merge-blocking-crosswake-ci` is the single required check; it is protected by `proof-aggregator-negative-control` and the daily audit. Good, and the failure path was observed (it fails when children fail: "Conclude the governed proof graph" red on #236). Skipped jobs on the docs fast path are intentional via `classify-change`; the classifier defaults to `full_proof` on checkout/validation failure (fail-closed, good).
- `continue-on-error` count: 1 in CI (classify checkout, deliberate and fail-closed), 1 to 3 in each phase workflow and native-collateral-advisory (advisory by design). No required lane uses it.
- Piped exit codes: no `| tail`/`| tee` gates found in required lanes. `ios-mirror-backfill.yml:187 | tee` and several `| tail -1` / `| head -1` on `git subtree split` are value extractions; `tee` there only masks the exit code if `pipefail` is absent. Verify `set -o pipefail` in that step (S).
- Same test suites run in 8 jobs (`hex-page-proof`, `phase130/132-core-hermetic`, `phase41`, `phase43`, `phase45`, `phase34`, `proof-requires-example-host` all executed the broad hermetic suite and all failed on identical tests). That redundancy multiplies signal noise: one real bug shows up as eight red jobs.
- Remaining "absence as success" candidates to measure before they gate: SEED-018 vacuous collection assertions, SEED-020 (compat matrix current version outside drift test). Measure findings first, per project rule.

### 2.4 Supply chain
- SHA pinning: complete. Version comments are inconsistent (the same checkout is labelled `# v7`, `# v6.0.2`), which is exactly SEED-022's unaudited surface. Cheap audit (S): one script that, for each pinned SHA, resolves the claimed tag via `gh api repos/<o>/<r>/git/ref/tags/<tag>` and fails on mismatch; run it inside the Dependabot-bump PR path rather than as a new lane.
- SEED-025 WR-01 (credential masking in public logs, Phase 192 review): ranks first in that seed, status dormant. Public logs are world-readable, so this is the only item in the seed that is an active exposure. Treat as immediate for review and fix (M): add `::add-mask::` before any value derived from secrets is echoed, and a CI-failure-output redaction test. I did not read the log content for secrets and did not copy any.
- Secrets present: HEX_API_KEY, MIRROR_PUSH_TOKEN, MIRROR_DEPLOY_KEY, RELEASE_PLEASE_TOKEN, BRANCH_PROTECTION_READ_TOKEN (fine-grained PATs expire <= 1y; the audit self-pages on expiry), Maven Central + signing key set. Do not rotate MIRROR_PUSH_TOKEN as a first reaction (memory note: wrong fix).
- Missing lanes noted by SEED-025: xcodebuild and example-host lanes. Evaluate after Android lanes; do not add before measuring.

## 3. Efficiency (measured)

### 3.1 What exists and works
Composite `setup-elixir-cache` (keyed on os/arch/OTP/Elixir/mix.lock) is used by most jobs; Android has `setup-gradle` with a config-hash context; Swift has a toolchain-identity cache key. Per-PR concurrency group exists, `cancel-in-progress: false` (deliberate, to avoid cancelled-as-red on required context). Path classification (`script/classify_ci_change.py`) already fast-paths docs. This is already good; do not rebuild it.

### 3.2 Largest waste: 14 weekly advisory duplicates
Every phaseNN-proof workflow runs weekly on Monday 06:00 UTC (4/4 success each, 0.1 to 2.6 min) and duplicates a job of the same name in main CI. They protect nothing that PR CI does not, and they are exactly the "one-time reconciliation lane" pattern. Retire the 14 `schedule:` triggers (delete the files, keep one weekly full-proof canary on main instead; S). Savings: 56 runs/30 days and 14 files of Actions-tab noise; the canary catches drift from dependency/runner updates when no PR ran.

### 3.3 Cancel Obsolete controller
99 runs, 99 success, fully non-authoritative by its own header, and CI already has a per-PR concurrency group (cancel-in-progress false for safety). Net effect: a 1.7 KB script that does nothing authoritative on every PR run. Retire the workflow and `script/select_obsolete_ci_runs.py` unless the Plan 165-10 probe is actually scheduled (S). If cancellation of superseded runs is desired for wall-clock, set `cancel-in-progress: ${{ github.event_name == 'pull_request' && !startsWith(github.head_ref, 'release-please--') }}` after the required-context behavior is verified: cancelled runs report as cancelled, which blocks merge only until a fresh run succeeds on the new head.

### 3.4 See It Run Collateral (macOS, 13/13 cancelled)
The `native` job captures iOS simulator and Android emulator screenshots and always times out at 35 min. It now blocks no one but wastes a runner and a failed-looking run on every shell-path push to main. Given Android is unfrozen, this is also the only emulator experiment in the repo and it has never completed. Recommendation: split it. Keep `web-and-gif` (completes in ~10 min). Remove the combined native job; re-introduce Android emulator proof as its own advisory lane per 3.5. (S to split, M to rebuild properly.)

### 3.5 Android lanes now that Android is unfrozen
Current: JVM unit, generated-shell JVM, BridgeChannel proof, phase79, phase67 JVM, all Ubuntu, in the required aggregator when `full_proof`; Maven Central publish proven by the fire-drill (9/9). Gaps and cost, in order:
1. Emulator/instrumented tests: GitHub Linux x64 runners support hardware-accelerated emulation (KVM) for public repos; typical cold-boot job 8 to 15 min with AVD snapshot cache. Free on this repo. Start advisory (nightly cron plus label-gated on PR), measure flake over 20 runs, then promote to required only if flake < 2%. Reuse the already-present `.github/actions/setup-android-jvm` composite.
2. Android release verification: the release workflow must prove Maven Central staging and signing key before the real publish (the fire-drill already does this; keep it).
3. Remove "frozen" gating checks from CI classification only where they deny Android work (grep `classify_ci_change.py` for freeze rules; update requirements/ROADMAP/ADR together, per AGENTS.md).
Footgun: Android emulator on macOS runners is slow without nested virtualization; stay on Linux KVM.

### 3.6 Wall clock
Successful PR: p50 24.8 min, p90 35 min. Per-job max 12.6 min (hex-page-proof, phase130 core) on failure runs; successful sampled run total 134 job-minutes over 49 jobs. Queue wait was not directly readable (API 502 on one job list); treat as not measured. Highest-leverage: (a) fold the 8 duplicated hermetic-suite jobs so one real failure shows once, (b) deduplicate by running the root `mix test` once and sharding it, (c) leave caching alone. Expected gain: p50 from ~25 min to ~15 min and 8x less failure-noise. Effort M; do after the red-cause fixes since a red base hides regressions.
Merge queue: not enabled; SEED-007 recorded a ~2 h serial drain. With strict required checks and merge-commit-only workflow, merge queue (or auto-merge plus update-branch) is only worth it when more than ~3 PRs land per day; currently ~15 PRs in 30 days. Do not adopt a merge queue yet.

## 6. Standing hygiene mechanism

Compare with `docs/MILESTONE-BOUNDARY-HYGIENE.md` (143 lines): it is a manual runbook assuming "local main runs ahead of origin and syncs through a boundary PR", which no longer matches how work lands (AGENTS.md: branch from origin/main, PR per change). Sections 1 to 3 (worktrees, GSD state, changelog) are still relevant; section 5 (boundary PR from local main) is stale. Update it to a short checklist that points at the report below, rather than keeping parallel prose.

Recommendation: ONE scheduled, read-only workflow `repo-hygiene-report.yml` (weekly, Monday after the audit; also `workflow_dispatch`), permissions `contents: read, issues: write, pull-requests: read`, that maintains a single tracking issue (open, edit in place, auto-close when clean, same pattern as `required-checks-audit.yml`). It asserts, fail-silent-never:
1. Last 5 `main` runs of required context are green (red main opens the issue; this is the highest-value line).
2. Open non-bot PRs older than 7 days; release-please PR older than 14 days with red head.
3. Dependabot PRs older than 14 days (should be 0 after grouping).
4. Remote branches with ahead=0 or last commit older than 45 days and no open PR (stale list).
5. Tracked root-level files not in an allowlist (`git ls-files -- ':!*/*'` against `.github/root-allowlist.txt`) and any `*.bundle`/`*.patch` file anywhere tracked.
6. Workflow-file count and a "schedule:" lint: any scheduled workflow whose last 4 runs were all cancelled or all identical-duration success with no failure ever (candidate dead lane).
7. Secret/PAT expiry: BRANCH_PROTECTION_READ_TOKEN age.
It must refuse to report green if any API read fails (exit non-zero, UNVERIFIED), same invariant as the existing audit. Implementation is about 80 lines of `gh api` plus jq (copy the audit's issue helper; do not add a dependency). The milestone-boundary command then reduces to: run this workflow, read the issue, act on what is listed.
Do NOT build: a dashboard, auto-closing or auto-deleting bots (delete needs the allow gate), or auto-merge of Dependabot beyond what the allow gate permits.

## 8. Do NOT do
- Do not optimize macOS minutes (public repo; free) or adopt a merge queue at ~15 PRs/month.
- Do not use `--admin` merges, force-pushes to bot branches, or hand-edit release-please branches.
- Do not rotate MIRROR_PUSH_TOKEN to chase SEED-003; evidence shows the mirror works.
- Do not add new phaseNN-proof workflows, a dashboard, or an auto-deleting hygiene bot.
- Do not make any new check merge-blocking before measuring its findings and flake rate.
- Do not add Android emulator proof on macOS runners.
- Do not close the release PR as noise; it is the standing change ledger.
