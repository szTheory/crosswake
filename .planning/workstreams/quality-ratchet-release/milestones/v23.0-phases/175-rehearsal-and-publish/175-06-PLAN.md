<planner_notes>
**This plan carries the phase tracer.** Task 1 is the phase's single `type="tracer"` slice: the thinnest
path that runs the whole release machinery end to end — capture the candidate identity, dispatch a real
workflow against it, download the artifact it produced, assert its fields, and land the evidence in-repo
— while stopping at the last reversible step. If the machinery is wrong, it is wrong here, before any
one-way door, and at a cost of one dispatch rather than one publish. Tasks 2 and 3 expand the proven
slice sideways to the other two registries; the publish plans that follow expand it forward.

**Edge-probe accounting.** The spec-less probe surfaced 3 classified rows for REL-11 — adjacency,
empty, and ordering. Two are authored as resolved-explicit truths (the head-SHA equality rule, the
`package_count` non-emptiness rule) and one as a resolved-backstop marker (stable leg ordering in the
evidence index), which abstains to human review at verify time if it cannot be confirmed with explicit
evidence. **3 surfaced == 3 authored (2 explicit + 1 backstop) + 0 flagged.**

**Nothing here builds a rehearsal harness.** All three mechanisms already exist and already produced the
artifacts the canonical candidate receipt consumed at the previous release. Writing new ones would
duplicate proven mechanisms and reintroduce the second-copy-drift defect an earlier phase was built to
eliminate. This plan dispatches and records; it does not design.
</planner_notes>

<scope_boundary>
This plan is read-only with respect to every public registry. It dispatches three existing
`workflow_dispatch` operations whose read-only properties are structural — a dry-run publish, a dry-run
push, and a validated-then-dropped upload — and it records what they produced.

It merges no pull request. It pushes no tag. It publishes nothing. If a rehearsal cannot be made to run
against the real candidate ref, stop and report; do not substitute an older run's evidence and do not
proceed to a publish plan on the strength of a rehearsal that describes a different tree.
</scope_boundary>

evidence in the repository.

registry's own validation rather than a simulation of it.

index that gates 1, 2 and 3 read from.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| A moving pull-request head -> the ref a rehearsal describes | The candidate head can be refreshed between rehearsal and merge, so the rehearsed tree stops being the merged tree |
| A rehearsal job -> a real public registry | All three legs contact real registries; only their read-only properties keep them from mutating public state |
| Rehearsal artifacts -> the evidence a one-way-door gate is approved on | A field not asserted by value is a field nobody checked |
| Repository secrets -> the fire drill's signed upload | The fire drill is the phase's only proof that the eight publish credentials exist and work |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-175-29 | Spoofing | A rehearsal run against a different ref than the one that will merge | high | mitigate | Task 1 captures the head immediately before dispatch and records it; every leg reuses that identity verbatim; the publish plans re-compare at merge time and redo the rehearsal on a mismatch (D-33). |
| T-175-30 | Repudiation | Reusing a previous release's rehearsal evidence | high | mitigate | D-32 is stated in the action and in a prohibition; each leg's evidence records a run identifier from this phase and the candidate identity it ran against. |
| T-175-31 | Tampering | A rehearsal mutating real registry state | high | mitigate | The three legs' read-only properties are structural — dry-run publish, dry-run push, validated-then-dropped upload — and a prohibition forbids weakening any of them; Tasks 2 and 3 independently corroborate absence with `git ls-remote` and a live POM request. |
| T-175-32 | Spoofing | An artifact field recorded as passing without being read | high | mitigate | Every assertion names the field and its expected value, a missing field is defined as a failure, and the acceptance criteria grep the recorded values rather than a tick. |
| T-175-33 | Information Disclosure | Secrets leaking into rehearsal output or into the committed evidence | medium | mitigate | All three jobs emit structured receipts with explicit fields rather than raw command output; the evidence index records field values and run identifiers only, never a credential or a raw log body. |
| T-175-34 | Denial of Service | The fire drill's deployment reaching the published state, consuming the coordinate before the real release | high | mitigate | Task 3 asserts the drop confirmation explicitly and independently checks the public POM URL returns not-found; reaching the published state is defined as a full stop, not a workaround. |
| T-175-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable to this plan — it adds no package-manager install step. </threat_model>
