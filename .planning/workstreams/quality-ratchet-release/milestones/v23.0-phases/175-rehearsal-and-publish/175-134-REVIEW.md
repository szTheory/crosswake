## Critical Issues

### CR-01: Elixir rejects valid manifest versions above 1.x

**Severity:** BLOCKER  
**File:** `lib/crosswake/release_candidate/plan105_mirror_tag.ex:1818-1820`  
**Issue:** The metadata reader’s Node parser accepts canonical stable `MAJOR.MINOR.PATCH` values with arbitrary nonnegative major components ([plan105_mirror_tag_collector.mjs:770-773](<home>/projects/crosswake/script/release_candidate/plan105_mirror_tag_collector.mjs:770)), but this shared Elixir facts validator permits only major `0` or `1`. When the manifest contains a valid value such as `2.0.0`, Node returns an observed result, then the production Elixir adapter rejects it and seals the attempt as UNKNOWN. This makes exact-head version acquisition fail for valid future release lines.
**Fix:** For the v3 metadata scope, validate `pr.version` with the same canonical stable-version rule used by the Node manifest parser, allowing any nonnegative major while rejecting leading zeros and suffixes. Preserve the prior v1/v2 validation behavior if legacy compatibility requires it.
