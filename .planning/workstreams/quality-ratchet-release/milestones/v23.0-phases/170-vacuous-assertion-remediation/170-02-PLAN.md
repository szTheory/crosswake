<objective>
Freeze the `needs-fix` population into a closed-world remediation manifest, insert the uniform
one-line non-emptiness guard at each of those sites, and prove — per entry — that the guard exists
and guards the same expression the assertion consumes.

Purpose: VAC-02. An empty collection must now fail where it previously passed. The structural half
of D-12's hybrid proof catches guard-checks-the-wrong-variable, which a runtime test cannot reliably
catch; the manifest keeps the proof closed-world so it satisfies ROADMAP SC#3 by construction rather
than by inspection.

Output: `script/collection_assertion_remediation.json`, guard insertions at every remediated site, a
regenerated ledger, and `test/crosswake/proof/phase170_guard_expression_match_test.exs`.
</objective>

Create `test/crosswake/proof/phase170_guard_expression_match_test.exs`, module
`Crosswake.Proof.Phase170GuardExpressionMatchTest`.

Extract the check as a pure predicate over source text — `guarded_correctly?(source_lines, row)` —
so a synthetic fixture can prove it capable of returning false, rather than resting on "it currently
passes against a currently-clean tree". The predicate:
1. reads the line at `row.display`'s line number minus one;
2. requires it to be a non-emptiness guard call;
3. extracts the guard's argument with the same balanced-paren capture the inventory script uses;
4. normalizes both the guard argument and `row.expression` through the inventory script's own
   normalization, and requires them equal.

Step 4 is the half that matters: it catches a guard that checks a different but similarly-named
collection, which no runtime test reliably catches.

Population source: `Jason.decode!(File.read!("script/collection_assertion_remediation.json"))`. Do
NOT hand-type a second copy of the row list inside this module — two lists that can silently
disagree about what was fixed are exactly the duplication D-18 forbids one level up.

Tests to write:
1. A guard-presence-and-match test that iterates every manifest row, collects the failures, and
   asserts the failure list is empty with a message naming the first offending row's `display`.
   Iterate in the manifest's committed order so the first-named failure is stable across runs.
2. A non-vacuity control (D-14): build a synthetic source-line list in memory with the guard line
   removed and assert `guarded_correctly?/2` returns false for that row.
3. A second non-vacuity control: build a synthetic source-line list where the guard is present but
   its argument is a different identifier, and assert `guarded_correctly?/2` returns false.
4. A population-floor test asserting the manifest's row count is greater than zero and equals a
   hard-coded `@remediated_site_count` module attribute set from the real measured number — the

5. A ledger cross-check test asserting every manifest key is present in
   `script/collection_assertion_ledger.json` with bucket `safe-guarded`.

Per D-13, this test enumerates only the frozen manifest keys. It must not scan the tree for new

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| committed remediation manifest → structural test | A human-editable JSON file defines the closed world the proof covers; shrinking it would silently shrink the proof |
| test source text → structural predicate | The predicate reads source lines by position; a moved assertion changes what line N-1 contains |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-170-05 | Tampering | `script/collection_assertion_remediation.json` | high | mitigate | The population-floor test pins the row count as a hard-coded literal (`@remediated_site_count`), and the ledger cross-check requires every manifest key to be `safe-guarded` in the regenerated ledger. Deleting rows to make the proof pass turns both red. |
| T-170-06 | Spoofing | guard expression | high | mitigate | The predicate compares the guard's normalized argument against the assertion's normalized collection expression; a guard naming a different collection is rejected, and a synthetic fixture proves that rejection path executes. |
| T-170-07 | Elevation of privilege | proof scope creep | medium | mitigate | The structural test reads only the frozen manifest and never scans the tree, keeping it closed-world; the pinned-range git diff over the check registry and workflows is asserted empty so no merge-blocking guard is registered (ROADMAP SC#3). |
| T-170-08 | Repudiation | guard insertion provenance | low | accept | `frozen_at` pins the manifest to a git SHA; per-site provenance beyond that is carried by ordinary git blame. |
| T-170-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no packages and adds no dependency; the supply-chain surface is unchanged. |

ASVS level 1; blocking threshold `high`. The two `high` threats are dispositioned `mitigate` with
