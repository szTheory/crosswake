the one SEED-018's grep named, widening the audited population from 173 to 220. A core assumption
("the defect is an `assert Enum.all?` problem") has lost its monopoly.

failure** — not "an `Enum.all?` site".

Decision: **promote**. The ledger's primary identity is the site-level classification row keyed by
content hash, and the quantifier is a per-row `shape` field (`assert_all` | `assert_any` |
`refute_any` | `refute_all`), never a separate mechanism or a separate table. Adding a second
side-by-side scanner for `refute Enum.any?` is explicitly rejected: it would let the two disagree
about what counts as safe, which is the same argument D-08 makes against two coexisting mechanisms.

Invariant this encodes: every shape in the shape vocabulary is enumerated by the same scan, keyed
the same way, and classified against the same bucket vocabulary. Advisory, non-blocking.

Required public surface for this task:
- `run(root, opts)` — returns an integer exit code; `root` is an argument, never `File.cwd!()`
  hardcoded, so tests can point it at a `@tag :tmp_dir` fixture tree.
- `rows(root, scope_glob)` — the pure function returning the ordered row list.
- `normalize_expression/1` — collapses all runs of whitespace (including newlines from wrapped
  calls) to a single space, strips leading/trailing space, and drops a trailing comma.
- `row_key/3` — `"sha256:" <> (:crypto.hash(:sha256, enclosing <> "\0" <> normalized_expression
  <> "\0" <> Integer.to_string(ordinal)) |> Base.encode16(case: :lower) |> binary_part(0, 16))`.
  The ordinal is the 0-based index of this row among rows sharing the same `{enclosing,
  normalized_expression}` pair within one file, assigned in ascending line order. The ordinal is
  what keeps two textually identical adjacent assertions as two rows instead of one.
- `render_snapshot(rows, scope_glob)` — deterministic text rendering (see schema below).

CLI flags for this task: `--root <path>` (default `File.cwd!()`), `--scope <glob>` (default
`test/**/*.exs`), `--emit-snapshot` (print the rendered snapshot to stdout), and `--check` (compare
the regenerated snapshot against the committed file and print the house-style result).

Detection core — reuse the repo's established source-regex-over-heredoc-stripped-text approach
(this repo's scanners do NOT parse real AST): read each file matched by the scope glob in
`Path.wildcard/1 |> Enum.sort/1` order, run it through a `strip_heredocs/1` clone that preserves
line numbers, then split into `{kind, name, body}` chunks with a `function_blocks/1` clone so each
match can name its enclosing `describe`/`test`. Match four shapes and record the shape tag:
`assert_all`, `assert_any`, `refute_any`, `refute_all`. Capture the first argument (the collection
expression) up to the top-level comma that separates it from the predicate, balancing parentheses
and brackets so a wrapped multi-line call is captured whole.

Row schema (fixed here, costly to change later) — exactly these seven keys, in this order:
`key`, `shape`, `bucket`, `rationale`, `display`, `enclosing`, `expression`. `display` is
`relative_path:line` and is a human-readable field ONLY — never the key, never used for lookup
(D-05). `rationale` is always a string, never a boolean or null.

Snapshot file format — `script/collection_assertion_ledger.json`, a JSON object rendered by the
script itself (do NOT hand `Jason.encode!` a map and hope for stable key order; build the text with
an explicit ordered key list so regeneration is byte-stable). Shape: a top-level object with
`scope`, `generator`, `sunset`, and `rows`; `rows` is an array with exactly one row object per
line, sorted by `display` then `key`. The file must remain `Jason.decode!`-able so plan 170-02's
structural test can read it back.
