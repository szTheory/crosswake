  </read_first>
  <behavior>
    - A package whose observed ref equals its approved ref and whose tarball content is byte-identical produces digests equal to the approved digests and a fully-proven result.
    - Changing a single byte of that package's real payload content — not the digest string — changes the recomputed payload digest and makes the same package report the digest-mismatch reason and a blocked aggregate state.
    - The same single-byte change applied while the ref is ALSO drifted reports the unproven reason, never the fully-proven result.
    - A declared outer checksum that does not equal the recomputed checksum still raises, unchanged by this phase.
  </behavior>
  <action>
The existing suite compares digest strings. A digest-string comparison can pass while the underlying
content check has silently stopped running. This task pins the floor one layer lower (SC#3,
XPUB-02).

**2a. Mutate content, not digests.** Extend the artifact fixtures so a test can rewrite one byte of a
real file inside a package's unpacked root, then re-run `Artifact.inspect_family!/1` and assert the
recomputed payload digest differs from the baseline. The existing changed-payload comparison in this
file is the analog to follow; the difference is that this test must carry the recomputed digest
forward into an exact-public evaluation rather than stopping at the digest comparison.

**2b. Carry it to a verdict.** Feed the baseline digests as the approved digests and the recomputed
digests as the observed ones, with the observed ref equal to the approved ref, and assert the
package's reason is the digest-mismatch diagnostic and the aggregate state is the blocked state.
Name this test explicitly as the byte-exact regression anchor in its description, so a future reader
cannot mistake it for an ordinary mismatch case.

**2c. Prove drift cannot launder a byte change.** Repeat 2b with the observed ref also drifted, and
assert the reason is the unproven diagnostic and the state is still not the completion state. This is
the case where a careless implementation would report the weaker-but-acceptable claim for an artifact
whose bytes actually differ — the single most dangerous regression this phase could introduce.

**2d. State the failure signal.** In the test description for 2b, state what a silent weakening would
look like: the same single-byte change producing a fully-proven result or a completion state. That
sentence is the phase's answer to "what output would reveal the byte-exact proof had silently
weakened", and the verifier will quote it.
  </action>

    - A companion test asserts that the same content change with a drifted ref reports the unproven reason and a state that is not the completion state.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Source text -> structural proof assertions | A structural assertion that reads source can pass while the behavior it names is dead; reachability tests are what close that gap |
| Real tarball bytes -> recomputed digests | The layer at which byte-exactness is actually decided, below the digest strings the rest of the suite compares |
| Executor's mutation runs -> phase-close verifier | The verifier cannot re-run a mutation against a tree that no longer exists; the record is the only durable evidence |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-172-11 | Repudiation | The non-vacuity record | high | mitigate | Task 3 requires a named mutation, quoted red output and a commit per row, forbids checkbox marks, and requires an explicit statement when a check has no mutation. Absence is never allowed to look like completeness. |
| T-172-12 | Tampering | Structural assertions that only refute | high | mitigate | Task 1a pairs every refutation with a positive replacement assertion in the same test, so deleting the function under test fails rather than passes. Task 1c adds evaluator-level reachability so a grep-only assertion cannot stand alone. |
| T-172-13 | Tampering | Byte-exact proof below the digest-string layer | high | mitigate | Task 2 mutates real file content and carries the recomputed digests to a verdict, with a recorded mutation of the digest comparison itself proving the regression test falsifiable. |
| T-172-14 | Denial of Service | A structural assertion keyed to the package count breaking on a future package addition | low | accept | Task 1d derives the package list from `Artifact.packages/0`, so an addition updates the assertion automatically.
