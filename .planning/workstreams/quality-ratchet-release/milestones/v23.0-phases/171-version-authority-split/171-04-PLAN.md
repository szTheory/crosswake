## D-171-D: the `attest-candidate-receipt` negative controls are parameterized in this phase

**Finding (verified, 171-RESEARCH.md Orchestrator Addendum):** the six assertions in
`ios-mirror-backfill.yml`'s `attest-candidate-receipt` job — that no git tag, no Hex release, no Maven
POM and no iOS mirror tag exist for the candidate version — sit in a `workflow_dispatch`-only job
further gated on `github.event.inputs.operation == 'candidate-receipt-attestation'`. They execute and
can fail, so they are a **live gate, not a fixture**. But the candidate version they name is now
published to all three registries, so all four negative controls are false today: **this attestation
path cannot pass for any dispatch, at any version, in its current form.** It is not vacuous — it
would fail loudly — it is welded to a version whose premise has since inverted.

**Decision: parameterize them in this phase.** They become negative controls over the *candidate*
version supplied to the dispatch, not over one historical literal.

**Why not defer:** Phase 175 (Rehearsal and Publish) depends on this attestation path working for the
next release. Deferring hands Phase 175 a blocked one-way-door rehearsal, and the ROADMAP does not
currently record that cross-phase dependency. This plan closes it instead of recording it as debt.

**Rating: `reversible`** — a dispatch-only, non-merge-blocking job; no production publish path changes.
</architectural_decision>
