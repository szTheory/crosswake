# Phase 171 Weld Inventory

- Base commit (branch tip when this table was assembled): `50a27285` (`gsd/phase-171-version-authority-split`)
- Grep command used for the completeness check: per-file presence check over the 18 originally-flagged
  files (see 171-05-PLAN.md Task 1 `<verify>`), plus a manual re-grep of each file's `version`/`0.2.x`
  sites at the current line numbers (research-era numbers are stale by design — several plans landed
  since research and shifted lines).
- Total occurrence count in this table: **49** data rows (counted via `grep -c '^| \`'` over this
  file's three tables), covering the 18 files: 8 `lib/` modules, 6 scripts, 4 workflows, plus one
  separate out-of-scope row for `mix.exs`.

**Scope and exclusions.** This inventory covers exactly the 18 files RESEARCH.md's Weld Inventory
section originally flagged, at the occurrence level — several files carry multiple, differently
classified occurrences, and ROADMAP criterion #5 is checked per occurrence, not per file. It does
**not** attempt to catalogue every dotted-version-shaped string in the repository; the much larger,
functionally unrelated set of version literals outside these 18 files (native runtime contract
versions, capability-schema examples, third-party GitHub Action version pins, etc.) is addressed
separately in `171-05-SUMMARY.md`'s measured-sweep reconciliation, not duplicated into this table.
`mix.exs`'s own `@version` is recorded below as an explicit out-of-scope row, not a 19th weld file.

**Classification vocabulary — six values:**
- `live gate` — controls whether a job or function proceeds
- `fixture` — a value bound to one specific historical event, correctly permanent
- `docstring` — prose or comment describing a past state
- `display string` — human-readable label or log text that gates nothing
- `orphaned validator (no production caller; test-only)` — `coordinate.ex`'s prior `@candidate` sites,
  per D-171-C
- `live gate, premise inverted` — `ios-mirror-backfill.yml`'s attestation negative controls, per D-171-D

**Disposition vocabulary:** `resolved` (weld removed; site is now version-parametric), `removed-with-proof`
(weld deleted outright, with a regression test proving it cannot silently return), `parameterized`
(orphaned/dormant site given a derived value instead of a literal, per D-171-C), `pinned historical
fixture` (literal retained on purpose; site is legitimately single-incident), `out of scope` (source of
truth, not a copy of a fact asserted elsewhere).
