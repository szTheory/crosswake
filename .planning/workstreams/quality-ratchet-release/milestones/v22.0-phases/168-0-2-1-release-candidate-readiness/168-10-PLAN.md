  <files>script/check_release_version_truth.exs, test/crosswake/proof/phase168_version_truth_test.exs</files>
  <behavior>
    - A manifest version older than the newest matching published tag for that component is FAIL with exit code 1, naming the component, the declared version, the newest published version, and one exact next action.
    - A manifest version equal to the newest matching tag is OK with exit code 0. A manifest version newer than the newest matching tag is also OK with exit code 0, because being ahead is the normal pre-release state.
    - No matching tag visible for a component, an unreadable manifest, a missing manifest key, an unavailable git, or an unparsable declared version is BLOCKED with exit code 2. BLOCKED is never collapsed into OK.
    - Tag names that do not parse as the component prefix followed by a semantic version are ignored when selecting the newest published version; they neither fail the run nor become the newest.
    - Newest is decided by semantic version comparison rather than lexicographic sort, so 0.10.0 is newer than 0.9.0.
  </behavior>
  <action>Write `script/check_release_version_truth.exs` as an Elixir script in the style of `script/check_release_workflow_integrity.exs`. Accept a `--manifest` path defaulting to `.release-please-manifest.json` and an optional `--tags-file` path holding newline-separated tag names; without that flag, read tags from `git tag --list`. Compare each of the three linked core components against its tag prefix per the interfaces block using `Version.compare/2`. Emit one answer-first line per component carrying the component, declared version, newest published version, and verdict, then one summary line, then exactly one next action whenever the run is not OK. Exit 0 for OK, 1 for FAIL, 2 for BLOCKED. Write `test/crosswake/proof/phase168_version_truth_test.exs` first, covering every behavior bullet with temporary manifest and tag-file fixtures, plus one invocation against the real repository that requires exit 0 when release tags are visible and requires the BLOCKED exit code and its stated reason when they are not — that real-repository case must assert one of those two branches and must not be able to pass by default. Commit the failing test as `test(168-10): prove manifest version truth against published tags`, then the script as `fix(168-10): add release version truth guard`.</action>
