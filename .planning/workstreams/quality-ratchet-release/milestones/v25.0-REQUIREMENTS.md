## v25.0 Requirements

### IOS: host setup without hand patches

- [x] **IOS-01:** Maintainer can declare iOS host build inputs once through ordinary Phoenix/Mix configuration, generate/regenerate supported outputs without unrelated runtime-server credentials, and retain host-owned native edits. Nonwriting check/diff identifies stale output and ownership conflicts without exposing private values.
- [x] **IOS-02:** Maintainer can generate app and proof-test identity/signing projections and verify their effective Xcode settings in simulator/device modes without editing project internals. Simulator checks need no Apple credentials; device settings inspection does not claim signed-device installation.
- [x] **IOS-03:** Maintainer can bundle the selected host route declarations, entry route and primary origin through the canonical manifest/static-activation path; missing/example production origin, invalid route/input or interrupted generation fails closed. Generated activation grants no session, scope or replay authority.

### TWIN: bounded reference demonstration

- [x] **TWIN-01:** Maintainer can run one documented automated reference demonstration that binds the actual generated candidate, visible study WebView/bridge, selected dependency/assets and owned Phoenix backend to the expected source/run. Browser-only, contract-only and generated-iOS observations remain distinguishable.
- [x] **TWIN-02:** Maintainer can observe verified installed media playback initiated by the actual visible offline-island action through the host-owned native adapter, selected/free-form offline persistence and true app terminate/relaunch without resetting storage. Network denial is verified at the tested target.
- [x] **TWIN-03:** Maintainer can observe the normal app's authorized reference replay, actual Ecto effect idempotency under duplicate delivery and empty outbox. Synthetic fixture authority is explicit and grants no real-adopter identity claim.
- [x] **TWIN-04:** Maintainer can demonstrate real server-backed rejection/conflict recovery, logout/account-switch replay fencing, entry/replay disablement with retained work and missing/corrupt-media denials through controlled run-owned fault cases. Learner-visible status/recovery reflects the actual durable state.
- [x] **TWIN-05:** Maintainer can inspect a closed, source-bound, privacy-safe twin receipt covering the complete required scenario/observation roster, retaining actual failure/unavailable causes; fabricated, missing, stale, sensitive or mismatched observations cannot pass or promote physical/adopter claims.
- [x] **TWIN-06:** Maintainer can see all ten bounded scenario-group outcomes, fidelity limits, failed/blocked work and residual external gates in one handoff. Work stops at the declared boundary; required virtual checks must pass for completion and broader core/runtime work is not silently added.

### SEAM: core host-command seam (Phase 181)

- [x] **SEAM-01:** A maintainer declares a host's `host.*` commands once, with versions, on the router, and each route references them in its own `crosswake:` capabilities. Undeclared, misspelled, malformed or reserved commands, and host commands on runtimes without a bridge session, fail at compile time with an explicit, actionable error.
- [x] **SEAM-02:** The generated manifest carries each route's own declared host commands, and the entry activation carries only the entry route's declaration. Projection is driven by each route's declaration for every declaring route, is never keyed to one probe route, and no route inherits another route's commands.
- [x] **SEAM-03:** The native session grants a route only commands that the route declared, the host registered, and that are version-compatible with the shell. They are delivered to the registered `HostBridgeCommandDelegate` and re-resolved on every navigation and deep link. Any other command is denied with a reason that names the route and command.
- [x] **SEAM-04:** The bounded iOS shell admits `offline_island` routes as an explicit presentation that shares the web container and applies the same version, entry, pack, origin and command checks. All other runtimes remain explicitly denied with an accurate hint.
- [x] **SEAM-05:** The wire change is additive and versioned (manifest schema 1.2.0, bridge protocol 1.1.0, Android vectors and assets unchanged). Existing hosts keep working or get an explicit denial in every old/new combination, a compiled-in shell constant and a fail-closed generation gate stop silent grants, and guides and support truth are updated together.
- [x] **SEAM-06:** A maintainer gets a seam handoff (`180-SEAM-HANDOFF.json`) that binds the repaired candidate head, tree, authorized paths and probe route. The 180-01/180-02 summaries are kept as baselines so the Phase 180 gate can rerun.

### LOOP: loopback origin for the local iOS host (Phase 182)

- [x] **LOOP-01:** A maintainer turns on the local mode only by adding `origin_mode: :local_loopback` to the `:ios_host` declaration. Without it, origin validation stays HTTPS-only and an `http` origin gets an explicit, actionable denial. An unknown mode value, an `https` origin under the mode, or the mode under `MIX_ENV=prod` is also denied with its own repair.
- [x] **LOOP-02:** In the mode, only `http://127.0.0.1` and `http://localhost` with an optional port are accepted, canonicalized without rewriting one host into the other. IPv6, other loopback or LAN addresses, `.local` names, credentials, path, query and fragment are denied.
- [x] **LOOP-03:** The generated Info.plist in local mode carries exactly ATS `NSAllowsLocalNetworking` and a `CrosswakeOriginMode` marker. Production output is byte-identical to before and has no ATS exception. `NSAllowsArbitraryLoads` and its variants never appear. Toggling the mode is managed-output drift. An automated iOS Simulator check observes the generated app's WebView actually loading a test-owned `http://127.0.0.1` page; an unavailable Simulator leaves this blocked, not passed.
- [x] **LOOP-04:** Doctor reports local mode as a not-production-ready warning (an error under `--check-publish`), and an inconsistent generated state as an error. `gen.shell --check` and inspect name the mode. The physical proof lane refuses it. Guides and support truth describe it. Output shows only the canonical origin.
- [x] **LOOP-05:** A maintainer gets `182-CANDIDATE-MOVE.json`, which records the Phase 180 candidate moving from `12f84cd` onto the Phase 182 head with byte-identical uncommitted 180-03/180-04 work and the three pinned tests. It also states that the 180-01 gate must rerun on the new head before 180-05 reruns from Task 1.

## Acceptance Boundaries

The canonical T01–T10 roster and required observation owners are fixed in the [research synthesis](../../research/v25/SUMMARY.md). Cold boot, origin, source and visible-WebView checks are preconditions, not extra scenarios. Browser/backend proof counts only for observations it actually makes. The generated app's visible island action must use the existing declared `host.*` command seam for host-owned native playback from verified installed bytes; a separate native player test cannot stand in for that join. A fresh run-owned database, server, loopback port and app context protect existing state. The twin receipt is derived, privacy-safe and grants no physical or adopter promotion.

Stable generation, ownership and receipt regressions may enter existing CI leaves; the full simulator demonstration remains local unless recurring value is proven. Required virtual checks must pass for completion. A genuine blocker or a need for broader generic core work leaves the relevant requirement incomplete. The parked First B2C Adopter path still requires validated sanitized route facts and a fresh source-bound signed-device run.

## Out of Scope

No package release, PR merge, physical-device promotion, adopter promotion, Android breadth, generic sync/storage, new public audio or file protocol, dashboard, cosmetic program, new companion, broad platform or CI lane, historical debt cleanup, protected-history mutation, or recovery-checkout Git operation is selected. PR #238's delivery is consumed and is not repeated.
