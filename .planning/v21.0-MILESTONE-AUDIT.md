# v21.0 First B2C Adopter Readiness — Milestone Audit

## Verdict

**GAPS FOUND.** All seven phases have passing verification reports and all 36 requirements have complete three-source phase evidence, but the milestone is not ready to archive. Cross-phase inspection found that the retained physical proof is a bounded reference-fixture happy path rather than the governing one-real-adopter exit flow.

**Parking disposition:** v21 remains resumable but inactive until real sanitized adopter route
facts exist. Quality and repository-maintenance work continues in a separate workstream; it must
not complete, archive, or promote v21 support claims.

The critical problem is not missing phase implementation in isolation. It is missing composition: the eligible physical host bypasses the Phase 161.1 navigation shell, several required lifecycle/failure assertions come from a separate backend producer instead of the iPhone flow, the repository still has no adopter-supplied concrete route inventory, and Phase 158's production privacy router does not classify required Phase 162/163 artifact types. Those gaps fail the milestone's original intent even though each phase's local requirement ledger is green.

## Definition-of-Done Assessment

The milestone goal requires one real Phoenix application, one physical iPhone, and one offline mutation island. The current tree proves a useful but narrower result:

- one anonymous reference Phoenix/iOS fixture installs verified learning-bundle bytes;
- one physical iPhone completes the happy offline study/audio/relaunch/replay path;
- independent backend automation proves rejection, conflict, scope, and disablement contracts;
- retained evidence is redacted, digest-bound, and tied to a bounded commit topology.

It does **not** yet prove the complete flow through a real adopter route or through the required physical navigation shell. The route-policy map explicitly says empty or unknown concrete inventory blocks host-proof and physical promotion, and TODO-002 remains open. The reference host's synthetic confirmed route is acceptable fixture evidence, but it is not a substitute for the adopter-supplied row required by the governing ADR and route-policy map.

## Closure Guidance

Do not archive v21.0 yet. Close the gaps with the smallest adopter-confirmed physical slice:

1. Obtain sanitized adopter route rows and keep promotion fail-closed until TODO-002 validates.
2. Compose the bounded Phase 161.1 navigation shell into the eligible physical host; do not generalize it.
3. Drive rejection/conflict recovery, logout/account switch, and entry/replay disablement through the physical device flow while preserving redacted evidence.
4. Extend the existing Phase 158 artifact classifier with explicit safe handling for the required evidence completion marker and pronunciation-audio binary; preserve fail-closed behavior for unclassified paths.
5. Prefer reusing the Phase 161 PackProvider boundary in the physical host unless a documented host-specific reason justifies the duplicate adapter.
6. Re-run the phase validations listed above, then rerun `$gsd-audit-milestone`.

The governing stop rule remains in force: only defects demonstrated by Phase 162 evidence may justify further Crosswake work. The closure work above is limited to demonstrated milestone-exit composition defects; it does not authorize Android, generic navigation, generic sync/storage, or broader framework investment.
