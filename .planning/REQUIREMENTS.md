# Requirements: Crosswake — v12.0 CI Honesty & Real-E2E Sweep

**Defined:** 2026-06-17
**Core Value:** Make Crosswake's CI proof surfaces *honest* — every green check proves what it claims. The flagship offline-sync E2E exercises the demo app's real IndexedDB-outbox→reconnect-flush path against the live Ecto backend (not a test-injected scratch variable), that lane actually gates merges, an anti-regression guard keeps it honest forever, and the validation-ledger closeout passes on real artifacts rather than vacuous globs.

## v1 Requirements

Requirements for milestone v12.0. Each maps to exactly one roadmap phase.

> Research backing every requirement: `.planning/research/SUMMARY.md` (+ STACK/FEATURES/ARCHITECTURE/PITFALLS) and three gray-area advisor researches (reconnect-trigger, manual-sync UX, requirements coherence). **Hard ordering:** the app-code requirements (E2E-01/02) must ship before the test that proves them (E2E-03/04), which must ship before the gates that enforce them (GATE-01, GUARD-01). The DEBT/DOC/GATE-02 closeout track is independent and parallelizable.
>
> **Two scope decisions are locked** (research-backed, see Out of Scope for the rejected alternatives): (1) the offline-sync reconnect flush is triggered by the browser `window 'online'` event on the existing socketless `/offline` island — **no migration to a LiveView route**; (2) the vestigial `StudySessionLive` `sync_outbox` mock is **removed entirely**, not relabeled as a manual-sync affordance.

### E2E — Real Offline-Sync Proof

Replace the structurally fraudulent `offline_sync.spec.ts` (which injects a mutation into a test-only `window['crosswake_offline_mutations']` global the app never reads, then manually fires `fetch('/study/sync')`) with a test that exercises the app's own code path. The server side is already correct (`Study.sync_events/1`, idempotent `on_conflict: :nothing`) and is not changed.

- [x] **E2E-01**: `offline_study.js` writes a mutation to the IndexedDB `mutations` store via `queueMutation()` triggered by a real UI action (flashcard rating control) — never by test-injected `page.evaluate()` — in the server-contract shape `{client_mutation_id, card_id, rating}`, with `client_mutation_id` generated by `crypto.randomUUID()` at queue time.
- [x] **E2E-02**: `offline_study.js` contains a real `flushOutbox()` that drains the IndexedDB `mutations` store by POSTing to `/study/sync`, deleting records on a 2xx and **leaving them queued on failure for retry**; it is fired by a `window.addEventListener('online', flushOutbox)` reconnect handler, an optimistic call when already online at review time, and an on-load drain. The `StudySessionLive` `sync_outbox` mock handler (and its "Simulate Network Sync" button/assigns) is removed entirely.
- [ ] **E2E-03**: `offline_sync.spec.ts` proves the full offline→reconnect→reconcile loop with **zero `page.evaluate()` calls that write app state or invoke app-owned behavior**: (a) real UI click while `setOffline(true)` queues via app code; (b) an IndexedDB read asserts the queued record and extracts the *app-generated* `client_mutation_id`; (c) `setOffline(false)` + `dispatchEvent(new Event('online'))` triggers the app's own `flushOutbox()`; (d) `expect.poll` on `/_e2e/sync-state/:id` confirms the Ecto row; (e) a follow-up IndexedDB read confirms the outbox is empty; (f) a duplicate-flush case POSTs the same `client_mutation_id` twice and asserts a single Ecto row. Each test resets IndexedDB via `beforeEach`.
- [ ] **E2E-04**: The `phase90-proof.yml` workflow runs `mix compile --warnings-as-errors` in `examples/phoenix_host` **before** the Playwright step, so a demo-app compile break fails loudly instead of masquerading as a Playwright port-connection timeout (the v6.0 failure mode, still structurally present).

### GATE — CI Gating

Make the proof and the closeout verifier actually enforce, instead of running advisory-in-disguise or passing vacuously.

- [ ] **GATE-01**: The offline-sync E2E job is named `merge-blocking-offline-sync-e2e` and registered as a required status check on `main` with all existing required checks preserved (the branch-protection `checks` array is **replaced, not appended** — all checks listed). The workflow carries a comment with the exact `gh api ... PATCH` command; if the protection toggle is harness-blocked, a `script/register-e2e-gate.sh` ships the complete command. Every non-required CI lane keeps `continue-on-error: true` and a `::notice` marking its advisory status.
- [ ] **GATE-02**: The `CloseoutVerifier` fails closed on its two vacuous paths: (a) it raises when `expected_phases` is absent/malformed in `CLOSEOUT.md` frontmatter instead of silently substituting a hardcoded phase set (`@v40_phases`); (b) `validation_ledger_check/2` returns a blocking result when an expected phase resolves to zero ledger files with no active deferral ("no files found" ≠ "found and compliant"). Stale unsatisfied prior-debt entries **block** the closeout rather than merely printing `(stale)`.

### GUARD — Permanent Structural Guards

Make the honesty guarantee permanent, matching the project DNA (v9.0 `brand-structural`, v11.0 `generator_coordinate_parity`) — a point-in-time fix is not enough.

- [ ] **GUARD-01**: A merge-blocking structural check (`script/check-e2e-honesty.mjs` or equivalent) scans `offline_sync.spec.ts` for the illegitimate-injection anti-patterns (`window['crosswake_offline_mutations']`, a `page.evaluate` that calls `fetch(`, or a test-minted UUID asserted before any IndexedDB read) and fails the build if any reappear, so the test cannot silently revert to fake in a future PR. Registered alongside the E2E job.
- [ ] **GUARD-02**: The `/_e2e/sync-state/:id` endpoint is confirmed and asserted to be mounted only in `:test`/`:e2e` (never `:prod`) — via a `routes_test.exs` assertion or documented workflow comment — and its test-only purpose is stated in the controller module docstring, so the proof endpoint is not a production data-leak path.

### DEBT — Carried Validation-Ledger Debt

Pay off the `tighten-validation-ledger-closeout-gate` backlog carried verbatim through v8.0→v11.0 — the gate now catches the absence (GATE-02), so the missing artifacts must actually exist.

- [ ] **DEBT-01**: Every phase the now-strict gate flags for a missing ledger (v3.6: 48/49/52/53; v3.8: 54-58; v3.9: 62/63) has a `*-VALIDATION.md` containing `nyquist_compliant: true` **and** a `tested_by:`/`evidence:` field citing a concrete CI run, test file, or artifact — not a bare attestation. The carried deferral entries are flipped to `status: resolved` with an evidence citation **only after** the ledgers exist, and `mix closeout.verify` passes with no `(stale)` entries for this scope.

## Out of Scope

Explicitly excluded. Documented to prevent scope creep.

| Feature | Reason |
|---------|--------|
| Migrating the `/offline` study island to a LiveView route (for the `reconnected()` Hook) | Betrays the offline-island thesis — the island is socketless **by design** (`put_root_layout(false)`); migrating deletes the very proof the library exists to provide, and the Hook's socket-reachable advantage is moot for a plain HTTP-POST sync. `window 'online'` + retry-on-failure is the honest minimal trigger. |
| A "Sync now" / manual-sync button on `StudySessionLive` | The `StudySessionLive` outbox is a server-side in-memory Elixir list flushed by a LiveView event — not a client offline outbox. Labeling it "Manual Sync" would misrepresent the mechanism — a fresh dishonesty. The real client outbox lives on `/offline`. |
| Changing the server-side sync/reconciliation logic (`Study.sync_events/1`) | Already correct and idempotent (`on_conflict: :nothing, conflict_target: :client_mutation_id`); v12.0 is client + test + gate honesty, not a server rewrite. |
| Background Sync (Service Worker `sync` event) for the island | `guides/offline.md` explicitly states "No Background Sync" — sync occurs only while the app is active on the route. Expanding it would widen the offline contract this milestone is meant to keep honest. |
| Retroactively rewriting `v*-MILESTONE-AUDIT.md` scores | Audit files are point-in-time snapshots; they are annotated, never overwritten (DOC-01). |
