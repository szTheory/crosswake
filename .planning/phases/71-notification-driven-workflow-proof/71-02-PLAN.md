<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Intent state -> public denial code | Internal intent states must normalize to stable, documented Chimeway codes and cannot leak arbitrary atom names. |
| Stored open intent -> evidence action ref | A backend-issued one-time intent must not be consumed for a different notification action. |
| RouteGate denial -> route transition | Notification-source denials must not become fallback route activation. |
| Sigra evaluator -> Chimeway resolver | Auth denials must pass through without being obscured as Chimeway-only errors. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-71-06 | Tampering | Chimeway resolver denial mapping | medium | mitigate | Normalize known states and fail closed on unknown states instead of interpolating public denial codes. |
| T-71-07 | Elevation of Privilege | Example-host open intent consumption | high | mitigate | Compare stored `action_ref` to evidence `action_ref` so a valid intent cannot be laundered into a different action. |
| T-71-08 | Elevation of Privilege | RouteGate fallback transition | high | mitigate | Notification-source denials halt before fallback redirects. |
| T-71-09 | Repudiation | Denial vocabulary | medium | mitigate | Unit tests lock exact Chimeway and Sigra denial codes for support truth. |
| T-71-10 | Information Disclosure | Denial details | medium | mitigate | Denial tests keep sanitized low-cardinality details and avoid raw payload/PII fields. |

## High Severity Block

Block completion if action-ref mismatch can consume a backend intent as a different action, or if notification-source Sigra denials can redirect to dashboard/home fallback.
</threat_model>
