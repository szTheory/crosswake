<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Notification evidence -> backend route activation | A simulated notification tap enters Chimeway as typed evidence but cannot grant auth or route authority. |
| Chimeway intent consumer -> RouteGate | Backend-owned open-intent state can authorize only the attempt to evaluate a manifest route, not bypass policy. |
| RouteGate -> Sigra | Route activation depends on backend-projected Sigra auth context and recent-auth predicates. |
| Denial details -> support/operator output | Public denial envelopes must not leak raw tokens, provider payloads, route params, actor/session refs, device IDs, IPs, emails, or user agents. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-71-01 | Elevation of Privilege | Notification open resolver | high | mitigate | Red proof asserts notification evidence cannot activate `saas_approval` without fresh backend Sigra MFA auth. |
| T-71-02 | Spoofing | Open intent and action refs | high | mitigate | Red proof asserts route, binding, and action mismatches fail closed with canonical Chimeway denials. |
| T-71-03 | Tampering | One-time open intent lifecycle | medium | mitigate | Red proof asserts expired, replayed, and revoked-binding intents deny before activation. |
| T-71-04 | Information Disclosure | Denial metadata | medium | mitigate | Red proof asserts hostile token/payload/PII metadata is absent from denial details and inspected denial output. |
| T-71-05 | Elevation of Privilege | Fallback route transition | high | mitigate | Red proof asserts notification-source auth denials halt and do not silently redirect to dashboard/home fallback. |
