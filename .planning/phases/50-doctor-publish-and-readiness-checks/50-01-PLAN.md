<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo files -> publish readiness | Package metadata, docs links, changelog truth, and release wording cross from source files into a machine-readable release/support contract. |
| operator inspection/support matrix -> readiness checks | Route/support/proof/rebuild/auth/notification truth is reused from canonical modules and must not be duplicated or reinterpreted into a second authority. |
| deferred scope -> actionable messaging | Provider/auth/notification/native-shell caveats can become accidental overclaims if the checks collapse advisory or verification-required posture into support. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-50-01 | Tampering | `lib/crosswake/doctor/publish_readiness.ex` | mitigate | Reuse `Crosswake.OperatorInspection` and `Crosswake.SupportMatrix` directly for route/support/proof/rebuild/auth/notification truth, and lock the eight categories with focused tests. |
| T-50-02 | Repudiation | readiness result/status derivation | mitigate | Keep explicit `result` and `blocking` fields on every readiness check and assert that `status` is driven only by blocking failures, never by empty findings. |
| T-50-03 | Information Disclosure | auth/provider/deferred-scope messaging | mitigate | Keep Sigra, provider adapters, notification delivery, and shell-package surfaces explicitly deferred in messages/details and assert the non-claims in `publish_readiness_test.exs`. |
| T-50-SC | Tampering | npm/pip/cargo installs | accept | No new package-manager installs or external dependencies are allowed in this plan. |
</threat_model>
