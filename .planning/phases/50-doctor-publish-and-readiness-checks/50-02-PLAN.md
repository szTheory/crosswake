<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argv -> doctor task | New flags and exit behavior can accidentally change established doctor semantics if not gated tightly. |
| publish-readiness contract -> doctor findings/renderers | The same readiness truth must appear in findings, human output, and JSON without drifting into multiple contracts. |
| optional publish lane -> default doctor lane | Flagged release checks must be additive only; ordinary doctor must not silently start implying publish-readiness status. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-50-04 | Input Validation | `lib/mix/tasks/crosswake.doctor.ex` | mitigate | Reuse strict `OptionParser` handling and add `--check-publish` only on the existing task, with regression tests for invalid options and unchanged default paths. |
| T-50-05 | Tampering | `lib/crosswake/doctor/doctor.ex` + renderers | mitigate | Consume `Crosswake.Doctor.PublishReadiness` directly, attach it conditionally, and test that human/JSON render the same readiness contract rather than re-deriving it. |
| T-50-06 | Denial of Service | doctor exit semantics | mitigate | Keep blocking behavior scoped to ordinary `:error` findings plus blocking publish checks under `--check-publish`, and assert that warnings/advisories remain visible without breaking the unflagged task. |
| T-50-SC | Tampering | npm/pip/cargo installs | accept | No new package-manager installs or external dependencies are allowed in this plan. |
</threat_model>
