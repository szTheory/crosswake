## What shipped

### RUNNER-01 — 13 non-Apple jobs moved macos-15 → ubuntu-latest

GitHub bills macOS at a **10x multiplier**, and the baseline measured a **163x queue
ratio** on top of that: 490 s mean queue per macOS job vs 3 s per ubuntu job. 19 macOS
jobs accounted for 9,305 s of the 9,454 s total queue on a single push.

Audited per-job by following every `run:` into its scripts **transitively**, not by
grepping the workflow file. **22 macOS jobs -> 9 need a macOS host, 13 do not.**

Moved: `phase23/34/41/43/45/48/52/58/70/71/73` (checkout + setup-beam + `mix` only),
`phase10` (three 10-line `mix` wrappers), `phase68` android-emulator-advisory.

`phase68` is the interesting one: it boots an `arch: x86_64` AVD, and macos-15 runners are
arm64, so that image was running under **full CPU emulation**. On ubuntu it gets KVM, which
is the path `ReactiveCircus/android-emulator-runner` documents. Added the standard
`/dev/kvm` udev step.

Stayed on macOS (9), each with file:line evidence — `phase5`, `phase18`, `phase79`,
`see-it-run-collateral/native` and both `native-collateral-advisory` jobs (xcodebuild via
`script/verify_generated_ios_shell.sh:14`); `native-behavioral-proof-gate/ios-package-unit`
(`swift test`); `release-please/clean-room-proof-ios` (`swift build`);
`native-behavioral-proof-gate/android-generated-shell-unit` (see below).

### RUNNER-02 — 47 jobs across 16 workflows given a `timeout-minutes`

They were inheriting GitHub's 360-minute default. On a 10x-billed macOS runner that is 60
hours of billable time for one hung job, and the baseline session already saw a real
20-minute hang while compiling deps on #84.

Values scoped to observed runtimes, not uniform: 45 (release-please clean-room proofs),
40 (macOS simulator/emulator advisory), 30 (publish-*, remaining macOS, see-it-run
web-and-gif), 20 (everything else).

## The two false positives the audit tool produced

Both would have turned a working merge-blocking proof **red**. Both were caught by
hand-verifying tool output against the workflow files — which is exactly why the plan
forbids verdict-by-grep.

1. **`phase79 / merge-blocking-v5-proof`** — the script-reference regex missed the leading
   `./` in `run: ./script/verify_generated_ios_shell.sh`. That script hard-requires
   `xcodebuild`. Fixed the regex to accept `./` and `${GITHUB_WORKSPACE}/` prefixes.
2. **`native-behavioral-proof-gate / android-generated-shell-unit`** — a different failure
   mode entirely. No Apple *toolchain*, but a macOS *host* assumption: the verify script
   downloads a JDK from adoptium `.../ga/mac/$(arch)/...` and falls back to Homebrew. The
   pre-existing `# REVIEW FIX finding 2` comment on that `runs-on:` line was correct and
   was very nearly overridden.

**Generalisation recorded for SEED-007:** "needs macOS" has at least two independent
causes — Apple toolchain and macOS host environment. An audit that greps only for
`xcodebuild`/`swift` finds the first and silently misses the second.

## Safety

Branch protection matches required contexts by **string**, so a job rename here would
silently un-protect `main`. **Zero `name:` lines appear in either commit's diff** —
verified mechanically, not by eye. `check_required_checks_registered.sh` reported all 26
declared lanes registered and uniquely emitted, before and after.

`release-please.yml` is security-sensitive (REL-05 SHA pinning, two previously armed
fuses). Its whole-file diff was verified to be exactly three distinct added-line shapes,
all `timeout-minutes`; concurrency settings (`cancel-in-progress: false`, `queue: max`)
untouched.

`DEVELOPER_DIR` was set at workflow `env:` level in 11 files with exactly one consumer
each; with no macOS job left in those workflows it was removed rather than left implying an
Xcode dependency.
