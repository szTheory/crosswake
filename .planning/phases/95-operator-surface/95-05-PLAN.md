<objective>
Close the single residual OPER-02 BLOCKER from 95-VERIFICATION.md (re-verification 2026-06-10, score 3/4). The schema-check branch in `phase_95_threadline_findings/2` calls `Code.ensure_loaded?(schema)` guarded only by a truthiness check (`schema &&`). `ledger_schema/1` can return a non-atom value (a string module name) from the documented map and keyword config shapes — the classic `config/runtime.exs` + `System.get_env` pattern, e.g. `%{schema: "MyApp.Audit.Ledger"}` or `[schema: "MyApp.Audit.Ledger"]`. A string passes the `schema &&` truthiness check and crashes `Code.ensure_loaded?/1` with `FunctionClauseError`, so the doctor crashes instead of returning a report — violating the fail-closed guarantee.

Purpose: A fail-closed diagnostic must ALWAYS return a report. A diagnostic that crashes on a real-world config shape gives the operator nothing — worse than a clean bill of health. This is the last defect blocking OPER-02 from being honestly satisfied.

Output: A one-clause guard fix in `lib/crosswake/doctor/doctor.ex` and a regression test in `test/crosswake/doctor/doctor_test.exs`.
</objective>
