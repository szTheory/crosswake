### Gaps Summary

**1 BLOCKER — SC-2 single-value invariant not met (CR-01)**

The ROADMAP's own success criterion 2 specifies that `grep -rn '"bridge_protocol_version"' lib/ test/ packages/ examples/` returns a single value everywhere. This grep returns two distinct values:

- `"1.1.0"` — in `examples/*/Fixtures/route_activation.json` (regenerated by gen task) and `test/fixtures/bridge_contract_vectors.json`
- `"1.0.0"` — in `examples/ios_shell_host/Fixtures/crosswake_manifest.json:350` and `examples/android_shell_host/app/src/main/assets/crosswake_manifest.json:350` (hand-maintained, not in gen task scope)

These `crosswake_manifest.json` files are tracked in git (confirmed via `git ls-files`). They are the manifest files that native shell apps bundle at runtime. Phase 121 updated the sibling `route_activation.json` files but left the manifest files at the pre-phase value.

The result is that within each example app's asset bundle, the manifest declares `bridge_protocol_version: "1.0.0"` while the activation fixture declares `bridge_protocol_version: "1.1.0"` — the exact contradiction this phase exists to eliminate.

**Root cause:** Plan 02 explicitly prohibited touching `crosswake_manifest.json` ("MUST NOT touch crosswake_manifest.json, denial.json, or other Fixtures.export targets"). This prohibition was the right engineering discipline to keep the gen task scope minimal, but it left the manifest files at 1.0.0. The phase goal's "every version surface" and SC-2's "single value everywhere" are not met.

**Fix:** Add the two `crosswake_manifest.json` paths to `mix crosswake.contract.gen`'s emitted set (emitting `compatibility.bridge_protocol_version` from `Contract.version()`), run the gen task, and commit the updated manifests. Then verify `grep -rn '"bridge_protocol_version".*"[0-9]' examples/*/Fixtures/ examples/*/assets/` returns only `"1.1.0"`.
