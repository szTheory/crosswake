<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Mix/seeds -> database | Reset mutates persisted example-host server state. |
| server reset -> browser offline state | Server response may be misread as clearing IndexedDB/outbox state. |
| lane fixtures -> support truth | Fixture records shape what users believe the lanes can do. |

## ASVS L1 / High-Blocking Posture

Security enforcement is active at ASVS Level 1 with high-severity issues blocking execution. Reset work maps to ASVS V4 because mutation surfaces must stay local/dev/test-only and never become production access, and to ASVS V5 because reset accepts no arbitrary table names, scopes, or user-controlled targets.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-147-07 | Tampering | `Showcase.Reset.reset!/0` | mitigate | Use fixed context functions only; no user-supplied table names or scopes. |
| T-147-08 | Repudiation | reset result digest | mitigate | Return deterministic counts and digest so tests can prove reset truth. |
| T-147-09 | Information Disclosure | server reset copy | mitigate | Return `browser_state_reset: false` and keep IndexedDB reset in Playwright helpers. |
| T-147-10 | Denial of Service | repeated fixture calls | mitigate | Make selective-native/field-service persisted seed path reset-safe and idempotent. |
| T-147-ASVS | Elevation of Privilege / Tampering | `Showcase.Reset.reset!/0` | mitigate | Enforce ASVS L1/high-blocking posture: V4 requires reset mutation access remain local/dev/test-only through seeds/Mix and the later gated endpoint; V5 requires fixed reset steps with no user-controlled reset scope. |
| T-147-SC | Tampering | package installs | accept | No new npm/pip/cargo packages. |
</threat_model>
