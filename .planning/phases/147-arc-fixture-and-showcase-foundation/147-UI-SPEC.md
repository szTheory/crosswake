# Phase 147 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Phase Scope Summary

Phase 147 turns the example-host root route `/` into the product-shaped Crosswake showcase hub. The first screen must show all three v19 lanes: SaaS/admin, field-service, and subscription learning/training. The hub must make route ownership and support posture visible without turning the page into a raw manifest inspector.

This phase must not implement full lane depth, a full capability map, broad native controls, live commerce/paywall SDK support, or a generic sync engine. Proof routes and diagnostics remain reachable but secondary.

Source decisions: 147-CONTEXT D-01 through D-27, REQUIREMENTS SHOW-01 through SHOW-04, ROADMAP Phase 147 success criteria, and brandbook/BRAND-SPEC.md.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline badge gaps, route metadata separators |
| sm | 8px | Badge padding, compact card rows |
| md | 16px | Default element spacing, mobile card padding |
| lg | 24px | Desktop card padding, grid gaps, page side padding |
| xl | 32px | Hub intro to lane grid spacing |
| 2xl | 48px | Major page bands below first-screen hub |
| 3xl | 64px | Reserved for later landing/collateral sections, not first-screen hub |

Exceptions:

- Minimum mobile touch target: 44px height for lane CTAs, proof links styled as buttons, and any in-app reset action.
- Hub content max-width: 1120px as a structural layout width from the brand landing range; secondary proof/docs pages may keep the existing 860px `.page-container`.
- Card radius follows the existing token `--cw-radius-lg` (14px); do not invent a second radius scale.
- First viewport density rule: on a 375px by 812px viewport, the intro plus all three lane card headers, route paths, primary labels, and CTAs must be visible without hiding a lane below the fold. Details may continue lower on the page.

## Typography

Use exactly these four sizes and two weights for new Phase 147 hub UI.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Badge / metadata | 12px | 600 | 16px |
| Body | 16px | 400 | 24px |
| Lane heading | 20px | 600 | 24px |
| Page display | 28px | 600 | 36px |

Rules:

- Body text uses Atkinson Hyperlegible Next.
- Page display and lane headings use Space Grotesk.
- Route paths, route IDs, digests, and exact policy values use JetBrains Mono.
- Do not use viewport-scaled font sizes.
- Do not use negative letter spacing in the hub. The brand `--cw-tracking-tight` exists, but Phase 147 needs compact, stable product UI rather than a marketing hero.
- Do not use all-caps labels. Runtime/support labels are sentence/title case text badges.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--cw-surface-default` (`#F7F1E6` light, `#09141A` dark) | Page background and first-screen open surface |
| Secondary (30%) | `--cw-surface-inset` plus `--cw-surface-raised` (`#FFFFFF`/`#EFE6D6` light, `#162B35`/`#0F1E26` dark) | Lane cards, proof strip, reset status panel |
| Accent (10%) | `--cw-action-bg` (`#2B756A` light, `#C98A2E` dark) | Primary CTA only, active lane marker, sparse wake/route seam line |
| Destructive | `--cw-status-error` (`#9A4D35`) | Destructive or policy-risk actions only, including reset confirmation warning if an in-app reset exists |

Accent reserved for: `Explore Showcase`, the current/active lane marker, one route-seam visual motif, and focus-supported primary actions. Do not use the accent for every link, every badge, or decorative page fills.

Runtime and support colors are semantic taxonomy signals, not general accent usage:

| Signal | Token | Label Examples |
|--------|-------|----------------|
| LiveView | `--cw-runtime-liveview` | LiveView route, Cached read-only |
| Offline | `--cw-runtime-offline` | Offline island, Local-first outbox |
| Native | `--cw-runtime-native` | Native screen, Requires native runtime |
| Bridge | `--cw-runtime-bridge` | Bounded bridge, Proof-backed example |
| Sensitive / gap | `--cw-runtime-sensitive` | Future gap, Demo pressure, Cache disabled |

Accessibility rules:

- Use visible text labels for every badge. Color is reinforcement only.
- Use `--cw-text-muted`, not Stone 500, for normal-size muted text.
- Focus rings use `--cw-action-focus-ring`, 2px outline, 2px offset.
- Preserve light, dark, and system theme behavior from `tokens.css`.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Explore Showcase |
| Empty state heading | Showcase data is not seeded |
| Empty state body | Run the showcase reset to restore deterministic SaaS, field-service, and learning records. Browser offline state is reset separately by the route-tour helpers. |
| Error state | Showcase reset failed. No browser offline state was changed. Check the server log, then rerun the reset task or gated `_e2e` reset endpoint. |
| Destructive confirmation | Reset showcase data: "Reset seeded server data? This restores deterministic records and does not clear browser IndexedDB." |

Hero/intro copy:

- Heading: Phoenix routes, native where it matters.
- Supporting copy: Three seeded lanes show which runtime owns each route: LiveView, offline island, or native-pressure path.

Lane card copy:

| Lane | Card Heading | Body Copy | Primary Link |
|------|--------------|-----------|--------------|
| SaaS/admin | SaaS/Admin | LiveView-first operations with admin and auth pressure kept Phoenix-owned. | Open SaaS Lane |
| Field-service | Field Service | Device-pressure jobs with capture gaps and native-screen candidates named honestly. | Preview Field Service |
| Learning/training | Learning/Training | Content packs and offline study without pretending every action commits offline. | Open Learning Lane |

Secondary proof/navigation copy:

| Surface | Copy |
|---------|------|
| Proof strip heading | Proof routes stay one click deeper |
| Proof strip body | Use these routes to inspect route-owner semantics, offline behavior, and bounded bridge proof after the showcase explains the product shape. |
| Proof link 1 | View Offline Study Proof |
| Proof link 2 | View Bridge Proof |

Allowed support labels:

- Available today
- Proof-backed example
- Demo pressure
- Advisory evidence
- Future gap
- Next-pack candidate

## Layout and Interaction Contract

### Root Hub

- Root `/` is the showcase hub. Do not make `/showcase` the primary entrypoint.
- The hub is Phoenix-owned, preferably `CrosswakeExample.Showcase.HubLive`, with route posture `runtime: :live_view`, `offline: :cached_read_only`, and `security: :standard`.
- The top of the page is a compact product surface, not a landing-page hero and not a docs index.
- The first viewport contains:
  - Product heading and one-sentence route-ownership explanation.
  - Three lane cards for SaaS/admin, field-service, and learning/training.
  - Visible route path, runtime badge, offline/support badge, capability chips, future-pressure note, and one clear CTA per lane.
- Diagnostics, raw manifest/support details, and old proof/demo routes sit below the lane grid or behind explicit secondary links.

### Lane Cards

- Each card uses the route-card motif: route path in monospace at the top, then runtime/offline/support badges, then concise JTBD copy, then CTA.
- The card body is not a hidden link. Only explicit links/buttons navigate.
- Badge vocabulary must come from the allowed support labels and runtime labels above.
- Each lane card must include one short boundary warning when a support claim could be confused:
  - SaaS/admin: Cached read-only does not mean offline edits.
  - Field-service: Capture/scanning pressure is a future/native-control candidate unless existing route proof backs it.
  - Learning/training: Offline study state is browser-owned; server reset does not clear IndexedDB.

### Reset / Reseed

- If an in-app reset control exists, it is visible only in local/dev/test/e2e posture and must not appear as a production mutation surface.
- Reset action label: Reset Showcase Data.
- Reset response display uses `role="status"` and `aria-live="polite"`.
- Reset result must show structured counts and a deterministic digest in monospace.
- Reset copy must explicitly state `browser_state_reset: false` or equivalent language when browser-owned IndexedDB is not touched.
- Reset errors use the error-state copy above and provide the next action.

### Motion

- Motion is optional and non-essential.
- Allowed motion: one route-seam/wake-line reveal or badge status transition.
- Timing: 120-160ms for button/status microinteractions; 180-240ms for panel transitions.
- Under `prefers-reduced-motion: reduce`, all motion becomes static state changes or simple opacity changes.
- No looping background motion behind text.

### Responsive Behavior

- Mobile base is single column at 375px and up.
- Lane cards stack on mobile and become three columns at desktop width.
- Text must not overflow buttons, badges, or cards. Long route paths wrap or use stable monospace truncation with accessible full text.
- Buttons and proof links are at least 44px high on mobile.
- No page section should be styled as a floating card; cards are only for individual lane/proof/reset items.
