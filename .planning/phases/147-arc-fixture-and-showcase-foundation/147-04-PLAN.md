<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| public browser -> root hub | Unauthenticated users can view showcase copy and labels. |
| test browser -> `_e2e` reset endpoint | Test code can mutate server-side showcase state. |
| catalog/reset modules -> rendered LiveView | Internal state and labels become user-visible product truth. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-147-11 | Spoofing | `HubLive` support labels | mitigate | Render only catalog labels verified in Plan 147-02; avoid broad support claims. |
| T-147-12 | Elevation of Privilege | `/_e2e/showcase-reset` | mitigate | Compile route only under `Mix.env() in [:test, :e2e]`; no arbitrary reset params. |
| T-147-13 | Tampering | reset endpoint | mitigate | Delegate to fixed `Showcase.Reset.reset!/0` and return counts/digest for proof. |
| T-147-14 | Information Disclosure | root hub diagnostics links | mitigate | Keep raw manifest/support detail one click deeper and do not expose backend internals in lane cards. |
| T-147-SC | Tampering | package installs | accept | No new npm/pip/cargo packages. |
</threat_model>
