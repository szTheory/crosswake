<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner → Hex registry | runner installs the `crosswake` archive from hex.pm at a pinned version |
| CI runner → SPM mirror / Maven Central | generated scaffold resolves the just-published native deps from external registries |
| third-party GitHub Actions → workflow | actions execute with runner permissions |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-111-10 | Tampering | malicious/wrong-version `hex crosswake` archive | mitigate | pin install to `needs.release-please.outputs.version`; never `latest` (RESEARCH Security Domain) |
| T-111-11 | Tampering | backdoored GitHub Action via tag reference | mitigate | SHA-pin all actions (CVE-2025-30066); reuse existing repo pins, no new tags |
| T-111-12 | Spoofing | scaffold resolves monorepo `packages/` instead of published deps (false pass) | mitigate | generate into `$RUNNER_TEMP` outside the checkout; no `--local`; SwiftPM/Gradle cannot reach `packages/` (RESEARCH Pitfall 2) |
| T-111-SC | Tampering | npm/pip/cargo installs | accept | no package-manager installs in this plan; only `mix archive.install` of the project's own published Hex package at pinned version (covered by T-111-10) |
</threat_model>
