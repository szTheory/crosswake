# Phase 155 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope reminder:** this phase ships the **confirm modal** (permanent, never a bridge fallback —
D-07) and the **action menu** (a real fallback, but pushes nothing in this phase — D-01/D-02).
Both ship as ONE host-owned `Phoenix.Component` module + one stylesheet, copied verbatim by
`mix crosswake.gen.native_controls_ui`. No importable `Crosswake.UI.*` module may exist
(FALL-02) — this is a structural CI guard (`Crosswake.ComponentTierGuard`), not a style
preference. All decisions below are LOCKED in `155-CONTEXT.md`; this file translates them into
the concrete tokens, markup contract, and proof assertions the planner and executor consume.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — this is a Phoenix/Elixir project; shadcn/React tooling does not apply |
| Preset | not applicable |
| Component library | Crosswake's own generator-owned `Phoenix.Component` pattern (`crosswake.gen.bridge_hook` precedent) — no external UI kit |
| Icon library | none — D-20 mandates **no icons** in the action menu; shape/color/text carry all signal |
| Font | Display: **Space Grotesk** (`--cw-font-display`) — titles, headings. Body: **Atkinson Hyperlegible Next** (`--cw-font-body`) — copy, button labels |

**Analogous safety gate (not shadcn registry, but same job):** `Crosswake.ComponentTierGuard`
(D-36/D-37/D-38) statically scans `lib/**/*.ex` for six violation classes (namespace,
namespace-minted, `Phoenix.Component`/`LiveComponent` use, `attr`/`slot` DSL, `~H` sigil, and the
anti-vacuity twin `components_exist_in_templates`) so nothing UI-shaped can ever ship importable
from `lib/`. This is the load-bearing equivalent of the registry vetting gate for this project.

## Spacing Scale

Declared values (multiples of 4 — matches `--cw-spacing-base: 4px` × N, already used throughout
`offline.css`/`app.css` as `calc(var(--cw-spacing-base) * N)`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-free tight gaps (destructive row's 4px separation band) |
| sm | 8px | Compact spacing inside a menu row, gap between label and helper text |
| md | 16px | Default padding rhythm inside modal/menu body |
| lg | 24px | Modal/menu inner padding, gap above button row |
| xl | 32px | Outer panel padding on wide viewports |
| 2xl | 48px | **Minimum interactive touch target** (buttons, menu rows) — matches D-16's "adopt platform ergonomics: 48px targets" exactly |
| 3xl | 64px | Not used by these two surfaces (reserved for page-level layout, out of scope here) |

Exceptions: none — 48px touch targets land exactly on the existing `2xl` step, so no ad hoc value
is introduced.

## Typography

All three sizes below are **existing** `--cw-text-scale-*` / `--cw-display-scale-*` tokens; none
are new. Exactly two weights, matching the generated-file precedent in `offline.css` (`600` on
the one existing heading, implicit `400` elsewhere) rather than the marketing showcase's heavier
weights (700/800), which belong to landing pages, not to a generated, adopter-owned utility file.

| Role | Size | Weight | Line Height | Usage |
|------|------|--------|-------------|-------|
| Body | 16px (`--cw-text-scale-md`) | 400 (regular) | 1.5 (`--cw-line-height-md` 24px) | Modal/menu body copy, Cancel button label, menu row label |
| Label | 14px (`--cw-text-scale-sm`) | 600 (semibold) | 1.43 (`--cw-line-height-sm` 20px) | Disabled-row helper text ("needs a supervisor"), empty-state copy, `role="alert"` inline error text |
| Heading | 20px (`--cw-text-scale-xl`), `--cw-font-display` | 600 (semibold) | 1.5 (`--cw-line-height-xl` 30px) | Modal `<h2>` title / menu `<h2>` heading — the one mandatory heading in each surface (D-20) |
| Display | not used | — | — | Reserved display-scale tier (28/40/56px) is not exercised by either fallback surface; row present for template completeness only |

Action button label (Approve/Delete/pending text) uses the **Body** row at weight **600** as an
exception baked into the button component, not a separate declared size — same 16px/1.5, bumped
to semibold for the one primary/destructive CTA per surface.

## Color

Both surfaces are ONE object per D-15: opaque `--cw-surface-inset` panel, one 20° 2px wake-seam
rule, `--cw-radius-lg`, display-font title, body-font copy — bottom-anchored below 768px, centred
above.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--cw-surface-inset` (white light / `current-800` dark) | Panel background — **mandatory**, not `--cw-surface-raised` (D-31: `text-muted` on raised is 4.11:1, fails AA) |
| Secondary (30%) | `--cw-overlay-scrim` (new token, `#09141AB8`, 8-digit hex, no `$dark` variant — D-27/D-28) | Full-viewport backdrop behind the panel only |
| Accent (10%) | `--cw-action-bg` (wake-700 light / brass-500 dark) + `--cw-action-focus-ring` (wake-700 light / wake-500 dark, fixed by D-33) | Reserved for: the neutral confirm/approve action button background; the `:focus-visible` ring on every interactive element; the 20° wake-seam decorative rule. **Nothing else.** |
| Destructive | `--cw-status-error` (rust-600, both themes) filled bg + `--cw-status-error-fg` (new token, white, 6.02:1 both themes — D-27/D-32) | Destructive confirm/delete button only, plus a 3px left bar shape cue on the destructive menu row (shape signal in addition to, never instead of, color) |

Accent reserved for: **primary/neutral action button background, focus-visible ring, wake-seam
rule.** Explicitly NOT menu row backgrounds, borders in general, or the Cancel button (Cancel
stays neutral/bordered, never accent-colored, at any tone).

**Contrast floor (computed via `brandbook/tools/contrast.mjs`, D-31):**
- `--cw-text-default` 18.64:1 light / 13.05:1 dark
- `--cw-text-muted` 5.09:1 light / 9.64:1 dark (**inset surface only** — fails on raised)
- `--cw-action-bg`/`-fg` 5.45:1 / 6.35:1
- `--cw-border-strong` 5.45:1 / 9.64:1 (Cancel border **must** use this, not `--cw-border-default` — dark `--cw-border-default` is 1.49:1)
- `--cw-status-error-fg` on `--cw-status-error` 6.02:1 both themes
- `--cw-action-focus-ring` (post-fix) — must be re-verified ≥3:1 against WCAG SC 1.4.11 in both themes before this phase closes; it is currently the one gate hole (D-33) this phase repairs

## Token Alias Layer (host-owned, D-24)

The generated CSS references a **scoped `--cwfb-*` alias block** on `.cw-fallback`, never
`var(--cw-*)` directly. This is the ~12-line re-point surface an adopter with their own design
system edits; the alias names below are the concrete contract (exact spelling was left to this
agent's discretion per CONTEXT.md — this is the resolution):

```css
.cw-fallback {
  --cwfb-surface:       var(--cw-surface-inset);
  --cwfb-scrim:         var(--cw-overlay-scrim);
  --cwfb-ink:           var(--cw-text-default);
  --cwfb-ink-muted:     var(--cw-text-muted);
  --cwfb-border:        var(--cw-border-default);
  --cwfb-border-strong: var(--cw-border-strong);
  --cwfb-action-bg:     var(--cw-action-bg);
  --cwfb-action-fg:     var(--cw-action-fg);
  --cwfb-action-hover:  var(--cw-action-hover);
  --cwfb-focus-ring:    var(--cw-action-focus-ring);
  --cwfb-danger-bg:     var(--cw-status-error);
  --cwfb-danger-fg:     var(--cw-status-error-fg);
  --cwfb-radius:        var(--cw-radius-lg);
  --cwfb-font-display:  var(--cw-font-display);
  --cwfb-font-body:     var(--cw-font-body);
}
```

**Zero theme logic in this file** (D-25): no `prefers-color-scheme`, no `[data-theme]`
selectors. Copy exactly one line from `offline.css:5-7`: `:root { color-scheme: light dark; }`.
Both light/dark resolution happens upstream in `tokens.css`, which is **library-served** at
`/crosswake/tokens.css` via a second `Plug.Static`, not copied into the host (D-26) — one source
of truth, fixing the `gen.offline_ui` 404 and the ungated third tokens.css copy as a side effect.

**Two new semantic tokens only** (27 → 29 of a documented hard cap of 30, `AUDIT.md:392`):
1. `--cw-overlay-scrim` ← new primitive `current.950a72` = `#09141AB8`. No `$dark` variant.
2. `--cw-status-error-fg` ← alias to `{primitive.white}`.

Both authored in `brandbook/tokens/crosswake.tokens.json`, compiled by `compile-tokens.js`.
**`compile-tokens.js:67`'s `groups` array must gain `'overlay'`** or the scrim token is silently
dropped and the modal renders with a transparent backdrop — no gate failure (D-29). No
`color-mix` anywhere in the scrim (iOS 16.2 floor vs. this project's iOS 15.0 floor,
`Package.swift:9` — D-28).

## Component Inventory & Artifact Contract

| Artifact | Path | Shape |
|----------|------|-------|
| Component module | `lib/<app>_web/components/crosswake_fallbacks.ex` | ONE host-owned `Phoenix.Component` (never `LiveComponent` — technically blocked, D-04) carrying `confirm_modal/1`, `action_menu/1` markup **and** the `Bridge.resolve/2` socket transitions (D-03) |
| Stylesheet | `priv/static/assets/crosswake_fallback.css` | Zero JS, zero theme logic (D-10/D-25) |
| Generator | `mix crosswake.gen.native_controls_ui` | No-clobber copy, following `crosswake.gen.bridge_hook`'s stamp pattern (D-35): `@template_version` header + doctor stamp-drift finding — **not** `gen.offline_ui`'s pattern, no `--force`, no three-way merge |
| Fixed event names | `crosswake_fallback_answer`, `crosswake_fallback_dismiss` | Not configurable attrs — adopter pastes 3 `handle_event` clauses from generator-printed output (D-06) |

**Focus trap = `Phoenix.Component.focus_wrap/1`** — a LiveView built-in already served/imported by
the reference host. Zero new JavaScript in this phase (D-10). Everything else — `JS.push_focus`
/ `pop_focus`, `phx-remove`, `phx-window-keydown` + `Escape`, `phx-click-away`, `JS.add_class` /
`remove_class` scroll lock, server-rendered `inert` on background — is LiveView built-ins
authored in HEEx (D-11). Reject `<dialog>`/`showModal()` (JS-only, regresses CSP; also below iOS
15.0 in spirit terms — actually iOS 15.4) and Popover API/CSS anchor positioning (iOS 17 floor,
D-12).

**Rendering model (D-02):** fallback-first, native-enhance. Visibility is a pure function of
assigns, rendered in the same server round-trip that opens it — never client-revealed, never
denial-triggered. The snapshot-assign discipline (D-14) means same-id re-patch is harmless and
`phx-remove={remove_class |> pop_focus}` handles resolve-while-open.

## Confirm Modal — Contract

**Permanent primary confirm surface on every platform, forever (D-07).** Zero `Bridge`
involvement: no push, no `ref`, no `resolve/2`, no denial branch. `Crosswake.REQUIREMENTS.md:116`
places a native alert/confirm bridge family permanently out of scope — this is not a fallback
degrading from something better; it is the only thing that will ever exist.

| Property | Contract |
|----------|----------|
| Layout | Centred dialog ≥768px, bottom sheet below |
| Role | `role="dialog"` neutral / `role="alertdialog"` destructive |
| Dismissal | Destructive: **no click-away dismissal** (Radix Dialog/AlertDialog split). Neutral: click-away allowed |
| Button order | DOM `[Cancel, Action]`; narrow `column-reverse` (Action top); wide `row` + `flex-end` (Cancel left, Action right) — no tone exception (D-18) |
| Initial focus | Action for neutral, **Cancel for destructive** (`JS.focus(to:)`) — the one tone branch (D-19) |
| Close timing | Closes on **server confirmation**, never on click |
| `title` / `confirm_label` attrs | **Required, no default** — a missing value is a compile error, not "OK"/"Confirm" (D-58) |
| Destructive treatment | Filled `--cwfb-danger-bg` button + `--cwfb-danger-fg` text (6.02:1 both themes) **plus** a border-left shape cue — never shape alone (D-32, user decision over the zero-token alternative) |

## Action Menu — Contract

**The one real fallback in this phase** — but it pushes nothing (D-01). Same chassis as the
confirm modal.

| Property | Contract |
|----------|----------|
| Layout | Centred modal at every viewport in this phase (**not** a trigger-anchored dropdown — deferred to SEED-005, D-22) |
| Structure | Mandatory `<h2>`; `<ul>`/`<li>`/`<button>`; **no icons** (D-20) |
| Row cap | ~7 rows before scroll: `max-height: min(60vh, 420px)`; heading and Cancel sit **outside** the scroll container |
| Destructive row | Last, behind a 4px gap band, 3px left bar; always routes through the destructive confirm modal — **never straight to the mutation** |
| Pending state | On the **trigger only**, never per-row |
| ARIA | **Do NOT use `role="menu"`** — the APG Menu contract obliges roving tabindex/arrow-keys/Home-End, which is the JS this phase exists to avoid; "no ARIA is better than bad ARIA" (D-21). Trigger takes `aria-expanded` + `aria-controls`, **not** `aria-haspopup`. Buttons live in a dialog, not a native menu role |
| `aria-modal` caveat | Unreliable in Safari + VoiceOver; the `inert` background mitigation covers it for free but this must be recorded as a **manual-check limitation**, not claimed as proven (D-23) |

**155 → 156 seam (D-53, one-way door):** frozen `actions` shape —
`actions :: [%{id, label, destructive, icon}]` — with two outcomes (select-with-id, dismiss). No
`Bridge.push/3` call in this phase; ship an inert commented Phase-156 hand-off block inside the
generated `action_menu` source itself (D-55), since the generator has no `--force` to deliver an
upgrade any other way.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Neutral confirm title | `Approve this request?` |
| Neutral confirm body | `The requester is notified and the decision is recorded.` |
| Neutral confirm action | `Approve request` (pending: `Approving…`) |
| Destructive confirm title | `Delete this job?` |
| Destructive confirm body (required, no default) | `This removes the job and its 3 photos. It cannot be undone.` |
| Destructive confirm action | `Delete job` (pending: `Deleting…`) |
| Cancel (both) | `Cancel` (NN/g Cancel-vs-Close) |
| Success (neutral) | `Approved. The requester was notified.` |
| Success (destructive) | `Deleted. The job and its photos are gone.` |
| Answer-didn't-land (`role="alert"`, panel stays open) | `That didn't save. Nothing was changed — try again.` |
| Menu heading | `Choose an action` |
| Menu dismiss | `Cancel` |
| Menu disabled row | `Reassign job — needs a supervisor` |
| Menu empty state | `No actions are available for this record.` |
| Fail-closed: stale-binary (`role="alert"`, inline, never a modal) | `This action needs a newer version of the app. Update the app, then try again.` |
| Fail-closed: undeclared (`role="alert"`, inline, never a modal) | `This action isn't available here. Nothing was changed.` |
| `:shell_unreachable` | No string at all — the fallback simply renders (precedent: `approval_live.ex:292-297`) |

**Hard copy rule (D-09):** the word **"fallback" must never reach an end user.** Nor may `push` /
`reply` / `answer` / `denial`, bridge, shell, capability, route policy, seam, manifest, or hook —
all internal-only (moduledocs, attribute names, doctor output, demo evidence panels).

**Framing in generator output (D-08):** the confirm modal's printed generator output and module
header comment must state plainly that this is the control a developer reaches for when looking
for a native confirm that does not exist — and must carry NN/g's rule: *if you can offer undo,
offer undo instead of this modal.*

## Second-Run, Drift & FALL-02 Guard Contract

- **No-clobber generator** with a stamped `@template_version` header (copy of
  `crosswake.gen.bridge_hook`'s pattern) + a `mix crosswake.doctor` stamp-drift advisory finding.
  No `--force`, no three-way merge, no igniter adoption in this phase (D-35).
- **Drift MANIFEST is curated, not a glob** (`check-consumer-drift.mjs:29`). The two new
  **library template** files (`priv/templates/crosswake/native_controls_ui/*.eex`) **must** be
  added to the manifest. Generated **host** files are explicitly **not** added — the gate proves
  the shipped default is brand-clean; it does not police the adopter's edited copy (D-34). Use
  literal `class="…"` only — `class={…}` dynamic bindings are a documented blind spot.
- **`Crosswake.ComponentTierGuard`** (new, `lib/`-resident, mirrors `CatalogGuard`/
  `CompanionGuard`) enforces FALL-02 with six rules: `namespace`, `namespace_minted`,
  `component_use`, `component_dsl`, `template_sigil`, and the anti-vacuity twin
  `components_exist_in_templates` (D-36/D-37). Guard failure messages follow the stable
  bracketed-id shape with a five-step retirement recipe (D-38) — never allowlist, always retire
  with a documented replacement path.
- **Endpoint patcher gains a second `Plug.Static`** for `/crosswake/tokens.css`, and needs
  marker-content reconciliation so existing Phase 154 adopters actually receive it — the current
  `[:marker_reused]` return never reconciles block contents (D-52, a shipped-code defect this
  phase must fix).

## PROOF-01 Browser Lane Contract

- **New spec file**, not an extension of the 613-line `route_tour.spec.ts`:
  `examples/phoenix_host/e2e/native_controls_fallback.spec.ts` (~200 lines). Lands in the
  already-required `e2e-proof` → `merge-blocking-offline-sync-e2e` job — **no new workflow, no
  new required check name** (D-42).
- **Three routes, three conditions** (D-45):
  - A1 fallback renders → `/saas/approvals/approval-1` (existing, product-shaped)
  - A2 undeclared → **new** `/_e2e/undeclared-control` (prod-policed by existing `guard-02`)
  - A3 no-silence → `/bridge-proof` (adds no UI, enumerates already-visible paths)
- **Corrected criterion wording (D-43/D-44 — supersedes ROADMAP.md success criterion 3 as
  written):** *"An undeclared capability raises and names the missing declaration; an
  unavailable capability renders an explicit denial. A merge-blocking browser route-tour proves
  that the fallback renders, that a shell-side denial renders and the mutation does not proceed,
  and that no failure path resolves to silence. The outbound `UndeclaredCapabilityError` is
  deliberately excluded from the browser lane — a browser cannot observe a server-side raise —
  and is asserted server-side in ExUnit instead."* Label this split **hybrid** in the spec
  docblock.
- **Non-vacuity conditions per assertion (D-46):**
  - Absent-before/present-after on `data-cw-fallback` — vacuous if the route hardcodes the modal;
    require the committed example-host file to carry the generator stamp.
  - Catalog sentence read from `Manifest.Builder`, never hardcoded.
  - Focus trap asserted as **behavior** (Tab/Shift-Tab wrap, Escape, focus return).
  - Computed WCAG AA in both schemes via in-page `data-theme` toggle, not extra Playwright
    projects (would triple the lane's wall clock).
  - **Focus-ring ≥3:1 fails today** and only passes after the D-33 fix — track this as the
    canary that proves the gate hole is genuinely closed.
  - Denial injected via `page.addInitScript()` using the **doubly-nested** wire shape verbatim —
    vacuous if single-nested.
  - Assert reason is `undeclared_capability`, **not** `unavailable_capability` (D-13 regression
    guard).
  - Assert **no `role="menu"`** anywhere.
  - **The negative control that matters:** assert the success surface AND the server-side effect
    are both absent — "a denial rendered" does not mean "the mutation did not happen."
- **"Never silently degrades" honest approximation (D-47):** enumerate the vocabulary from
  `CatalogGuard.closed_vocabulary/0`; require *exercised ∪ explicitly-excluded == full set* so a
  new reason turns the lane red. Assert rendered text changed **from idle**, not merely
  non-empty. Add a MutationObserver dead-air invariant. Add a
  `CROSSWAKE_PROOF_BREAK_FALLBACK` mutation control in the example host only, never in `lib/`.
- **Explicit non-claims (D-48) — paste into the spec moduledoc:** not "never" as a universal,
  only the enumerated current vocabulary (excludes SEED-008's five unbounded `String` seams); not
  native behavior (Chromium is a stand-in, not iOS/Android); not the adopter's edited fallback;
  not that the UI is *good* (contrast/focus are floors, not judgments); not reachability on every
  route; not screenshots.
- **All of PROOF-01 is merge-blocking** — consistent with the existing `brand-structural`
  (required, DOM/Playwright) vs. `brand-visual` (advisory, pixel) split; none of this proof is a
  pixel assertion (D-49). Fix the missing failure-artifact upload on `e2e-proof` before landing
  this required assertion. No `continue-on-error`, no `@flaky` quarantine, no `sleep` — the
  ~2000ms ack deadline is awaited via rendered outcome.
