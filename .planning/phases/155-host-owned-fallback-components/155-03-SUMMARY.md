# Phase 155 Plan 03: Focus-Ring Contrast Fix and the Non-Text Gate Hole Summary

**Corrected `--cw-action-focus-ring`'s light value from a WCAG SC 1.4.11-failing brass-500 (2.93:1 on white) to a passing wake-700 (5.45:1), added `--cw-status-error-fg` for the destructive button's dark-theme colour channel, and widened `contrast.test.mjs` with its first non-text UI-component assertion class — proven by two recorded, restored mutation controls.**

## Performance

- **Duration:** ~25 min
- **Tasks:** 2 completed
- **Files modified:** 7

## Accomplishments

- Added `status.error-fg` (pure alias to `primitive.white`) to `crosswake.tokens.json`; measured 6.02:1 on `status.error` in both themes via `node brandbook/tools/contrast.mjs`, giving the filled destructive button a colour danger signal on dark where `status.error` as text is only 2.44:1.
- Corrected `action.focus-ring`'s light value from `brass-500` to `wake-700`; measured pre-fix (2.93:1 on white, 2.61:1 on foam-50 — both below WCAG SC 1.4.11's 3:1 non-text floor) and post-fix (5.45:1 on white, 4.85:1 on foam-50) in this session. Dark value (`wake-500`, 4.43:1 on the dark inset surface) was already passing and stayed unchanged.
- Regenerated all three compiled `tokens.css` copies (`brandbook/tokens/tokens.css`, `priv/static/crosswake/tokens.css`, and the 155-01-added served sibling `priv/static/tokens.css`) byte-identically from `compile-tokens.js`'s single write path — no extra step needed, since all three come from the same `out` string in one run.
- Repaired `brandbook/AUDIT.md`'s stale semantic-token inventory (it still said "27 total" with no `overlay` group table despite 155-01 already shipping `--cw-overlay-scrim`) and brought it to 29/30 with an explicit "1 slot remains" note.
- Widened `contrast.test.mjs` with its first non-text (WCAG SC 1.4.11, ≥3:1) assertion class, distinct from the pre-existing text-only (≥4.5) class — the gap that let a 2.93:1 ring ship green. All new assertions resolve hex from `crosswake.tokens.json` at test time via a new `resolveTokenHex()` alias-chain walker, never a pasted literal.
- Added a mechanical semantic-token count cap (≤30, exactly 29 today) and a group-exhaustiveness assertion (every color-typed top-level JSON group must emit at least one compiled `--cw-<group>-*` property) to `compile-tokens.test.mjs`.
- Ran both required mutation controls in this session, observed both fail red with the expected named failures, and restored both files via `git checkout --` (never touching `refs/stash`).
