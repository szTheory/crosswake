## Trust Boundaries

| Boundary | Description |
| --- | --- |
| host config → normalizer | Host-controlled keys and filesystem paths enter library-owned validation. |
| templates → host filesystem | Library bytes cross into permanently host-owned files. |
| generated driver → evidence builder | Test outcomes cross into a retained artifact boundary. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
| --- | --- | --- | --- | --- | --- |
| T-159-01 | Tampering | `Generator.generate/1` destinations | high | mitigate | Normalize and contain every destination, use missing-only collision-safe writes, and prove edited-byte preservation plus concurrent collision failure. |
| T-159-02 | Information Disclosure | config/error/output boundary | high | mitigate | Emit stable rule/key/remediation only; templates consume normalized values but CLI and retained evidence never print them. |
| T-159-03 | Repudiation | generated device outcomes | high | mitigate | Closed outcomes and explicit prerequisite IDs prevent skip/no-op paths from representing a device pass. |
| T-159-04 | Elevation of Privilege | generated test-only driver | medium | mitigate | Keep the driver test-only and opaque; it carries no credential, replay, pack, mutation, or authorization authority. |
| T-159-SC | Tampering | package/template supply chain | low | accept | Research confirms no install; only repository-owned templates, locked dependencies, and platform XCTest/XCUITest are used. |
</threat_model>
