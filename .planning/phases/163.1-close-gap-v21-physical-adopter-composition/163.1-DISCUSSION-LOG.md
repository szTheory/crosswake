## Route handoff and promotion gate

| Option | Description | Selected |
|--------|-------------|----------|
| Block all work until TODO-002 arrives | Maximizes boundary simplicity but leaves independently actionable composition and classifier defects open and creates a larger late integration burst. | |
| Promote the synthetic reference route | Preserves the current fixture flow with little churn, but directly contradicts the route-policy gate and would turn fixture evidence into a false adopter claim. | |
| Two-tier fixture/adopter gate | Permit clearly labeled fixture-safe remediation; require one validated sanitized handoff for eligible-host binding, physical execution, retained promotion, and support truth. | ✓ |

**User's choice:** The user selected all areas and delegated a deeply researched, coherent one-shot
recommendation so they would not need to arbitrate the tradeoffs.

**Notes:** The selected approach keeps route validation pure and closed, rechecks it on every promotion,
and never treats a one-time configuration decision as permanent authority. This matches Plug's halt-on-
denial model, Ecto's constraint/transaction posture, and Hotwire Native's useful server-owned-routing
lesson without adopting URL history as Crosswake route authority.

## Physical shell composition

| Option | Description | Selected |
|--------|-------------|----------|
| Delivered shell around a host-owned study leaf | Exercises the actual compiled topology, `NavigationCoordinator`, UIKit tab/stack authority, typed transitions, insets/marker, accessibility, and state retention. | ✓ |
| Proof-target-local UIKit wrapper | Quick local chrome, but duplicates coordinator and topology authority and can drift into the same integration failure under a different type name. | |
| SwiftUI tabs around the standalone proof view | Lowest apparent churn, but bypasses the delivered UIKit shell, typed transition bridge, restoration reauthorization, and physical navigation requirements. | |

**User's choice:** Delegated expert recommendation; the delivered shell composition was selected.

**Notes:** Hotwire Native demonstrates the value of real native container lifecycle and retained web
state, while its tab-reload reports reinforce the need for an explicit tab-return persistence test.
Apple's conventions favor stable labeled destination tabs, standard back behavior, and a single
UIKit/SwiftUI representable boundary rather than competing navigation state machines.

## Device-driven failure and lifecycle flows

| Option | Description | Selected |
|--------|-------------|----------|
| Continuous happy path plus isolated negative cases | Preserves the learner journey and device/server causality while making each destructive or denying branch deterministic and diagnosable. | ✓ |
| One monolithic master flow | Produces one narrative, but logout, switching, denial, conflict, and resets make it order-fragile and difficult to rerun or diagnose. | |
| Fully isolated cases only | Gives short tests, but loses the uninterrupted offline-save/relaunch/replay proof and becomes a collection of observations rather than a journey. | |

**User's choice:** Delegated expert recommendation; the mixed sequential/isolated model was selected.

**Notes:** Host-private controls prepare conditions but do not satisfy assertions. The iPhone must
perform the product action, and Phoenix must verify the resulting invariant. Ecto database constraints
avoid uniqueness races; accepted replay and domain effect commit together. PouchDB's visible-conflict
honesty is useful, while its winner-selection/replication model and WatermelonDB's broad two-phase sync
surface are intentionally not adopted.

## Pack and evidence convergence

| Option | Description | Selected |
|--------|-------------|----------|
| Complete learning-bundle provider through existing `PackProvider` | Reuses one lifecycle and activation authority while keeping manifest/assets/layout/playback host-private; device/backend evidence joins through one redacted all-or-nothing contract. | ✓ |
| Keep the bespoke installer beside `PackProvider` | Preserves current code but creates split-brain installation, integrity, recovery, and relaunch truth. | |
| Generalize core storage and evidence APIs | Could support future hosts, but violates the stop list and creates compatibility, Android, storage, and maintenance obligations without the ADR reversal condition. | |

**User's choice:** Delegated expert recommendation; the existing `PackProvider` seam and strict
redacted evidence join were selected.

**Notes:** The provider may privately validate multiple files as one immutable bundle, but Crosswake
receives only the existing closed installed record. Playback stays host-owned. Evidence retains the
canonical contract and completion marker only; AIFF is an explicitly excluded reference resource,
not evidence. Backend producers verify device-caused outcomes instead of manufacturing them.
