## Summary

Phase 163.1 should close four audit-proven composition defects through the existing seams: make physical execution depend on a current sanitized route handoff and compiled topology; mount the existing UIKit shell instead of `ReferencePhysicalStudyView`; replace the private learning-bundle installer with one host-private `PackProvider`; and convert backend-only negative scenarios into device-caused, independently checked cases. The audit explicitly reports that all prior phase-local requirements are green yet the cross-phase composition is broken, so this phase needs new gap requirements rather than re-closing ALPHA/DEVICE/NAV IDs. [VERIFIED: .planning/v21.0-MILESTONE-AUDIT.md]

`RouteInventory` already rejects unknown, duplicate, forbidden, and unsafe input, while `NavigationTopology` only returns `ready` for eligible rows plus valid entries. `NavigationCoordinator` already owns tab/stack state and reauthorizes roots, transitions, restoration, and native pops; `NavigationShellViewController` retains a leaf controller per stack entry and posts one `.screenChanged` event after completed navigation. The missing work is orchestration and physical-target composition. [VERIFIED: lib/crosswake/adoption/route_inventory.ex; lib/crosswake/adoption/navigation_topology.ex; packages/crosswake-shell-core-ios/Sources/CrosswakeShellCore/NavigationCoordinator.swift; examples/ios_shell_host/CrosswakeShell/NavigationShellViewController.swift]

**Primary recommendation:** Implement one host-owned `adopter-bound` composition mode that is impossible to invoke without fresh handoff/topology preflight, then make the physical XCTest/XCUITest target drive every required lifecycle/recovery action through that mode and promote evidence only from its exact joined report. [VERIFIED: 163.1-CONTEXT.md; .planning/v21.0-MILESTONE-AUDIT.md]

**What:** Load one host-private handoff, validate inventory, compile a `ready` topology, and perform the same validation again inside preflight. Return a stable blocked rule without returning rejected input. [VERIFIED: 163.1-CONTEXT.md; RouteInventory; NavigationTopology]

**When to use:** Every physical-run invocation, evidence promotion, support-claim promotion, and adopter-bound host composition. Fixture runs remain separately named and non-promotable. [VERIFIED: 163.1-CONTEXT.md]

### Pattern 3: Provider/store split for a private immutable bundle

**What:** Implement one host-private `PackProvider` that stages manifest/image/audio, validates every internal file against host-private expected facts, atomically promotes the complete bundle, and returns only `PackInstalledRecord`. Let `PackStore.reconcileAll()` decide route availability from fresh `status(for:)`. [VERIFIED: 163.1-CONTEXT.md; PackProvider.swift; PackStore.swift]

**When to use:** Physical host install, relaunch, replacement failure, revocation, and activation—not a separate proof adapter. [VERIFIED: 163.1-CONTEXT.md]

### Pattern 4: Device-caused negative cases and exact evidence join

**What:** Each independent XCUITest starts with isolated host-private control setup, causes the normal device action, observes only learner-safe UI state, then asks Phoenix to verify the authority/domain result for the same ephemeral nonce and opaque case/mutation reference. The existing Mix task should still reject missing, reordered, wrong-owner, or non-passing report entries. [VERIFIED: 163.1-CONTEXT.md; crosswake.proof_lane.physical_iphone.ex]

### Anti-Patterns to Avoid

- **Synthetic route used as a promotion route:** fixture success is regression evidence only and must never become support or physical-promotion evidence. [VERIFIED: 163.1-CONTEXT.md]
- **Swift-side route/topology constants:** creates a second authority and bypasses fresh current-run validation. [VERIFIED: 163.1-CONTEXT.md]
- **Standalone `ReferencePhysicalStudyView`:** bypasses topology, coordinator, marker, insets, and native transition behavior. [VERIFIED: v21.0-MILESTONE-AUDIT.md]
- **Backend-created recovery evidence:** proves a server unit behavior, not the iPhone flow. [VERIFIED: v21.0-MILESTONE-AUDIT.md]
- **Availability from an install button or audio playback:** must reconcile a verified provider result first. [VERIFIED: PackStore.swift; 163.1-CONTEXT.md]
- **Retaining the physical run root or `.xcresult`:** breaks the evidence privacy contract. [VERIFIED: 163.1-CONTEXT.md]

## Common Pitfalls

### Pitfall 1: Making fixture repair look like adopter promotion

**What goes wrong:** A synthetic confirmed row remains in the physical host and produces a passing retained artifact.
**Why it happens:** The current host uses `route-1630000000000001` and a synthetic inventory. [VERIFIED: physical_iphone_proof_host.ex; v21.0-MILESTONE-AUDIT.md]
**How to avoid:** Model fixture and adopter-bound modes as distinct results; promotion must demand a freshly loaded, host-owned sanitized handoff and a `ready` topology. [VERIFIED: 163.1-CONTEXT.md]
**Warning signs:** Preflight can pass when TODO-002 is open, or evidence contains the synthetic reference route. [VERIFIED: TODO-002; physical_iphone_proof_host.ex]

### Pitfall 2: Replacing a shell rather than composing it

**What goes wrong:** The physical branch renders a plain SwiftUI study screen and tests never exercise tabs, retained stacks, marker/insets, deep links, back, or focus. [VERIFIED: ProofLaneApp.swift; v21.0-MILESTONE-AUDIT.md]
**How to avoid:** Make the host leaf factory the only physical study presentation; assert shell marker/inset/transition behavior via the actual target. [VERIFIED: 163.1-CONTEXT.md]
**Warning signs:** `ReferencePhysicalStudyView()` remains reachable when the physical adapter environment is set. [VERIFIED: ProofLaneApp.swift]

### Pitfall 3: Backend tests passing without a device cause

**What goes wrong:** `PhysicalIphoneAuthority.report/2` resets fixtures and produces rejection/conflict/lifecycle outcomes itself. [VERIFIED: physical_iphone_authority.ex]
**How to avoid:** Treat backend controls as setup only; require a device request and device-observed retained/recovery state before the backend checks the correlated invariant. [VERIFIED: 163.1-CONTEXT.md]
**Warning signs:** Negative assertions still pass if XCUITest omits the corresponding interaction. [VERIFIED: v21.0-MILESTONE-AUDIT.md]

### Pitfall 4: Pack truth split between two installers

**What goes wrong:** The existing private adapter validates assets independently of `PackProvider`/`PackStore`. [VERIFIED: ProofLaneDriver.swift; v21.0-MILESTONE-AUDIT.md]
**How to avoid:** Move its host-private byte handling behind the existing provider and check fresh store reconciliation on every activation/relaunch. [VERIFIED: 163.1-CONTEXT.md; PackStore.swift]
**Warning signs:** `ReferenceLearningBundleAdapter` remains an availability authority or reports success before a provider `status(for:)`. [VERIFIED: 163.1-CONTEXT.md]

### Pitfall 5: Privacy-router broadening

**What goes wrong:** A convenient `*.aiff` or generic binary exclusion allows unrelated artifacts through silently. [VERIFIED: 163.1-CONTEXT.md]
**How to avoid:** Add exact approved paths/classes only; retain `:unclassified` as a failing result for every other path. [VERIFIED: FirstAdopterContext; 163.1-CONTEXT.md]
**Warning signs:** Classifier accepts a newly introduced binary without an explicit test. [VERIFIED: FirstAdopterContext]
