<decisions>
## Implementation Decisions

### Route handoff and promotion gate

- **D-01:** Use a two-tier gate. The existing synthetic/reference route remains useful only for
  deterministic fixture regression. Fixture-safe composition repairs may proceed while TODO-002 is
  unavailable, but their outputs stay explicitly `fixture` or `blocked`; they are never eligible-host,
  physical-promotion, or support evidence.
- **D-02:** Before adopter binding, physical execution, evidence promotion, or public support truth,
  require one host-owned sanitized handoff bundle containing the closed route-inventory fields and
  minimum navigation entries. Validate it through `Crosswake.Adoption.RouteInventory`, compile a
  `ready` `Crosswake.Adoption.NavigationTopology`, and recheck both in physical preflight before any
  device or evidence side effect. — **Reversibility:** costly — promotion tooling, generated hosts,
  topology compilation, and retained evidence all depend on one shared eligibility chain.
- **D-03:** The handoff has one route/topology authority. Do not add Swift-side route declarations,
  infer missing fields, copy a raw adopter artifact into git, or let a previously validated row bypass
  current-run preflight. Unknown, incomplete, contradictory, duplicated, or unrecognized input remains
  `unknown_blocking` with a stable non-echoing reason.
- **D-04:** Sanitized durable rows may contain only the existing closed, non-identifying vocabulary.
  Host-private paths, flags, endpoints, integrity values, scope mappings, content layout, product
  taxonomy, identity, and raw payload facts stay outside repository artifacts.

### Physical navigation-shell composition

- **D-05:** Replace the physical branch's standalone study screen with the delivered bounded shell:
  `NavigationShellView`, `NavigationCoordinator`, the compiled topology, and the existing
  UIKit-tab/navigation-controller authority. The adopter host supplies the study leaf; Crosswake keeps
  route authorization, typed transitions, denials, shell marker, and safe-area/keyboard contracts.
  — **Reversibility:** costly — the physical target, host composition root, XCUITest flow, topology,
  and evidence assertions must exercise the same shell path.
- **D-06:** Materialize a leaf only after manifest/topology validation and current activation
  reauthorization. Keep one leaf container per live stack entry so tab return and native back do not
  discard unsynced study state. `push_patch` remains in-frame; `push_navigate`, tab selection,
  deep-link reconstruction, restoration, back, and edge swipe remain coordinator-mediated native
  transitions.
- **D-07:** Keep the generic `ProofLaneView` only for nonphysical generated contract/advisory lanes.
  The physical path contains production-shaped shell and study surfaces, not proof buttons,
  diagnostics, assertion IDs, route IDs, scope references, or backend controls visible to learners.
- **D-08:** Use host-owned concise tab labels and familiar SF Symbols, standard tab/back behavior,
  Dynamic Type, 44-point targets, text plus icon/status, system light/dark appearance, Reduce Motion,
  and one meaningful focus/VoiceOver handoff after a completed transition. Insets never trigger an
  announcement. Tab return must preserve the active local study state.

### Device-driven failure and lifecycle flows

- **D-09:** Preserve one uninterrupted physical happy path: verified pack install, authorized entry,
  selected and free-form offline saves, offline audio, terminate/relaunch without reset, reconnect,
  same-ID retry, one accepted domain effect, and empty outbox. Never reset between offline mutation,
  relaunch, and accepted replay.
- **D-10:** After that journey, run independently reset cases in the same physical XCTest/XCUITest
  target for rejection recovery, conflict recovery, logout, account switch, entry disablement, and
  replay disablement. Isolation is between cases; no case may manufacture evidence for another.
  This balances causal coverage with deterministic diagnosis instead of one order-fragile mega-flow.
- **D-11:** Host-private, run-scoped fixture controls may prepare rejection, conflict, session, or
  feature conditions, but they are not the passing assertion. Each case passes only when an iPhone
  action traverses the normal app/Plug/Phoenix path, the device observes the correct product state,
  and the backend independently verifies the resulting authority/domain invariant.
- **D-12:** Plug/Phoenix derives session, route, feature, Sigra, scope, and domain authority on every
  request and halts on denial. Ecto owns a database uniqueness constraint scoped by opaque scope plus
  mutation ID; accepted event persistence and its single domain effect commit atomically. Do not use a
  race-prone preflight uniqueness query, acknowledge before commit, or delete rejected/conflicted/
  fenced/disabled local work.
- **D-13:** Account transitions fence first. Logout and account switching make the old partition
  ineligible before a new scope becomes active; retained work never appears in another account. Entry
  and replay disablement are separately exercised, retain queued work, and cannot silently downgrade
  the route to online-only behavior.
- **D-14:** Learner UX uses the existing task-oriented status language and a contextual in-flow status
  region: `saved_locally`, `syncing`, `needs_attention`, and `sync_paused`. Use calm copy such as
  “Saved on this iPhone,” “Some saved answers need review,” and “Your saved answers remain on this
  iPhone.” Hide scope, mutation, replay, flag, transaction, and test-fixture mechanics. Recovery offers
  one meaningful next action, preserves draft/work state, and uses a single semantic announcement or
  focus handoff per transition.

### Pack and evidence convergence

- **D-15:** Replace `ReferenceLearningBundleAdapter` as an installation authority with one host-private
  immutable learning-bundle provider conforming to the existing `PackProvider` contract. Do not add a
  second core pack/storage API. — **Reversibility:** costly — activation, relaunch reconciliation,
  recovery UI, physical proof, and host provider tests must converge on the existing public seam.
- **D-16:** The host provider owns one bundle version and privately stages and verifies its manifest,
  card image, and pronunciation audio, including exact declared sizes/digests, before one atomic
  promotion. Those assets share install, integrity, rollback, relaunch, and invalidation truth.
  Crosswake consumes only the closed `PackInstalledRecord`; asset lookup and audio playback remain
  host-owned and do not expand `PackProvider`.
- **D-17:** Pack readiness comes only from fresh provider status reconciliation. An install command,
  marker, partial directory, outer archive digest without internal validation, or successful playback
  alone cannot grant route availability. Preserve the last-known-good complete bundle until verified
  replacement commits; stale or revoked content remains route-blocking.
- **D-18:** Keep independent device and Phoenix evidence owners, but change the backend producer from
  manufacturing negative outcomes to verifying device-caused outcomes. Bind device action, request,
  backend invariant, and report to one ephemeral run nonce plus opaque case/mutation references. The
  join is all-or-nothing, requires the exact ordered assertion set, and publishes only after every
  device/backend pair agrees.
- **D-19:** Retain only the canonical redacted physical run contract and its digest-bound completion
  marker. Never retain the run nonce, raw route handoff, payloads, scope/account values, flags,
  endpoints, media, manifest contents, digests for private assets, `.xcresult`, screenshots, logs, or
  backend rows. Bump the closed evidence schema only when new device-origin assertions require it;
  provide exact decoder/fixture migration and reject partial or reordered reports.
- **D-20:** Extend the Phase 158 repository classifier narrowly: recognize the exact approved physical
  evidence completion-marker class as scannable durable metadata, and recognize the exact approved
  reference-host AIFF resource class as an excluded binary/host fixture. Do not treat AIFF as evidence,
  broaden generic binary acceptance, or turn unknown paths into optimistic exclusions. Every other
  unclassified path still fails closed.

### Closure, proof, and developer experience

- **D-21:** Give a host maintainer one composition path and one final proof command: sanitized handoff
  validation -> topology/manifest compilation -> shell/pack/replay preflight -> physical cases ->
  independent backend checks -> redacted evidence join. Every blocked result names a stable rule and
  host-owned remediation without echoing rejected input.
- **D-22:** Define explicit Phase 163.1 gap requirements from the milestone audit and update ROADMAP,
  REQUIREMENTS, STATE, route-policy/support truth, and generated guide renderings together. Existing
  36/36 phase-local requirement evidence does not close these cross-phase gaps.
- **D-23:** Completion requires fresh automated tests for the composed target, a source-bound physical
  run against validated adopter input, privacy/adoption-context scans, the outstanding Nyquist
  validations identified by the audit, and a fresh `$gsd-audit-milestone`. Simulator/reference-fixture
  results remain advisory and cannot substitute for the adopter-bound device run.

### the agent's Discretion

The user delegated a coherent expert recommendation after multi-agent research. Planning may choose
safe type/module/task names, host-private handoff encoding, fixture-control endpoint shape, run/case
identifiers, accessibility identifiers, evidence schema version, and exact test partitioning. It may
not weaken the two-tier promotion gate, introduce a second route/pack/navigation authority, expose
proof controls to learners, let backend-only producers satisfy device assertions, retain sensitive
data, broaden the artifact classifier optimistically, add Android work, or generalize navigation,
sync, storage, conflict resolution, or evidence infrastructure.

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets

- `RouteInventory` and `NavigationTopology`: already provide the pure, closed two-stage eligibility
  boundary; Phase 163.1 needs to compose them into every physical promotion invocation.
- `NavigationShellView`, `NavigationCoordinator`, and the iOS shell host: already implement the
  required UIKit/SwiftUI boundary, retained native stacks, typed transitions, and host leaf factory.
- `PackProvider` and `PackStore`: already implement the narrow host provider, closed states, fresh
  reconciliation, rollback, and revocation semantics; the physical host should consume them.
- Generated proof/XCTest/XCUITest and Phoenix replay lanes: already supply host-owned automation,
  endpoint authority, Ecto idempotency, and closed report plumbing.
- `FirstAdopterContext` and `Evidence`: already enforce fail-closed artifact routing and exact redacted
  publication; extend their allowlists narrowly rather than introducing a new evidence system.

### Established Patterns

- Pure closed validators feed side-effecting orchestration; unknown input blocks without echoing data.
- Phoenix/Plug derives live authority per request; Ecto constrains scoped idempotency and commits one
  accepted event with its domain effect atomically.
- Native shell state owns ephemeral navigation but never session, route, replay, or credential
  authority.
- XCTest/XCUITest owns device-local and observable behavior; Phoenix independently proves backend
  invariants; promotion requires both.
- Host presentation and provider details remain host-owned while Crosswake owns semantic contracts,
  compatibility, denials, and proof shape.

### Integration Points

- Replace the physical app branch at the composition root, not by decorating the standalone proof view.
- Feed validated handoff rows into manifest/topology compilation and physical preflight without a
  second Swift configuration source.
- Convert the private learning installer into a host `PackProvider` and inject it into `PackStore`.
- Add run-scoped device cases and endpoint-level fixture preparation; convert backend producers into
  independent verifiers of device-created state.
- Version and extend the closed physical report/evidence join, then classify only the exact new marker
  and reference media paths needed by the proof.

</code_context>

<specifics>
## Specific Ideas

- The user asked for one coherent, research-backed recommendation across architecture, Phoenix/Ecto/
  Plug idioms, successful hybrid/offline systems, DX, DevOps/SRE, privacy, JTBD, accessibility, and
  visual design, with decisions delegated to the agent.
- Follow the useful lessons from Hotwire Native: native containers and stack state are real, leaf web
  state should survive tab changes, and native/web coordination must be narrow. Do not copy URL/browser
  history as route authority.
- Follow Ecto's database-constraint and transaction model rather than race-prone uniqueness prechecks.
  Follow PouchDB's honesty about conflicts without copying automatic winner selection or generic
  replication. WatermelonDB's broad sync surface is evidence for keeping this phase narrow.
- Consumer JTBD: a learner can enter the correct study route, trust that required content is genuinely
  ready, save work without connectivity, understand whether it is local/accepted/needs attention, and
  return or change account without losing or leaking work. A host maintainer gets one explicit
  composition/proof path with actionable non-echoing denials.

</specifics>
