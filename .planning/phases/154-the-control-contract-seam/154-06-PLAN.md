<objective>
Ship the client half of the `crosswake.bridge` protocol and close the iOS reply return leg, then
give adopters the two surfaces that make wiring it survivable: a generator that refuses and teaches,
and an installer that patches what is canonical.

The hook's single most important job is not transport — it is synthesizing the unreachable fact
when there is no shell. That is why it is library-owned rather than generated into the host: the
project's own package-design rule says use generators when adopters need editable app code, and
keep security-sensitive or protocol-sensitive behavior library-owned. The no-component-tier
anti-feature governs PRESENTATION — things adopters restyle. This file is the client half of a
versioned wire protocol whose one job is deciding whether a denial gets synthesized (D-31).
Generating a host-owned copy would mean silent protocol drift on the exact file that decides
whether the fail-closed contract holds.

The iOS return leg does not exist today and must be built here (D-02). Android is already duplex;
iOS hands the reply to a Swift closure that the example host constructs as a no-op, and nothing
ever evaluates JavaScript back into the WebView — the message-handler API is send-only by design.
This plan writes the leg and proves it with Swift unit tests and committed vectors. It reaches
adopters with the Phase 156 native release, which needs the mirror anyway; the support matrix must
say so rather than claim completeness (D-03).

This is D-76's **PR #2**, client and native half. Still no showcase changes — the example host's
endpoint, layout, and LiveViews are Plan 07.

Output: `priv/static/crosswake.esm.js`, a private dependency-free repo-root manifest, the iOS
return leg with vectors, `mix crosswake.gen.bridge_hook`, an endpoint-patching installer, a doctor
wiring check, and three updated guides.
</objective>

**Path decision closing RESEARCH.md Assumptions Log A2.** D-30's literal path
`priv/static/crosswake.esm.js` WINS over nesting it beside the two existing files in
`priv/static/crosswake/`. Rationale: the endpoint mounts it as a fourth static plug at the
`/crosswake` prefix from the `:crosswake` app, exactly mirroring the existing `phoenix` and
`phoenix_live_view` blocks, which yields the clean URL `/crosswake/crosswake.esm.js`. Nesting would
yield a doubled path segment. The three things that must stay consistent in one change are: the
file's location under `priv/static/`, the endpoint's static plug, and the layout's import path.

**No `mix.exs` edits are required by this plan.** RESEARCH.md §11 verified the docs
`groups_for_modules` regex already matches any new module under the `Crosswake.Bridge` namespace,
and the hex `files:` allowlist already contains `priv`. The repo-root manifest is deliberately NOT
added to that allowlist — it is a development-time resolution aid and a node test script, never part
of the published package.

**Rejected outright, with reasons to keep on record.** Generating the hook into the host is
rejected twice over: once on the protocol-sensitivity rule above, and once because the reference
host has NO bundler at all — its endpoint serves dependency JavaScript through static plugs and its
layout imports from a bare module script tag, so a generator writing into an assets directory would
write into a directory nothing builds (D-32). Shell injection of the hook logic is rejected as
definitionally fatal (D-34): the hook must run when there is no shell, and it would also put the
fastest-moving half of the contract behind the slowest release train. Steal exactly one piece — both
shells already inject the capabilities and thread-id facts at document start; keep that and have the
hook read it.
