<objective>
Harden the tracer's correlation path into the exactly-once, bounded-time machinery the seam
promises: an opaque adopter-facing `ref`, a per-mount epoch, a three-layer compare-and-delete,
`resolve/2` for the fallback race, two timers, the telemetry catalog entries, and the test helper
without which nobody — including this project's own tests — can simulate a hook reply.

Everything here is expansion of the slice Plan 03 proved end-to-end. The delivery shape is already
settled and tested; this plan makes it survive concurrency, reconnects, races with on-page
fallbacks, and a hook element that gets patched away mid-flight.

This is D-76's **PR #2**, second half: still unit-tested only, still no showcase changes.

Purpose: D-23's argument is that exactly-once must be structural rather than conventional.
Anything failing a layer is dropped before adopter code runs, with telemetry, so a subtle
double-delivery becomes an observable counter instead of a duplicated side effect in production.

Output: `resolve/2`, the epoch and in-flight machinery, both timers, five telemetry events in the
existing catalog, and `Crosswake.Bridge.Test`.
</objective>

**Forward-compatibility note to record, not to solve here (D-29).** Both native shells type the
bridge payload as a string-to-string map, so Phase 156's menu actions list literally cannot fit.
That is a wire-only protocol-version bump in 156 — not an adopter-API break, because the
capability handshake already routes old natives to the unavailable-capability denial, and 156 is
native-rebuild-required regardless. Neither the milestone ground-truth document nor the API design
document notices this. Record it in the `Crosswake.Bridge` moduledoc so Phase 156 is not surprised
by it; do NOT pre-solve it here.

**Rejected alternative to keep rejected (D-19).** Per-call reply-to event names are not an option.
Hotwire Native correlates by event name and its message-retrieval API returns only the LAST message
of that name — provably broken for N-in-flight. It also makes the event namespace unbounded and
stringly typed, and prevents Crosswake from intercepting an unknown name, which would forfeit
dedupe, timeout, and telemetry — the entire fail-closed story.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser client → in-flight correlation table | The correlation id is the capability token for delivering a reply; anything that can guess or replay one can deliver an answer. |
| LiveView process → telemetry backend | Telemetry metadata escapes the process and is retained; anything unbounded admitted here becomes an unbounded cardinality and a data-retention surface. |
| on-page fallback UI → native reply path | Two independent answer sources race for one ask. |

## STRIDE Threat Register

ASVS L1; blocking threshold `high`. V4 and V5 apply per RESEARCH.md's Security Domain.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-154-13 | Spoofing | correlation id replay across a reconnect | high | mitigate | The per-mount epoch is embedded in the correlation id and minted fresh at `attach/1`, so a pre-reconnect reply cannot deliver into the new mount. Asserted by the foreign-epoch behavior in Task 1. |
| T-154-14 | Tampering | duplicate reply delivery | high | mitigate | The three-layer compare-and-delete makes exactly-once structural: the second delivery for a correlation id finds the ask gone and drops with a telemetry event, so a duplicate side effect becomes an observable counter rather than a silent double mutation (D-23). |
| T-154-15 | Repudiation | double-answer race between fallback UI and native reply | high | mitigate | `resolve/2` is an atomic compare-and-delete on a serialized LiveView process; whichever answer arrives first wins and the other finds nothing to resolve. The rejected API-design alternative — routing both into one event name — is explicitly not implemented (D-25). |
| T-154-16 | Information Disclosure | telemetry metadata cardinality | medium | mitigate | The adopter `ref` never enters telemetry, and the reply event's denial-reason metadata is the bounded 14-atom vocabulary rather than a free string, so neither adopter identifiers nor unbounded native strings reach the metrics backend (D-20). |
| T-154-17 | Denial of Service | unbounded in-flight table growth | medium | mitigate | Every ask carries a server backstop timer at the requested timeout plus two seconds; the unbounded-timeout option is opt-in per call and documented as being for human-in-the-loop controls only, so the default path always reclaims its entry. |
| T-154-SC | Tampering | npm/pip/cargo installs | low | accept | No package-manager install task in this plan; zero new external packages this phase per RESEARCH.md's Package Legitimacy Audit. |
