<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| compiled manifest -> inspection document | Route/runtime/auth/commerce/notification truth crosses from manifest/support modules into a new operator contract and can drift if duplicated. |
| canonical route entries -> indexes/findings/conditions | Derived views can become a second authority if they are built independently of `routes`. |
| typed inspection structs -> JSON contract | Serialization can blur support status, severity, or deferred-claim posture if it rewrites canonical axes into prose or lossy booleans. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-49-01 | Tampering | `lib/crosswake/operator_inspection.ex` route/index builder | mitigate | Build `summary`, `indexes`, `findings`, and `conditions` only from canonical `routes` and lock that relationship in `operator_inspection_test.exs`. |
| T-49-02 | Repudiation | `lib/crosswake/operator_inspection/json_formatter.ex` | mitigate | Serialize `support.status`, finding `severity`, proof class, and rebuild posture as separate fields and assert the separation in `json_formatter_test.exs`. |
| T-49-03 | Information Disclosure | auth/notification/provider readiness fields | mitigate | Mark auth as contract-only and notification as provider-snapshot-only; encode provider adapter posture as deferred or verification-required and assert non-claims in focused tests. |
| T-49-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs or new dependencies are allowed in this plan. |
</threat_model>
