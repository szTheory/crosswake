<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| inspection document -> human formatter | Human rendering can accidentally become the de facto API or hide critical caveats if it collapses raw axes. |
| CLI argv -> operator inspection task | Invalid router names or unsupported formats can silently mislead operators unless the task fails closed. |
| valid inspection output -> CI/support consumption | If the task raises after rendering blocking truth, automation loses the very machine-readable payload OPER-02 requires. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-49-04 | Tampering | `lib/crosswake/operator_inspection/formatter.ex` | mitigate | Keep human output concise but route-centric, preserve raw support/proof/rebuild/auth/notification axes, and lock non-API formatting expectations in `formatter_test.exs`. |
| T-49-05 | Input Validation | `lib/mix/tasks/crosswake.inspect.ex` | mitigate | Reuse strict `OptionParser` parsing plus `router_module!/1` and explicit `unsupported format` errors so invalid CLI input fails closed. |
| T-49-02 | Repudiation | task success/failure semantics | mitigate | Keep valid human/JSON output consumable even when routes are blocking; reserve `Mix.raise` for invalid input or construction failures and assert the distinction in `crosswake_inspect_test.exs`. |
| T-49-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs or new dependencies are allowed in this plan. |
</threat_model>
