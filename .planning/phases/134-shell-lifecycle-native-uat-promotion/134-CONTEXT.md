# Phase 134: Shell Lifecycle + Native UAT Promotion - Context

**Gathered:** 2026-06-28
**Status:** Ready for planning
**Method:** Research-then-recommend — 3 parallel research agents (versioning/drift, CLI status+diff UX, Android UAT promotion); decisions synthesized into one coherent, cross-checked set and locked by the maintainer.

<domain>
## Phase Boundary

Give hosts a **safe upgrade path** for generated native shells. Today `mix crosswake.gen.shell`
generates iOS (7 templates) + Android (11 templates) but stamps nothing into the output, has no way
to tell a host their shell is stale, and the `gen.shell.ex:254` "patch-or-doc guidance" line is a
dangling placeholder. Five requirements (LIFE-01a/b, LIFE-02a/b/c):

1. **LIFE-02a** — generated shells carry a `@template_version` stamp + the producing `crosswake`
   version; a drift test fails if templates change without a version bump.
2. **LIFE-02b** — `mix crosswake.shell.status` reports up-to-date / N-behind; `mix crosswake.gen.shell --diff`
   prints a non-destructive unified diff (never overwrites host files).
3. **LIFE-02c** — `guides/native_shell_upgrade.md`: per-template-version changelog referencing
   `RuntimeLine.RebuildPolicy.classify/2`; replace the dangling `gen.shell.ex` placeholder with a real pointer.
4. **LIFE-01a** — the hermetic Android **JVM generated-shell** UAT lane becomes merge-blocking.
5. **LIFE-01b** — iOS simulator/device UAT stays advisory, honestly labeled in `guides/support_matrix.md`.

**Not in scope:** iOS becoming merge-blocking (macOS/Xcode CI is flaky — stays advisory); Android
**device/emulator** verification (`shell.android.device_verified` is Phase 67/68, deferred); the
DRY_RUN=0 admin required-check **registration** (stays an admin gate, coherent with Phase 135/PROOF-03);
a 3-way interactive merge/upgrade engine (we ship status + read-only diff + a changelog, NOT an
auto-patcher — host files are host-owned).
</domain>

<decisions>
## Implementation Decisions

> All decisions are HOW-to-implement choices within the fixed phase boundary, grounded in the actual
> codebase + ecosystem evidence (copier, igniter, gradle-wrapper, kubebuilder, sqlc/protoc, terraform,
> kubectl, hex.outdated, npm/rustup footguns). Three cross-area reconciliations and one correctness
> catch are called out in `<cross_area_reconciliations>` below.

### Template versioning & stamp (LIFE-02a) — Area 1 (keystone)
- **D-01:** **Whole-set single `@template_version`, a monotonic INTEGER epoch** (1, 2, 3…),
  **decoupled from the `crosswake` library SemVer.** The ~20 template files are one conceptual
  artifact (the shell), not 20 independent deliverables. Per-file or per-platform versioning was
  rejected: it explodes the changelog/status/diff into multi-clock complexity for false precision
  (most changes are cross-cutting structural ones). Precedent: gradle-wrapper single version,
  kubebuilder single `layout` version. **The integer is deliberately NOT the library version** —
  see D-01 rationale in `<cross_area_reconciliations>` (avoids the crying-wolf "behind" alarm).
- **D-02:** Provenance is recorded **in BOTH places**: (a) a `.crosswake/shell.json` **manifest**
  (machine contract — what `shell.status`/`--diff` parse), AND (b) a **2-line comment header** in each
  comment-supporting generated file (human context in-editor + a cross-check that defends against a
  hand-edited manifest). Comment shape:
  `// Generated by crosswake <ver> (template_version: <N>)` + `// Host-owned after generation. See guides/native_shell_upgrade.md`.
  Per-platform comment syntax: Swift/Kotlin/Groovy `//`, properties `#`, XML/plist `<!-- … -->`
  **after** the `<?xml …?>` declaration. **NO stamp** in `CrosswakeShell.xcodeproj/project.pbxproj`
  (Xcode auto-manages it — foreign comments are a footgun) or `gradlew`/`gradlew.bat` (shell-parse
  risk, rarely read). **Never** a "DO NOT EDIT" header — it contradicts the documented host-owned
  contract in `guides/native_shell.md`.
- **D-03:** `.crosswake/shell.json` lives at the **native project root** (e.g.
  `<target>/.crosswake/shell.json`) and contains: `crosswake_version`, `template_version` (int),
  `platform`, `generated_at`, and a copier-style `params` block capturing the generation switches
  (`router`, `local`, `target`) so `--diff` can re-render with identical assigns. Include a leading
  "do-not-hand-edit — regenerate to update" comment key (copier's `.copier-answers.yml` discipline).
  Written with **`File.write!/2`** (always overwrite on regeneration), NOT the existing `ensure_file/2`
  (which skips when present — would leave a stale manifest). The manifest must NOT be gitignored.
- **D-04:** Drift test `test/crosswake/proof/phase134_template_version_drift_test.exs`:
  a **checked-in content-hash** (SHA-256 of all `.eex` templates concatenated in sorted path order)
  vs the live hash; fail with `ProofAssertions.stable_id_message/7` `:merge_blocking` if they differ
  (i.e. a template changed but `@template_version` was not bumped). Mirrors the Phase 132 COMPAT-03
  drift pattern + a **non-vacuity guard** (≥1 iOS AND ≥1 Android template present). **Hermetic
  filesystem hash, NOT git-based** — git-based would break in the project's worktree-isolation
  workflow (the known worktree-base divergence) and in shallow clones.
- **D-05:** Ship `mix crosswake.bump_template_version` (maintainer task): increments the integer AND
  recomputes/rewrites the manifest hash in the drift test — one command for the bump ceremony, so the
  "remember to bump" step can't be silently forgotten.

### Upgrade changelog (LIFE-02c) — Area derived from versioning research
- **D-06:** `guides/native_shell_upgrade.md` = **per-template-version sections, newest-first.** Each
  entry **leads with the RebuildPolicy verdict** (`ota_safe` / `{:rebuild_required, :native_shell|:companion_shell}`)
  + the named change-class atoms, then: *What changed* → *Should you rebuild?* (quoting the actual
  `RebuildPolicy.classify/2` call + return) → *Files changed in this template version*. Most-urgent
  question (rebuild?) gets top position (calm/explicit — BRAND-SPEC voice). Even OTA-safe entries
  document what changed (host files are host-owned, so every upgrade is elective).
- **D-07:** Replace the dangling `lib/mix/tasks/crosswake.gen.shell.ex:254` "patch-or-doc guidance"
  placeholder with a real pointer to `guides/native_shell_upgrade.md` (closes LIFE-02c's named gap).
- **D-08:** The changelog verdict is **derived from `RebuildPolicy` change-class vocabulary**, not free
  prose: at bump time the maintainer declares which change-classes apply; the verdict follows from the
  policy module ("derive, don't duplicate" — `RebuildPolicy`'s own moduledoc principle).

### `mix crosswake.shell.status` (LIFE-02b) — Area 2
- **D-09:** Locates the shell via `.crosswake/shell.json`. No-arg checks **both** platform manifests
  relative to cwd at the default `gen.shell` rooting; `--target PATH` overrides. Reports per platform
  (one, both, or neither present). Matches `gen.shell`'s existing `--target`/`--local` rooting and
  copier's zero-arg `copier update` (reads the answers file, no re-passing).
- **D-10:** **"N behind" = integer epoch delta** (`current @template_version − stamped`), surfaced
  **together with the highest-severity RebuildPolicy verdict spanned** by those versions
  (e.g. "2 template versions behind — includes a rebuild-required change"). Shows both numbers
  (stamped → current), `hex.outdated`-style, so severity is never a bare ambiguous integer.
- **D-11:** Output = `[crosswake]` log prefix + **calm prose** (a single shell project does not warrant
  a multi-row table) + a **`--format json`** flag for scripts/CI, reusing `crosswake.doctor`'s
  JSONFormatter. Concrete states designed: up-to-date, N-behind, not-a-shell, mixed (both generated,
  one behind). Microcopy is calm/specific/actionable per BRAND-SPEC §6.
- **D-12:** **Exit codes: `0` = up-to-date (and not-a-shell — don't break a non-adopter's CI), `2` =
  at least one shell behind, `1` = error** (bad/unreadable manifest). Follows the
  `terraform plan -detailed-exitcode` / `copier check-update` / `kubectl diff` convention; deliberately
  separates "behind" (2) from "broken" (1) to avoid the npm/rustup "exit-1-means-outdated" backlash
  that breaks JSON pipelines. (`--require-shell` strict mode can be added later if a host wants it.)

### `mix crosswake.gen.shell --diff` (LIFE-02b) — Area 3
- **D-13:** Diffs **on-disk generated files vs templates freshly re-rendered IN-MEMORY** (the only
  honest diff — mirrors `terraform plan` / `kubectl diff`: compute desired state, compare, never apply).
  **Non-destructive is enforced structurally** — the diff path branches before any write call (Igniter
  `do_or_dry_run` pattern), so "never writes" is a code guarantee, not a convention. Print a trust
  banner: `[crosswake] diff — read-only, no files changed`.
- **D-14:** Spurious-diff avoidance = **re-render using the manifest's saved `params`** (copier's
  `.copier-answers.yml` re-render mechanism) so app name / bundle id / router / version assigns match
  exactly and don't show as noise. Rejected structural-ignore (a genuinely-changed bundle id is signal,
  not noise). Pre-manifest shells: accept a one-time `--router` override + offer to write the manifest
  after a successful diff. If `params.local == true` and the local package path no longer resolves:
  **explicit warn + fall back to the Hex package — never silently fail.**
- **D-15:** Output = **unified diff** (git-style, pipeable/greppable/patchable), per-file header +
  **per-file RebuildPolicy verdict annotation**, summary stats (ota-safe / rebuild-required / unchanged
  counts), colorized on a TTY. **Exclude `CrosswakeShell.xcodeproj/project.pbxproj`** from diff output
  (Xcode-managed UUIDs/build-settings always diverge → constant noise). Build the unified diff from
  stdlib **`List.myers_difference/2`** on lines — no external diff dependency needed.
- **D-16:** **CORRECTNESS CATCH — do NOT route file diffs through `RebuildPolicy.diff/2`.** That function
  diffs two capability **`Root.t()` manifests**, not files (`rebuild_policy.ex:145-151`). For per-file
  annotation use a small **file→change-class lookup** (`Info.plist`/`AndroidManifest.xml`/`app/build.gradle`/
  entitlements → `:rebuild_required`; coordinator/viewmodel `.swift`/`.kt` → `:ota_safe`) that **reuses
  `RebuildPolicy`'s verdict vocabulary** for consistency. The annotation is **advisory** — `classify/2`
  is documented as "tooling/doctor input, NOT a release-gate oracle."

### Android JVM UAT promotion + iOS advisory (LIFE-01a/01b) — Area 4
- **D-17:** Add a **NEW dedicated hermetic job `android-generated-shell-unit`** to
  `.github/workflows/native-behavioral-proof-gate.yml`, wrapping `script/verify_generated_android_shell.sh`
  with **`RUN_CONNECTED_TESTS=0`** (JVM-only; the script's emulator branches are bypassed). **Do NOT
  extend the existing `android-package-unit` job** — that tests the *package/library*, not a *generated
  shell*; conflating them would make the `shell.android.jvm_hermetic` claim dishonest. The runner needs
  **`erlef/setup-beam`** (Elixir, because the script calls `mix crosswake.gen.shell`) **and**
  `actions/setup-java` Temurin 17 (satisfies the script's `JAVA_HOME` check, skips its slow self-install).
- **D-18:** Wire it into the existing `merge-blocking-native-behavioral-proof` aggregator by adding it to
  `needs:` (`[android-package-unit, android-generated-shell-unit]`); keep `if: always()` and the
  `re-actors/alls-green` rollup unchanged.
- **D-19:** **Required-check registration is DEFERRED — fully coherent with Phase 135/PROOF-03.** The
  aggregator `merge-blocking-native-behavioral-proof` is **already the registered required check**, so
  fanning the new lane into its `needs:` propagates merge-blocking with **zero new registration**. No
  Phase 134 call to `register_required_checks.sh`; `check_required_checks_registered.sh` /
  `list_merge_blocking_checks.py` stay green unchanged (they match only the aggregator's
  "merge-blocking"-named job). The admin gate is untouched; Phase 135's model is not re-litigated.
- **D-20:** **iOS stays advisory.** Honest `guides/support_matrix.md` labels: Android shell row →
  `merge-blocking proof (JVM hermetic)` with the verbatim legend caveat **"JVM hermetic proof is not
  emulator evidence or physical-device proof"**; iOS shell row keeps `verification required` + an
  explicit note: **"advisory — not wired as a required CI lane; macOS/Xcode toolchain not guaranteed in
  CI."** No "iOS supported/verified in CI" over-promises. (iOS row = docs-only change per the support
  matrix Change-Classes table — no proof-gate wiring.)
- **D-21:** The plan MUST encode these aggregator footguns: (1) **skipped == success** — never remove
  `if: always()`, or a red dependency would let a PR merge; (2) the runner needs Elixir setup (easy to
  miss behind the more-visible JDK dependency); (3) **register ONLY the aggregator**, never the
  individual lane jobs (two required-check registrations + independent flake-blocking otherwise);
  (4) verify `alls-green` sees BOTH jobs in the `toJSON(needs)` input on the first run.

<cross_area_reconciliations>
## Cross-Area Reconciliations (where the research agents' assumptions met)

1. **Integer epoch vs library SemVer (D-01).** The versioning agent recommended a standalone integer;
   the CLI agent initially modeled `template_version` == `crosswake_version`. **Resolved to the integer
   epoch.** If the stamp tracked library SemVer, every `crosswake` release would report shells "behind"
   even when no template changed — the exact npm/rustup "crying-wolf" footgun the CLI agent documented.
   The integer bumps **only** when templates actually change (enforced by the D-04 drift test).

2. **One manifest design (D-02/D-03).** Versioning agent proposed `.crosswake/shell.json`; CLI agent
   proposed a copier-style answers file. **Merged:** `.crosswake/shell.json` carries BOTH provenance
   (crosswake_version, template_version, platform, generated_at) AND the copier-style `params` block,
   and we keep the in-file comment stamp as a cross-check. Single source of truth for status + diff.

3. **Exit codes (D-12).** CLI agent's research forced the refinement from "exit 1 when behind" to
   "exit 2 when behind, 1 for errors" (terraform/copier/kubectl `--detailed-exitcode` precedent).

4. **CORRECTNESS CATCH (D-16).** `RebuildPolicy.diff/2` diffs capability manifests, not files — so the
   `--diff` verdict annotation uses a file→change-class lookup reusing the verdict *vocabulary*, and is
   advisory only.

5. **`shell.status` is host-facing, not an in-repo CI gate.** It runs in an *adopter's* project; the
   only NEW merge-blocking lane in the Crosswake repo is the D-17 Android job. The D-04 drift test is
   the in-repo gate for the version-bump discipline. (The CLI agent's "gate CI on major staleness only"
   note is guidance we can document for adopters, not an in-repo requirement.)
</cross_area_reconciliations>
