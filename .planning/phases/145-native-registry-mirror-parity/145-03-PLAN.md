## Trust Boundaries

| Boundary | Description |
|---|---|
| Workflow inputs -> backfill script | Operator-provided version/ref/apply flags enter shell and can influence Git refs. |
| Git refs -> mirror repository | Script verifies release refs and writes `refs/tags/v${VERSION}` only in apply mode. |
| Public registries -> mutation decision | Hex and Maven live-state probes gate iOS mirror mutation. |
| Backfill docs -> maintainer action | Runbook guidance must avoid unsafe registry re-entry and public tag movement. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|---|---|---|---|---|
| T-145-11 | Tampering | `--ref` input | mitigate | Reject mutable refs and require Release Please component tag refs or full exact refs; default to `refs/tags/ios-core-v0.2.0`. |
| T-145-12 | Tampering / Repudiation | public SwiftPM `v0.2.0` tag | mitigate | Exact tag identity is OK; mismatch fails closed and requires a deliberate maintainer decision. |
| T-145-13 | Denial of Service | immutable registry recovery | mitigate | Verify Hex and Maven already-live state before mutating only the missing SwiftPM mirror tag; docs do not route operators through full release reruns. |
| T-145-14 | Information Disclosure | mirror token and registry details | mitigate | Happy-path output excludes token mechanics and raw registry JSON; failure output names actionable package/version/ref/state facts. |
| T-145-15 | Elevation of Privilege | apply-mode workflow | mitigate | `MIRROR_PUSH_TOKEN` is required only for apply-mode mutation and must be mirror-repo scoped with Contents:write. |
| T-145-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install task is planned; no package legitimacy gate required. |
</threat_model>
