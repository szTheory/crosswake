<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Operator input to Git checkout | Manual workflow input controls which ref is checked out. |
| Checked-out source to Hex helper | Recovery source identity crosses into publish authority. |
| GitHub Actions secret env to helper | `HEX_API_KEY` enables registry mutation. |
| Recovery logs to operator | Logs must guide safe recovery without leaking secrets or implying native recovery coverage. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-143-07 | Tampering | `inputs.ref` | mitigate | Reject branch-shaped refs before checkout and accept only tag-like release refs or full SHAs per D-13. |
| T-143-08 | Spoofing | `inputs.package` | mitigate | Use a finite choice list for the six Hex packages and let the helper package map reject unknown identities per D-11 and D-15. |
| T-143-09 | Repudiation | recovery logs | mitigate | Print checked-out SHA, package, version, and helper state with `[crosswake]` prefix per D-10 and D-27. |
| T-143-10 | Information Disclosure | `HEX_API_KEY` | mitigate | Pass secret only through env to the helper; workflow copy and logs never echo secret values. |
| T-143-11 | Elevation of Privilege | manual workflow permissions | mitigate | Use `contents: read`; recovery publishes to Hex only via existing secret and does not push repository state. |
| T-143-12 | Tampering | native registry recovery scope | mitigate | Do not add SwiftPM/Maven recovery or mirror backfill in this workflow; keep those semantics separate per D-12 and D-34. |
| T-143-SC | Tampering | package-manager installs | accept | No npm/pip/cargo package install tasks are introduced; workflow uses existing GitHub Actions, Mix, and Plan 01 helper. |
</threat_model>
