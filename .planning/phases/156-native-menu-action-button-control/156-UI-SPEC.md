# Phase 156 - UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope reminder:** Phase 156 ships `action_menu` as the first genuinely-new native control on the
Phase 154 request/reply seam. The visible trigger remains Phoenix-owned, the Phase 155 fallback
remains complete and host-owned, and native presentation is a platform-owned enhancement over the
same runtime action projection. This phase does not create shell-owned toolbar chrome, native
confirmation, a component library, rendered icons, multiple named menus, or mutation authority in
native code.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none - this is a Phoenix/Elixir and native-package phase; shadcn/React tooling does not apply |
| Preset | not applicable |
| Component library | Existing generated, host-owned `Phoenix.Component` fallback (`CrosswakeFallbacks.action_menu/1`) plus platform-native UIKit/Android presenters; no importable Crosswake UI tier |
| Icon library | none - `icon` remains reserved and must be `nil`; labels carry the visible and spoken action meaning |
| Font | Fallback uses `--cw-font-display` for headings and `--cw-font-body` for trigger/buttons/rows; native surfaces use the platform system font, Dynamic Type/font scaling, and OS menu chrome |

**Existing design-system state:** no `components.json`, Tailwind config, or shadcn registry surface
was detected. The inherited design source is Crosswake's brand token system:
`brandbook/tokens/crosswake.tokens.json` -> `brandbook/tokens/tokens.css` ->
`priv/static/crosswake/tokens.css`, plus the generated fallback CSS in
`priv/templates/crosswake/native_controls_ui/crosswake_fallback.css.eex`.

**Equivalent safety gate:** registry vetting is not applicable. The project-level UI safety guard
is structural: generated host-owned components may live in templates/example output, but no
importable `Crosswake.UI.*` component tier may appear under `lib/`.

## Spacing Scale

Declared values (multiples of 4, inherited from `--cw-spacing-base: 4px` and Phase 155):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Destructive-row separation band and tight inline offsets |
| sm | 8px | Menu row gaps and compact inline spacing |
| md | 16px | Trigger/fallback outer padding and menu row horizontal padding |
| lg | 24px | Fallback panel padding and body-to-actions spacing |
| xl | 32px | Wide layout gaps around the existing AdminPilot panel, not inside native chrome |
| 2xl | 48px | Minimum interactive target for Phoenix trigger, fallback rows, Cancel, and action buttons |
| 3xl | 64px | Page-level spacing only; do not introduce it inside the menu control |

Exceptions: native iOS and Android menu internals follow platform metrics. The Crosswake contract
controls semantic structure, anchor validity, item order, and outcomes, not OS row pixel heights.

## Typography

Exactly three text sizes and two weights are declared for the Phoenix/fallback surface. Native
presenters use platform typography and user text scaling.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`--cw-text-scale-md`) | 400 | 1.5 (`--cw-line-height-md` 24px) |
| Label | 14px (`--cw-text-scale-sm`) | 600 | 1.43 (`--cw-line-height-sm` 20px) |
| Heading | 20px (`--cw-text-scale-xl`) | 600 | 1.5 (`--cw-line-height-xl` 30px) |
| Display | not used | not used | not used |

Use Body 16px/600 for the Phoenix-owned trigger label and primary/destructive buttons. Use Label
14px/600 only for disabled explanatory rows, inline fail-closed alerts, and empty state copy.
Do not truncate row labels; wrap them and let the row grow.

## Color

The fallback color contract is inherited from Phase 155. Native presentation uses platform system
appearance while preserving destructive semantics where the platform exposes them.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--cw-surface-inset` | Fallback panel background; must remain inset, not raised |
| Secondary (30%) | `--cw-overlay-scrim` | Full-viewport fallback backdrop only |
| Accent (10%) | `--cw-action-bg` and `--cw-action-focus-ring` | Phoenix trigger/primary button background, focus-visible rings, and the 2px wake-seam rule only |
| Destructive | `--cw-status-error` with `--cw-status-error-fg` | Destructive confirm button and destructive menu-row left bar; color must be accompanied by shape/position |

Accent reserved for: the Phoenix-owned action trigger if styled as the primary action, neutral
confirm/action button backgrounds, focus-visible outlines, and the wake-seam rule. Do not color
ordinary menu rows, disabled rows, or secondary buttons with the accent.

**Native treatment:** iOS uses the native destructive action treatment in
`UIAlertController.Style.actionSheet` when available. Android `PopupMenu` may not expose equal
destructive styling; Crosswake must not simulate parity with custom color hacks. Phoenix still
routes destructive selection through the generated destructive confirm before mutation.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Job actions` for the AdminPilot exemplar; generic generated docs may use `Actions` or `More actions` |
| Native/fallback menu heading | `Choose an action` |
| Empty state heading | not separate; render the normal menu heading |
| Empty state body | `No actions are available for this record.` |
| Disabled row example | `Reassign job — needs a supervisor` |
| Fail-closed: stale binary | `This action needs a newer version of the app. Update the app, then try again.` |
| Fail-closed: undeclared/unavailable here | `This action isn't available here. Nothing was changed.` |
| Shell unreachable | No end-user error copy; the already-rendered fallback remains usable |
| Native dismissed outcome | No toast, alert, or status copy; close the fallback/menu with no mutation |
| Neutral selected outcome | Product-specific status copy only after Phoenix reauthorizes and applies the action; AdminPilot example: `Flagged for review.` |
| Destructive selected outcome | Open the existing destructive confirm first; confirm copy remains `Delete this job?` / `This removes the job and its 3 photos. It cannot be undone.` / `Delete job` |

Hard copy rules:

- End-user copy must not mention bridge, shell, capability, route policy, manifest, hook, push,
  reply, denial, protocol, native enhancement, or fallback.
- Developer-facing diagnostics may name those terms, but must stay calm and actionable.
- Labels are localized in the LiveView runtime projection, not route policy.
- Native item labels and spoken names are exactly the localized `label` value.

## Interaction Contract

### Phoenix-Owned Trigger

| Property | Contract |
|----------|----------|
| Ownership | The action button is ordinary LiveView markup owned by Phoenix |
| Required id | The trigger has a stable DOM id and passes the same value as `anchor_id:` to `Crosswake.Bridge.push/3` |
| ARIA | Use `aria-expanded={@menu_open}` and `aria-controls="<menu-id>"`; do not use `aria-haspopup` unless a future phase implements the full APG menu trigger contract |
| Focus | Fallback close returns focus to the trigger; native dismissal/selection must also leave the route in a coherent focus state |
| Pending | Use trigger-level pending affordance such as `phx-disable-with`; do not add per-row spinners |

### Runtime Action Projection

| Property | Contract |
|----------|----------|
| Shape | `[%{id: String.t() | nil, label: String.t(), destructive: boolean(), icon: nil}]` |
| Item count | Maximum 8 rows total, including disabled explanatory rows. More than 8 is a loud validation failure before dispatch |
| Label length | Maximum 80 Unicode graphemes. Longer labels fail validation before dispatch; labels still wrap in fallback/native where platform permits |
| Empty list | Do not present native chrome. Keep/render the fallback empty state and resolve through a typed denial/fallback outcome |
| Disabled row | `id: nil`, present and disabled, label includes the reason inline; never silently omit it |
| Destructive row | Sort last in fallback and native presentation model; selection returns the id only and opens Phoenix-owned confirm before mutation |
| Icons | `icon` must be `nil`; native and fallback render no icons |

### Native Presentation

| Platform | Contract |
|----------|----------|
| iOS | Present `UIAlertController.Style.actionSheet`; iPhone uses the system sheet idiom, iPad requires valid popover `sourceView` and `sourceRect` derived from the explicit trigger anchor |
| Android | Present `PopupMenu` anchored through a bounded native anchor adapter/view derived from the explicit trigger rectangle |
| Placement failure | Missing, zero-size, offscreen, stale, or unmappable anchors deny before native presentation; never guess active element, center, or screen corner |
| Dismissal | iOS cancel/tap-outside and Android Back/tap-outside return exactly one `dismissed` outcome |
| Accessibility | Use native controls for roles, enabled state, focus, font scaling, contrast, and platform dismiss gestures; proof is semantic contract proof, not a claim of real VoiceOver/TalkBack speech |

### Reply and Race Behavior

| State | Contract |
|-------|----------|
| Selected | Native returns `%{"outcome" => "selected", "action_id" => id}` exactly once |
| Dismissed | Native returns `%{"outcome" => "dismissed"}` exactly once |
| Unknown/disabled id | Drop/fail closed before adopter mutation handling |
| Native wins | Close the fallback assign and handle the selected/dismissed outcome through normal `handle_info/2` |
| Fallback wins | `Bridge.resolve/2` wins the ref and the native presentation is cancelled/dismissed; late native callback is dropped with bounded telemetry |
| Denial | Leave the fallback usable; stale-binary may render update guidance, shell-unreachable renders no end-user error |

## UI Considerations

Applicable state considerations resolved: 28 covered, 2 backstop, 0 unresolved.

**Surfaces probed:** E1 Phoenix-owned trigger, E2 fallback action menu, E3 native iOS/Android menu,
E4 inline fail-closed alert, E5 destructive confirmation follow-on.

### E1 - Phoenix-Owned Trigger

| Category | Status | Resolution / Reason |
|----------|--------|---------------------|
| loading | covered | Trigger-level pending affordance only; no per-row pending state |
| error | covered | Anchor validation failure resolves as denial and leaves fallback usable |
| overflow | covered | Trigger label is short (`Job actions`, `Actions`, or `More actions`) and uses the existing 48px button contract |
| long-text | covered | Trigger copy is fixed and not data-driven |

### E2 - Fallback Action Menu

| Category | Status | Resolution / Reason |
|----------|--------|---------------------|
| empty | covered | Zero actions render `No actions are available for this record.` under the normal heading with Cancel still present |
| loading | covered | Pending disables rows and Cancel; the trigger carries pending copy |
| error | covered | Selection errors render through the inline alert or destructive confirm path, not inside a separate menu error view |
| populated | covered | Mandatory heading, list of button rows, Cancel outside scroll, no icons, destructive row last |
| partial | covered | Disabled explanatory rows remain visible with `id: nil` and reason in the label |
| overflow | covered | Scroll container remains `max-height: min(60vh, 420px)` with heading and Cancel outside it |
| zero-one-many | covered | Zero -> empty copy; one to eight -> visible rows; more than eight -> validation failure before dispatch |
| long-text | backstop | Row labels wrap and row height grows; planner must preserve a visual/browser check at 320px |

### E3 - Native iOS/Android Menu

| Category | Status | Resolution / Reason |
|----------|--------|---------------------|
| empty | covered | Empty action list does not present native chrome |
| loading | covered | No native loading state; native presentation is requested only after server projection validation |
| error | covered | Native presenter construction/anchor failure returns a typed denial before UI is shown |
| populated | covered | Native displays the same validated action projection; platform owns chrome and motion |
| partial | covered | Disabled explanatory rows are present and disabled; omission is a contract failure |
| overflow | covered | Item count ceiling of 8 keeps the menu short; platform handles row layout within native bounds |
| zero-one-many | covered | Zero denies/no native presentation; one to eight present; above eight fails validation |
| long-text | backstop | 80-grapheme ceiling plus platform text scaling must avoid clipped unreadable labels; native harness proves model, optional device evidence remains advisory |

### E4 - Inline Fail-Closed Alert

| Category | Status | Resolution / Reason |
|----------|--------|---------------------|
| error | covered | Stale-binary and undeclared/unavailable cases use fixed `role="alert"` copy from `## Copywriting Contract`; shell-unreachable renders no copy |
| overflow | covered | Alert has no fixed height and wraps in normal document flow |
| long-text | covered | Strings are fixed literals with no interpolated values |

### E5 - Destructive Confirmation Follow-On

| Category | Status | Resolution / Reason |
|----------|--------|---------------------|
| loading | covered | Existing destructive confirm pending label remains `Deleting…` |
| error | covered | Confirm failure leaves the panel open with `role="alert"` and no mutation ambiguity |
| populated | covered | `role="alertdialog"`, no click-away dismissal, initial focus on Cancel, destructive button styling plus shape cue |
| partial | covered | Destructive body is required; no missing consequence sentence |
| overflow | covered | Existing scroll-container contract keeps buttons reachable |

## Native Accessibility and Proof Contract

- VoiceOver/TalkBack semantics are required as implementation behavior: native labels, enabled
  state, destructive metadata where supported, and dismiss gestures must be represented.
- Merge-blocking proof must be hostless/vector-based: committed
  `test/fixtures/bridge_contract_vectors.json` drives Swift and Kotlin harnesses through fake
  presenters for select and dismiss callbacks.
- Source/structural checks may pin UIKit/Android presenter adapter presence, but must not claim
  final pixels, real screen-reader speech, animation quality, or simulator/device behavior.
- Optional simulator/device screenshots or accessibility recordings are advisory evidence only.
