<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fallback event -> in-flight table | Host UI competes with native reply for one terminal state. |
| Server cancellation -> browser/native | Internal correlation controls queued/open native chrome. |
| Lifecycle data -> telemetry | User-controlled menu data could leak into observability. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-156-R1 | Repudiation | duplicate terminal callbacks | high | mitigate | Atomic compare-and-delete and explicit dropped telemetry guarantee one authority. |
| T-156-R2 | Tampering | cancellation correlation | high | mitigate | Derive cancellation from server-owned in-flight state, never caller input. |
| T-156-R3 | Information Disclosure | telemetry metadata | high | mitigate | Negative tests reject all sensitive/high-cardinality menu and anchor values. |
| T-156-R4 | Denial of Service | queued stale presentations | medium | mitigate | Cancel pending/open presentation when fallback resolves first. |

ASVS Level 1: unresolved high-severity threats block plan completion. T-156-R1 and T-156-R2 are enforced by Task 1's two race-order acceptance and ExUnit/Node command; T-156-R3 is enforced by Task 2's forbidden-metadata acceptance and telemetry contract command.
</threat_model>
