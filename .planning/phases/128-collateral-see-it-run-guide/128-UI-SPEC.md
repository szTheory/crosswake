## Context: Docs-First Phase

Phase 128 has no React/Next.js/Vite frontend. The deliverables are:

1. **Markdown documents** rendered by ExDoc (HexDocs) and GitHub (`guides/see_it_run.md`, README, `examples/QUICK_START.md`)
2. **Image collateral** committed to `brandbook/collateral/see-it-run/` and referenced via `raw.githubusercontent.com` absolute URLs
3. **Elixir test** (`test/crosswake/guides/see_it_run_test.exs`) — no visual contract needed
4. **Capture harness** (`bin/capture-collateral.sh`) — shell script, no visual contract

The design system is **Crosswake's own CSS token system** (`brandbook/tokens/tokens.css`), which governs the Phoenix web app and ExDoc theme. shadcn is not applicable.

## Spacing Scale

Markdown document rhythm follows 8-point scale mapped to standard markdown heading/block conventions. ExDoc and GitHub enforce their own inter-block spacing; these values govern authored whitespace and collateral capture dimensions.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Inline element gap (not directly authored in markdown) |
| sm | 8px | Compact block spacing |
| md | 16px | Default paragraph/block spacing |
| lg | 24px | Between major callout blocks and sections |
| xl | 32px | Between h2 sections (GitHub/ExDoc auto-spacing) |
| 2xl | 48px | Major section breaks in long guide |
| 3xl | 64px | Page-level section separation |

**Collateral capture dimensions (source: CONTEXT.md D-04, D-05):**

| Asset | Width | Notes |
|-------|-------|-------|
| Web screenshots (`web-*.png`) | 900px | 1x (non-Retina) — avoids illegible terminal text at GitHub's column width |
| iOS/Android screenshots | device-native | Cropped to ~900px width before commit |
| GIF recording (`see-it-run.gif`) | ~900px | 12fps, 10–15s, gifsicle -O3, hard cap 8MB |
| Three-runtime montage | ~900px wide | All three side-by-side, committed PNG |

Exceptions: 900px cap on all images (not a spacing multiple — derived from GitHub column rendering constraint per CONTEXT.md D-04). GIF 8MB hard cap is a file-size constraint, not spacing.

## Typography

**Rendering context:** ExDoc and GitHub Markdown both have their own typography renderers. The following contract governs authored markdown structure choices (heading levels, code fence usage) and any inline HTML used in the guide. All values are derived from `brandbook/tokens/tokens.css`.

| Role | Size | Weight | Line Height | Token |
|------|------|--------|-------------|-------|
| Body (guide prose) | 16px | 400 (regular) | 1.5 (24px) | `--cw-text-scale-md` / `--cw-line-height-md` |
| Label / caption | 14px | 400 (regular) | 1.43 (20px) | `--cw-text-scale-sm` / `--cw-line-height-sm` |
| Subheading (h3) | 18px | 600 (semibold) | 1.56 (28px) | `--cw-text-scale-lg` / `--cw-line-height-lg` |
| Section heading (h2) | 20px | 700 (bold) | 1.5 (30px) | `--cw-text-scale-xl` / `--cw-line-height-xl` |

**Markdown authoring rules derived from typography contract:**

- Use `#` (h1) for the guide title only: `# See It Run`
- Use `##` (h2) for all top-level sections: `## What You'll See`, `## Run It Now (Zero Toolchain)`, etc.
- Use `###` (h3) for sub-items within sections only
- Use fenced code blocks (triple backtick) for all commands — never inline backtick-only for multi-line commands
- Use `>` blockquote for the gameplan declaration block (D-07) and advisory-native callouts (D-06)
- Code font (JetBrains Mono) applies automatically inside fenced code blocks and inline backticks

## Color

All color values derived from `brandbook/tokens/tokens.css` (source: codebase).

| Role | Value | Token | Usage |
|------|-------|-------|-------|
| Dominant (60%) — page surface | `#F7F1E6` | `--cw-surface-default` (`--cw-primitive-foam-50`) | Guide page background (ExDoc light mode) |

**Accent reserved for:**

## Collateral Layout Contract

**Three-runtime montage (`three-runtime-montage.png`) composition:**

- Arrange three screenshot frames side-by-side horizontally
- Label each frame below the image: `Web (localhost:4700)`, `iOS Simulator (emulator evidence)`, `Android Emulator (emulator evidence)`
- Target width: ~900px total (each frame ~280px) at 1x
- Background: none or transparent (GitHub renders on white; ExDoc on foam-50)
- Tool: ImageMagick `convert +append` or equivalent (executor's discretion per CONTEXT.md discretion items)

**GIF recording (`see-it-run.gif`) scope:**

- Terminal showing `bin/see-it-run.sh` → banner output → browser auto-open
- Duration: 10–15 seconds
- Width: ~900px
- Frame rate: 12fps
- Optimization: `gifsicle -O3` before commit
- File size hard cap: 8MB (target: under 5MB)
- Native frames: may use static `three-runtime-montage.png` if capturing all three GUI windows simultaneously is impractical (executor's judgment per CONTEXT.md)

## Accessibility Contract

- All images carry descriptive alt text that includes the honest native label where applicable (see Copywriting Contract above)
- Alt text maximum: 150 characters for GitHub rendering (longer alt text is truncated in some renderers)
- The GIF must not flash at frequencies that could trigger photosensitive seizures (12fps smooth terminal scroll is safe; avoid high-contrast strobe transitions)
- Advisory labels appear BEFORE or ADJACENT to native images — never after (reader meets caveat before/with image per CONTEXT.md D-06)
- All code examples use fenced code blocks for screen-reader compatibility (not indented-space blocks)
