## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LiveView/current session -> approval context | Current user/account assigns cross into authorization and mutation logic. |
| Approval context -> database | Ecto writes persisted approval/activity evidence. |
| Reset orchestration -> database | Showcase reset deletes/reseeds lane-owned mutable rows. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-149-11 | Elevation of Privilege | `Approvals.approve_approval/2` | mitigate | Authorize from server-owned scope, require approver role, and deny cross-account approvals. |
| T-149-12 | Tampering | Ecto writes | mitigate | Use Ecto changesets and `Ecto.Multi`; no raw SQL or interpolated user input. |
| T-149-13 | Repudiation | approval activity events | mitigate | Insert activity rows with stable event IDs, actor ID, route ID, support ref, outcome, and occurred_at. |
| T-149-14 | Information Disclosure | activity metadata | mitigate | Store low-cardinality support evidence only; exclude tokens, session refs, provider payloads, and PII beyond fictional fixture IDs. |
</threat_model>
