<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser click -> LiveView event | Untrusted browser interaction asks the server to approve a record. |
| LiveView assigns -> approval context | Current user/account assigns authorize mutation. |
| LiveView success -> native bridge request | Optional haptics request crosses from server-rendered page to native shell bridge. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-149-19 | Tampering | `ApprovalLive.handle_event/3` | mitigate | Ignore client-supplied account/user authority and call `Approvals.approve_approval/2` with server assigns. |
| T-149-20 | Elevation of Privilege | approval action | mitigate | Context denies non-approver and cross-account scopes; LiveView renders denial without mutating. |
| T-149-21 | Spoofing | haptics bridge payload | mitigate | Emit haptics only after persisted server success and include route id/active route id; haptics never changes approval status. |
| T-149-22 | Information Disclosure | forbidden/error UI | mitigate | Use calm short copy and no raw denial-code dumps or sensitive session details. |
</threat_model>
