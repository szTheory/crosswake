<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| mix.exs `:files` allowlist → published hex tarball | The `:files` list is the source-of-truth for what content crosses from the repo into the immutable public tarball on hex.pm. Anything not in the list is filtered out. |
| `:links` map values → public hex.pm sidebar | The three link values are rendered as clickable links on every adopter's view of the package page. A broken or malicious URL here is a permanent first-impression failure (1-hour republish, 24-hour revert windows only). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-02-01 | Information Disclosure | `:files` allowlist | mitigate | Use the explicit allowlist `~w(lib priv .formatter.exs mix.exs README.md LICENSE CHANGELOG.md guides)` per D-06. Excludes `.planning/`, `prompts/`, `test/`, `.github/`, `examples/`, `native/` which contain internal planning artifacts, OSS DNA prompts, test fixtures, and CI internals. Verified at Phase 30 (HEX-02) via `mix hex.build --unpack`. |
| T-26-02-02 | Spoofing | `:links` "GitHub" value | mitigate | The link value flows from a single `@source_url` module attribute (D-09) — there is one place to verify the URL is the real `szTheory/crosswake` repo (Pitfall 7). No string duplication that could drift. |
| T-26-02-03 | Tampering | `:licenses` declaration vs LICENSE file | mitigate | Plan 01 creates LICENSE matching SPDX `Apache-2.0`; this plan declares the same identifier. The two are cross-referenced by the `mix hex.publish` preflight (deferred to Phase 30). |
| T-26-02-SC | Supply Chain | No package installs in this plan | accept | This plan modifies a single source file (`mix.exs`) and does not run `mix deps.get` or any install command. No supply-chain surface in this plan. Package install gates apply to plan 03 (ex_doc) and plan 04 (verification). |
