<objective>
Create the Apache-2.0 LICENSE file at the repository root so that the `:files` allowlist in `mix.exs` (added by plan 02) can reference an on-disk file and so that the `:licenses ["Apache-2.0"]` declaration is legally honest per D-05/D-10.

Purpose: hex.pm requires that the license declared in `:package :licenses` be backed by a real LICENSE file in the published tarball; an explicit Apache-2.0 declaration without a LICENSE file is a hex publish preflight failure. This is the prerequisite for satisfying SC #3 and META-05.

Output: A new `LICENSE` file at the repository root containing the canonical Apache-2.0 boilerplate from `https://www.apache.org/licenses/LICENSE-2.0.txt`, with `[yyyy]` replaced by `2026` and `[name of copyright owner]` replaced by `szTheory`. No appendix stripping, no clause modifications.
</objective>

  <action>
    Create a new file at `LICENSE` (repo root, no extension) containing the canonical Apache License, Version 2.0 boilerplate published by the Apache Software Foundation at `https://www.apache.org/licenses/LICENSE-2.0.txt`.

    Substitution rules:
    - Replace `[yyyy]` in the "APPENDIX: How to apply the Apache License to your work" section with exactly `2026`.
    - Replace `[name of copyright owner]` in the same appendix with exactly `szTheory`.
    - The resulting copyright line in the appendix MUST read: `Copyright 2026 szTheory`.

    Verbatim rules (no deviation per D-10):
    - Do NOT strip the APPENDIX section.
    - Do NOT modify any clause text (TERMS AND CONDITIONS sections 1-9).
    - Do NOT add a project-specific preamble above "Apache License".
    - The first non-blank line of the file MUST be exactly: `                                 Apache License`.
    - The version line directly under it MUST be exactly: `                           Version 2.0, January 2004`.
    - The URL line directly under that MUST be exactly: `                        http://www.apache.org/licenses/LICENSE-2.0`.

    Source canonical text: fetch from `https://www.apache.org/licenses/LICENSE-2.0.txt` or use the byte-identical SPDX-published copy at `https://spdx.org/licenses/Apache-2.0.html` (plain-text view). Both sources are equivalent for the body; the file MUST be the plain-text version (not HTML).

    Do not include any trailing comments, signatures, or szTheory-specific text outside the two appendix substitutions above.
  </action>
  <verify>
    <automated>test -f LICENSE && head -1 LICENSE | grep -q "Apache License" && grep -q "Version 2.0, January 2004" LICENSE && grep -q "Copyright 2026 szTheory" LICENSE && grep -q "http://www.apache.org/licenses/LICENSE-2.0" LICENSE && ! grep -q "\[yyyy\]" LICENSE && ! grep -q "\[name of copyright owner\]" LICENSE && echo OK</automated>
  </verify>
  <acceptance_criteria>
    - `test -f LICENSE` exits 0.
    - `head -1 LICENSE` contains the literal substring `Apache License` (the centered heading line).
    - `grep -c "Version 2.0, January 2004" LICENSE` returns at least 1.
    - `grep -c "Copyright 2026 szTheory" LICENSE` returns exactly 1 (the appendix substitution).
    - `grep -c "http://www.apache.org/licenses/LICENSE-2.0" LICENSE` returns at least 1.
    - `grep -c "\[yyyy\]" LICENSE` returns 0 (placeholder substituted).
    - `grep -c "\[name of copyright owner\]" LICENSE` returns 0 (placeholder substituted).
    - `wc -l LICENSE` returns at least 175 lines (canonical Apache-2.0 plain text is ~202 lines; this is a sanity-check floor against accidentally stripping the body).
    - The file contains the section heading `TERMS AND CONDITIONS FOR USE, REPRODUCTION, AND DISTRIBUTION` (verify with `grep -c "TERMS AND CONDITIONS FOR USE, REPRODUCTION, AND DISTRIBUTION" LICENSE` returns at least 1).
    - The file contains the section heading `APPENDIX: How to apply the Apache License to your work.` (verify with `grep -c "APPENDIX: How to apply the Apache License to your work" LICENSE` returns at least 1).
  </acceptance_criteria>
  <done>
