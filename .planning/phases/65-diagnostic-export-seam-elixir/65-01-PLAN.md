<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted attrs map → sanitize/1 | A caller (eventually the native shell in Phase 67) hands an arbitrary map that must become a typed Envelope or be rejected. This is the only untrusted-input crossing in this plan. |
| Crosswake lib → host-owned endpoint | The transport boundary is documented (POST contract) but NOT implemented here. Network threats are host-owned and out of scope for Phase 65 (no transport ships). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-65-01 | Information Disclosure | Envelope / NativeDiagnostic struct shape | mitigate | Allowlist-by-construction (D-11): the typed structs literally cannot hold tokens/PII/route-params/payloads. No `raw_payload`, no open `map()`/`keyword()` field (D-13). The schema IS the redaction. |
| T-65-02 | Information Disclosure | sanitize/1 input map | mitigate | sanitize/1 rejects (`{:error, :redaction_failed}`) any input key in the 19-key forbidden set or outside allowed_keys — a token-bearing key can never round-trip into an Envelope. |
| T-65-03 | Repudiation | sanitize/1 partial-data behavior | mitigate | Fail-closed (D-14): sanitize rejects the whole payload rather than drop-and-continue, so a diagnostic is never silently truncated into a misleading partial record. |
| T-65-04 | Information Disclosure | free-form crash text | accept (out of scope) | Stack traces / exception messages are inherently un-allowlistable and are host-owned (D-12). The Elixir contract carries typed codes only; free-form capture lives at the host endpoint, not in Crosswake's payload. |
| T-65-NET | Spoofing/Tampering | network transport to host endpoint | accept (host-owned) | No transport ships in Phase 65; the POST is implemented by the native shell + host in Phase 67. Network-layer threats are host-owned and explicitly out of scope. |
| T-65-SC | Tampering | npm/pip/cargo/hex installs | mitigate | This plan adds NO dependency. The no-HTTP-dep assertion is enforced by the proof lane in Plan 03. No package-install task exists here. |
</threat_model>
