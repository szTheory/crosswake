## Common Pitfalls

### Pitfall 1: Support Matrix Guide-Only Fix
**What goes wrong:** Editing `guides/support_matrix.md` without changing canonical source passes review visually but fails renderer parity. [VERIFIED: test/crosswake/support_matrix/renderer_test.exs]  
**Why it happens:** The guide is generated from `SupportMatrix.canonical()`. [VERIFIED: lib/crosswake/support_matrix/renderer.ex]  
**How to avoid:** Change canonical support derivation, regenerate the guide, and run support-matrix tests. [VERIFIED: test/crosswake/support_matrix/renderer_test.exs]  
**Warning signs:** Byte-parity failure says `guides/support_matrix.md drifted from canonical Renderer output`. [VERIFIED: test/crosswake/support_matrix/renderer_test.exs]

### Pitfall 2: Advisory Proof Still Renders Supported
**What goes wrong:** A deferred row with `proof_class: :advisory` can still render proof status as supported. [VERIFIED: lib/crosswake/support_matrix/support_matrix.ex]  
**Why it happens:** Current helper maps advisory proof to `:supported`. [VERIFIED: lib/crosswake/support_matrix/support_matrix.ex]  
**How to avoid:** Add explicit `:unsupported` handling for deferred rows or explicit scanner/document_scan rows. [VERIFIED: guides/capability_map.md]  
**Warning signs:** `| scanner | ... | supported | supported | defer |` or `| document_scan | ... | supported | supported | defer |`. [VERIFIED: guides/support_matrix.md]

### Pitfall 3: Reconstructing Verification Without Reruns
**What goes wrong:** `VERIFICATION.md` exists but only quotes old summaries, leaving current support-truth changes unverified. [VERIFIED: .planning/v19.0-MILESTONE-AUDIT.md]  
**Why it happens:** The original missing ledger was an artifact gap, but Phase 152.1 changes source truth and must prove no regression. [VERIFIED: 152.1-CONTEXT.md]  
**How to avoid:** Rerun focused support/capability/Fieldserv checks before writing final verification status. [VERIFIED: Validation Architecture below]  
**Warning signs:** Verification file claims `passed` but has no Phase 152.1 rerun section. [VERIFIED: 149/151 verification format comparison]

### Pitfall 4: Phase 148 Historical Rewrite
**What goes wrong:** Retroactive summary frontmatter can satisfy a mechanical cross-check while making it look as if plan summaries existed at execution time. [VERIFIED: 148-VALIDATION.md]  
**Why it happens:** The milestone audit uses three-source cross-checks. [VERIFIED: .planning/v19.0-MILESTONE-AUDIT.md]  
**How to avoid:** Prefer an explicit accepted exception, or label any retro artifact as retroactive. [VERIFIED: 152.1-CONTEXT.md]  
**Warning signs:** A new `148-*-SUMMARY.md` lacks "retroactive" language. [VERIFIED: 148-VALIDATION.md]
