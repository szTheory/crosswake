<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| signed ticket -> example-host redemption context | Untrusted client-presented envelope crosses into host-owned Repo and projection logic. |
| server record/audit transaction -> Plug session mutation | Durable backend state transitions cross into non-transactional session mutation. |
| route id / intent / binding facts -> return target | Requested handoff target crosses into route activation and redirect behavior. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55-05 | Replay | `CrosswakeExample.SaaSPortal.Handoff.redeem/2` | mitigate | Use a conditional consume inside one transaction so only `:issued`, unconsumed, unrevoked, unexpired rows can transition to redeemed, and prove replay returns `auth.handoff.replayed_ticket`. |
| T-55-06 | Elevation of Privilege | server-record authority vs envelope | mitigate | Verify the envelope for integrity only, then derive all authority from the authoritative server record and the resulting `SessionAuthorityLane` per D-08/D-09. |
| T-55-07 | Spoofing | binding / intent / route match | mitigate | Compare backend-known subject/org/session/version/intent/route facts to the record, deny mismatches with canonical codes, and never treat IP or user-agent as default hard bindings per D-06 and D-19. |
| T-55-08 | Open Redirect | target route resolution | mitigate | Resolve handoff returns through manifest-known Crosswake route ids only and deny arbitrary `return_to` URLs or route mismatches instead of redirecting. |
| T-55-09 | Session Fixation | `CrosswakeExample.SaaSPortal.Auth` renewal boundary | mitigate | Call `configure_session(conn, renew: true)` only after the redemption transaction succeeds and keep failed redemption paths side-effect free for host session state per D-11/D-25. |
| T-55-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs are part of this plan. |
</threat_model>
