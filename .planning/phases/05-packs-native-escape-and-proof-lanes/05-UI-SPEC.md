## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #F4F7FA | App background, full-screen shell surfaces, neutral proof reports |
| Secondary (30%) | #E4EAF1 | Cards, grouped rows, status panels, route-local metadata containers |
| Accent (10%) | #0F766E | Primary CTA, active progress bars, selected proof-lane filter chips, install/update/retry states only |
| Destructive | #B42318 | Pack invalidation, cancel-and-discard transfer actions only |

Accent reserved for: `Install Required Pack`, `Retry Transfer`, `Open Native Capture`, active transfer progress, and proof-lane pass/fail filter selection. Do not use accent for passive metadata, generic links, or every tappable row.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | Install Required Pack |
| Empty state heading | No pack activity yet |
| Empty state body | This route has not installed, transferred, or invalidated any declared packs. Activate a manifest-declared route to start pack work or open the proof lane for install checks. |
| Error state | Crosswake could not complete this route step. Retry the declared action, or ship the required shell, pack, or manifest update before reopening the route. |
| Destructive confirmation | Invalidate pack: Remove this local pack from the shell? Routes that depend on it will stay unavailable until a compatible pack is installed again. |

Additional destructive confirmation: Cancel transfer: Stop this transfer and discard partial local data? The route remains unchanged until a new declared transfer starts.

## Phase Surface Contract

| Surface | Owner | Contract |
|---------|-------|----------|
| Pack status panel | Native shell surface | Shows declared version, installed version, bytes, last verified time, and one next action |

## Native Escape Hatch

- The first documented native escape hatch is a manifest-declared media capture screen. It owns camera permission, capture UI, local file staging, and the handoff back to a declared transfer seam.
- The escape hatch opens only from a route explicitly marked `native_screen`. Do not open it as a hidden fallback for LiveView or offline-island routes.
- The screen header must show the route title, a short ownership label (`Native capture`), and a dismiss or return action that names the destination route.
- The screen body must show exactly one purpose sentence, one primary action, and one secondary action. Do not present generic browser chrome, tabs, or arbitrary plugin controls.
- On denial or incompatibility, reuse the existing fail-closed tone: explain what is blocked, why it is blocked, and the exact recovery path (`retry`, `update app`, or safe return route).
- Captured media is not treated as "uploaded" until the declared transfer seam starts. Keep "captured locally" and "transferred to host" as separate visible states.

---

## Pack Lifecycle Visibility

- Every route that declares packs must show a pack panel before route activation completes when the pack state is not `available`.
- Allowed pack states are `checking`, `not_installed`, `installing`, `available`, `stale`, `invalidating`, and `failed`.
- Each state must render the same metadata fields in the same order: pack name, required version, installed version or `none`, size, and latest verification timestamp.
- `checking` uses neutral styling and no spinner longer than 400ms before text appears.
- `not_installed` shows the primary CTA `Install Required Pack`.
- `installing` shows determinate progress when bytes are known; otherwise show stage text only: `Preparing`, `Downloading`, `Verifying`, `Installing`.
- `available` shows a subdued success badge and no accent CTA unless an update is required.
- `stale` means the installed pack exists but no longer satisfies manifest truth; show `Update Pack`, not `Open Route`.
- `invalidating` must block route entry until the invalidation finishes or fails.
- `failed` must preserve the last successful installed version, if any, and expose one retry action plus one details disclosure.

---

## Route-Local Transfer States

- Transfer UI is scoped to the active route or native capture flow. Do not imply a background app-wide transfer manager.
- Allowed transfer states are `queued`, `preparing`, `transferring`, `awaiting_network`, `verifying`, `complete`, `failed`, and `canceled`.
- Upload and download rows use the same layout: item label, state label, bytes or count detail, and one route-local action.
- `awaiting_network` must say that the transfer cannot continue until connectivity returns; do not promise silent background reconciliation.
- `verifying` is required after a completed download or capture handoff before the pack or media is considered available.
- `complete` switches accent away from the row and keeps a neutral completion summary so the screen does not look permanently active.
- `failed` shows the failure reason first, then the next action. Prefer specific reasons such as `pack checksum mismatch`, `capture permission denied`, or `upload seam unavailable`.
- Canceling a transfer is destructive only when partial local data will be discarded; require confirmation in that case.

---

## Proof-Lane Reporting Surfaces

- Proof lanes are product UI, not hidden CI trivia. Surface them in doctor output, docs examples, and example-host verification pages with the same status vocabulary.
- Allowed proof statuses are `passed`, `failed`, and `verification required`. Do not collapse `verification required` into success or warning-copy ambiguity.
- Report iOS, Android, and Phoenix host proof separately. A single green platform does not unlock a global "supported" claim.
- Each proof card must show artifact name, command or script path, last run timestamp, exit result, and one next step.
- When proof is blocked by host environment issues, say that explicitly and name the failing dependency class, such as simulator boot or managed-device startup.
- Use monospace treatment for script paths, pack identifiers, route ids, and version tuples anywhere they appear in proof or denial details.
- Proof failure details should default collapsed after the first 3 lines, with an explicit `Show full output` affordance, so the primary state remains scannable.

---

## Interaction Rules

- Keep runtime ownership visible at the top of every Phase 5 surface with one compact label: `LiveView`, `Offline island`, or `Native capture`.
- Never auto-open a generic WebView when a pack, transfer, or native-screen contract fails. Failure remains visible and fail-closed.
- Primary actions are singular per surface. If two actions compete, demote the less likely recovery path to a text button.
- Reuse the existing denial vocabulary from shell activation and compatibility findings: `route unavailable`, `pack incompatible`, `origin denied`, `update app`, and `retry`.
- Route ids, pack ids, and versions are operator-facing data and should stay visible in details drawers rather than being hidden from adopters.
