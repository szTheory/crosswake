<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Canonical support truth -> public guides | Typed package classifications become adopter-facing support claims. |
| Public docs -> adopters | Ledger wording can create or prevent false support expectations. |
| Example-host README -> future proof lanes | The checked-in host could be mistaken for a runtime package if boundary wording drifts. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-01 | Spoofing | `guides/capabilities.md`, `guides/install.md`, `examples/phoenix_host/README.md` | mitigate | Require explicit `not first-class supported`, `supported example`, and D-34 docs-only section wording so docs-only or proof artifacts cannot masquerade as supported runtime packages. |
| T-12-02 | Elevation of Privilege | `guides/capabilities.md` | mitigate | State that package class does not override route ownership and keep docs-only templates explicit about `Route owner`, `Denial behavior`, and `Fallback behavior` so packaging copy cannot widen runtime authority by implication. |
| T-12-03 | Tampering | `lib/crosswake/support_matrix/support_matrix.ex`, `lib/crosswake/support_matrix/renderer.ex` | mitigate | Render the packaging ledger from typed canonical state and lock it with ExUnit renderer/support tests so manual edits cannot drift support truth. |
| T-12-04 | Repudiation | `guides/support_matrix.md` | mitigate | Put the primary-package and package-class truth into generated support output so future release notes or guide edits cannot deny the published boundary decisions. |
</threat_model>
