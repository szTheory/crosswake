<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Change-class support truth -> public guides | Generated class labels shape release notes, compatibility examples, and adopter action. |
| Public guides -> adopters | Rebuild guidance determines whether users ship a new binary or misapply a docs-only or compatibility-only change. |
| Docs-only graduation rules -> future proof lanes | Graduation wording determines whether examples can be promoted without proof and reclassification. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-12-09 | Tampering | `lib/crosswake/support_matrix/support_matrix.ex`, `lib/crosswake/support_matrix/renderer.ex` | mitigate | Generate the change-class matrix from typed support truth and assert exact class labels plus proof-lane mapping in support-matrix tests so compatibility-policy drift cannot silently rewrite adopter action. |
| T-12-10 | Repudiation | `guides/install.md`, `guides/compatibility.md`, `guides/support_matrix.md` | mitigate | Require all three guide surfaces to publish the same class labels and action-first wording so release notes cannot later deny rebuild expectations were documented. |
| T-12-11 | Spoofing | `examples/phoenix_host/README.md` and docs-only graduation copy | mitigate | Keep runnable docs-only lanes explicitly disallowed without reclassification plus proof so advisory example text cannot masquerade as supported release-ready surface. |
| T-12-12 | Elevation of Privilege | `guides/native_shell.md`, `guides/compatibility.md` | mitigate | Tie rebuild-required and compatibility-bump language to explicit route-ownership and runtime-line rules so package-copy changes cannot imply unsupported native authority is safe. |
</threat_model>
