  <behavior>
    - Resolving against a route without `notification_open` returns `{:error, %Shell.Denial{reason: :notification_open_denied, code: "notification.open.policy_denied"}}`.
    - Resolving against a route with an unpermitted `action_ref` returns `unsupported_action`.
    - Successful pre-flight calls `RouteGate.evaluate` and returns its `Decision` (or passes through its `Denial` like `:step_up_required`).
  </behavior>
  <action>
    Create `Crosswake.Companions.Chimeway.Resolver`.
    Implement `resolve/2` taking `Manifest.Root` and `NotificationOpenEvidence`.
    Flow: 
    1. Look up `route_id` in manifest. If absent, fail `route_mismatch`.
    2. Read `route.notification_open`. If falsy, fail `policy_denied`.
    3. If `notification_open` restricts actions (`[actions: [...]]`), verify `evidence.action_ref` is allowed. If not, fail `unsupported_action`.
    4. Validate intent state (mocked or contract check if Registry handles DB; since resolver is in core and registry is in host, the Resolver receives evidence of consumption, or the host calls registry then calls Resolver. Assume host consumes intent THEN calls resolver, or resolver receives intent state. Note: Core cannot access host DB. Core's Resolver receives the `NotificationOpenEvidence` which the host constructs after consuming the intent).
    Wait, D-10: "Resolver pre-flight: (1) route_id present... (2) consume the open-intent...". Since core cannot call host DB, the host consumes the intent, then passes the resulting intent metadata/evidence to `Resolver.resolve/2`. The `NotificationOpenEvidence` includes the intent state. If state indicates expired/replayed, Resolver returns appropriate denial.
    5. Delegate to `RouteGate.evaluate(manifest, route_id, target, activation_source: :notification, auth_context: evidence.auth_context)`.
    6. Return the `Decision` or pass-through the `Denial` unmodified. (Decisions D-07, D-08, D-10, D-11, D-12)
  </action>
