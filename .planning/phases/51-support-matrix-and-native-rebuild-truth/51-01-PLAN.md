| Boundary | Description |
|----------|-------------|
| canonical support data -> docs and diagnostics | New action/promotion vocabulary becomes public support truth once renderer, inspection, and doctor consume it. |
| deferred-scope rows -> public support claims | Provider, auth, notification-delivery, and shell-package defers must stay explicit instead of being inferred as shipped support. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-51-01 | Tampering | `lib/crosswake/support_matrix/support_matrix.ex` | mitigate | Keep raw axes separate with exact closed vocabularies and lock them with focused support-matrix tests per D-01 through D-08. |
| T-51-02 | Information Disclosure | deferred provider/auth/notification/shell claims | mitigate | Model deferred surfaces as explicit canonical rows and promotion rules, never as omitted rows that could be misread as shipped support. |
| T-51-03 | Repudiation | promotion criteria | mitigate | Store promotion thresholds, check ids, docs anchors, and demotion triggers as typed fields so later runtime surfaces can audit them verbatim. |
| T-51-SC | Tampering | npm/pip/cargo installs | accept | No new package-manager installs are allowed in this plan. |
</threat_model>
