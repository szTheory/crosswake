## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| canonical support truth -> operator inspection | Route-level inspection can drift or collapse axes if it re-derives support states instead of reusing canonical data. |
| canonical support truth -> publish readiness | Doctor checks can imply promotion or rebuild safety if they omit action or demotion metadata. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-51-07 | Tampering | `lib/crosswake/operator_inspection.ex` | mitigate | Enrich existing route maps from `Crosswake.SupportMatrix` and lock `support.status` versus `support.proof_class` separation in inspection tests. |
| T-51-08 | Repudiation | `lib/crosswake/doctor/publish_readiness.ex` | mitigate | Emit canonical promotion-rule ids, docs anchors, action classes, and demotion triggers in check payloads so readiness claims are auditable. |
| T-51-09 | Information Disclosure | human operator output | mitigate | Keep formatter output concise but explicit, showing `change_class=` and `actions=` rather than vague safety language like "ready" or "green". |
| T-51-SC | Tampering | npm/pip/cargo installs | accept | No new package-manager installs are allowed in this plan. |
</threat_model>
