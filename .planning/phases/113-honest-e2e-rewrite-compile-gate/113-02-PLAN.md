Rewrite the structurally-fraudulent `examples/phoenix_host/e2e/offline_sync.spec.ts` into the honest offline→reconnect→reconcile proof (E2E-03 a–f).

The old spec is fraudulent: it injects a mutation into `window['crosswake_offline_mutations']` (a global the app never reads), manually fires `fetch('/study/sync')`, asserts on a test-minted UUID it placed there itself, and hits the wrong route (`/study/session`). Phase 112 shipped the real app (real IndexedDB outbox + reconnect flush on `/offline`); this plan writes the real test that exercises that app's own code paths and nothing else.

The honesty boundary is the entire point of the milestone: mutation queuing and outbox flushing are driven EXCLUSIVELY by real UI interaction and the app's own reconnect handler. The only permitted `page.evaluate` uses are (a) read-only IndexedDB observation and (b) dispatching `window 'online'` (environment simulation — replicating the OS connectivity event a real browser fires on reconnect). Encoding these prohibitions as must_haves so Phase 114's GUARD-01 scan passes is load-bearing.

Purpose: Prove the full loop using only the app's own code paths — the proof a CI green check claims.
Output: A rewritten `offline_sync.spec.ts` that runs green and is GUARD-01-clean.
</objective>
