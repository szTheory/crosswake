    Base image (Claude's-discretion settled): use `hexpm/elixir:1.19.5-erlang-27.3-debian-bookworm-20250630-slim` for BOTH stages. Rationale: the repo pins erlang 27.3 + elixir 1.19.5-otp-27 in .tool-versions; mix.exs requires elixir ~> 1.19; `ecto_sqlite3`/`exqlite` compiles a NIF, so a glibc (Debian) base is required — Alpine/musl is unsafe.     Dockerfile (multi-stage, layer-ordered per DOCKER-02): Stage `build` — WORKDIR /app, ENV MIX_ENV=dev, `RUN mix local.hex --force && mix local.rebar --force`. Then `COPY mix.exs mix.lock ./` followed by `RUN mix deps.get`, THEN `COPY config/ config/`, `COPY lib/ lib/`, `COPY priv/ priv/`, THEN `RUN mix deps.compile`. The deps layer MUST come before any source COPY so editing app/style code never re-triggers deps.get/compile. Stage 2 (runtime): same base image, WORKDIR /app, ENV MIX_ENV=dev, `COPY --from=build /app /app`, `COPY --from=build /root/.mix /root/.mix`, `COPY entrypoint.sh ./`, `RUN chmod +x entrypoint.sh`, `EXPOSE 4700`, `CMD ["./entrypoint.sh"]`. Note: under docker-compose the source bind-mount and named dep volumes supersede the image's baked deps for live-reload; the image build still validates a clean dep compile.

    entrypoint.sh (per D-09, idempotent): `#!/bin/sh`, `set -e`, then `mix ecto.create --quiet`, `mix ecto.migrate --quiet`, `mix run priv/repo/seeds.exs`, `exec mix phx.server`. Re-seed posture (discretion settled): plain unconditional re-seed — seeds.exs is already idempotent (delete_all → insert 1 deck + 3 cards), so no count==0 guard is added (matches D-09 "default re-seed is fine"). The DB target is DATABASE_PATH (set to /data/crosswake_example.db by compose), so ecto.create lands the DB inside the named volume.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host network → container :4700 | `ports: 4700:4700` + `0.0.0.0` bind exposes the dev server on the host's interfaces |
| build context → image layers | files not excluded by .dockerignore are copied into the image and may bake host artifacts/secrets |
| package registry → image | `mix deps.get` pulls hex packages into the image at build time |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-125-05 | Information Disclosure | Docker build context | mitigate | .dockerignore excludes .git, .planning, .claude, .env, evidence/artifacts, and *.db — no repo secrets, planning docs, or DB artifacts bake into the image (Task 2 verify enumerates exclusions) |
| T-125-06 | Tampering | crosswake_example.db* baked into image | mitigate | Explicit `crosswake_example.db*` + `*.db*` exclusion ensures the named volume (not a stale baked file) is the single DB source — prevents shadowing |
| T-125-07 | Elevation of Privilege / Exposure | 0.0.0.0 bind via BIND_ALL=true | accept | 0.0.0.0 is required for host/emulator reachability of a local-dev demo backend; it is container-scoped (BIND_ALL set only in compose) and not a prod path; acceptable for local dev |
| T-125-SC | Tampering | mix deps.get (hex packages) | mitigate | Deps are pinned by the committed mix.lock (no floating installs); no new package-manager installs are introduced in this plan, so no [ASSUMED]/[SUS] legitimacy checkpoint is required |
