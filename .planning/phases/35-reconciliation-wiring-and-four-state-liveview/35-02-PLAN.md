<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| PubSub bus -> PaywallEntryLive | LiveView receives `{:entitlement_update, state}` via handle_info. Payload is the derived atom only — no snapshot/lane fields. |
| LiveView render -> browser | HEEx markup consumes only the derived atom and the static PaywallEntry contract. No EntitlementSnapshot internal lane fields reach the DOM. |
| dev/build boundary | Dev scenario drivers are gated by the compile-time `@dev_mode Mix.env() == :dev` flag; they must not appear in a production build. |
| HTTP client -> phx-click events | subscribe/restore/dev_force_* events build all intents/snapshots from internal constants — no client-supplied data reaches business logic. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-05 | Information Disclosure | LiveView render + PubSub handle_info | mitigate | The UI consumes ONLY the derived atom (D-11/STATE-01); raw EntitlementSnapshot lane fields are never assigned to the socket for rendering nor broadcast. Acceptance criteria assert components render only the derived state and the PaywallEntry contract, never lane fields. |
| T-35-06 | Elevation of Privilege | dev scenario drivers leaking into production | mitigate | Dev scenario buttons + handlers are gated behind the compile-time `@dev_mode Mix.env() == :dev` module attribute (Pitfall 7), not a runtime check that survives in a release. The dev guard is the explicit delimiter between demo scaffolding and real data flow (D-15). |
| T-35-07 | Tampering | npm/pip/cargo/hex installs | accept | No package installs in this plan — zero new dependencies. Package Legitimacy Gate not applicable. |
| T-35-08 | Spoofing/Tampering | unauthenticated phx-click events | accept | No auth gating on the paywall route by design (AF-05, adopter responsibility). Events construct intents from internal constants + generated correlation_ids; no client data reaches MockStorefront/ingest. Low risk on a mock, no-persistence example host. |
| T-35-09 | Elevation of Privilege | mock evidence granting authority via UI flow | mitigate | The subscribe/restore flow grants only through MockBackend -> project_snapshot/2 (which rejects unverified reconciliation states); the UI cannot promote raw evidence to authority. Anchored on `authority_mutation_allowed_from_evidence?/1 -> false`, asserted by the Phase 36 proof (PROOF-03). |
</threat_model>
