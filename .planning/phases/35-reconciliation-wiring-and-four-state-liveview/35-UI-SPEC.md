## Interaction Contract

### `PaywallEntryLive` event map

| User Action | phx-click / handle_info | State Transition | Notes |
|-------------|------------------------|-----------------|-------|
| Mount (connected) | — | assign `derived_state: :stale` | Fail-closed (D-05, CONTEXT specifics) |
| Click "Subscribe" | `"subscribe"` | `:stale` → `:pending` (immediate broadcast) → terminal state via Task | Task broadcasts terminal `{:entitlement_update, state}` after mock delay (D-04) |
| Click "Restore purchase" | `"restore"` | same async path as subscribe | Uses `simulate_restore/2` instead of `simulate_purchase/2` |
| `{:entitlement_update, state}` PubSub | `handle_info` | assign `derived_state: state` → re-render | Only message that can change derived_state post-mount |
| Dev: "Force: {state}" | `"dev_force_{state}"` (`:dev` only) | immediate assign `derived_state: state` after real `derived_state/1` derivation | Builds real snapshot, calls `derived_state/1`, broadcasts (D-15) |

### Render dispatch

```
case @derived_state do
  :granted -> <.granted />
  :pending -> <.pending />
  :denied  -> <.denied />
  :stale   -> <.stale />
end
```

The `case` is exhaustive — all four atoms are explicit branches. No `_ ->` fallthrough. This makes the four states findable by symbol search (D-09).

### PubSub subscription

Subscribe topic: `"entitlement:" <> group_id` where `group_id` is derived from `ReconciliationKeys.subject_key/2` using `MockStorefront.@subscription_entry_id` ("sub_pro_monthly"). Subscription happens only inside `if connected?(socket)` (D-13).

### CorridorController actions

`POST /commerce/purchase` and `POST /commerce/restore` delegate to the same `MockStorefront → ReconciliationInbox → MockBackend` path as `PaywallEntryLive`. Response: `200 OK` with JSON `%{status: evidence_status}`. These are thin seams, not interactive UIs (D-07).
