<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP client -> CorridorController POST | Untrusted client can POST to /commerce/purchase and /commerce/restore. In this phase the actions ignore the request body entirely and build all intents from internal constants + generated UUIDs (no client data reaches business logic). |
| MockBackend -> PubSub bus | In-process broadcast on topic `"entitlement:" <> group_id`. The payload is the derived atom only. |
| dev/build boundary | This is a `provider: "mock"`, no-persistence, no-auth, no-network example host. The only non-trivial leakage surface is the PubSub message contract. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-35-01 | Information Disclosure | MockBackend PubSub broadcast | mitigate | Broadcast carries the derived atom ONLY (`{:entitlement_update, state}`) — never the `%EntitlementSnapshot{}` or any raw lane field (D-11/D-14, STATE-01). Acceptance criteria assert the message tuple shape and absence of snapshot transmission. |
| T-35-02 | Tampering | npm/pip/cargo/hex installs | accept | No package installs in this plan — zero new dependencies (phoenix_pubsub 2.2.0 already in mix.lock). Package Legitimacy Gate not applicable. |
| T-35-03 | Spoofing/Tampering | CorridorController POST body | accept | Actions ignore the request body and construct all intents from internal constants + generated correlation_id; no client-supplied data reaches MockStorefront/ingest. Auth gating is explicitly out of scope (AF-05, adopter responsibility). Low risk on a mock example host. |
| T-35-04 | Elevation of Privilege | mock evidence granting authority | mitigate | The grant path runs through `EntitlementProjection.project_snapshot/2`, which rejects unverified reconciliation states; mock evidence can never directly mutate authority (the `authority_mutation_allowed_from_evidence?/1 -> false` fence, asserted by the Phase 36 proof PROOF-03). MockBackend manufactures the verified snapshot explicitly rather than promoting raw evidence. |
</threat_model>
