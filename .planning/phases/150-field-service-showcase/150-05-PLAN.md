## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Fixture/context data -> HEEx | Fieldserv jobsite data becomes browser-visible UI. |
| Diagnostics data -> HEEx | Route policy/support truth becomes browser-visible UI. |
| Browser click -> LiveView event | Inspection event requests cross from browser into server-owned state. |

## Security Gate

Phase 150 uses ASVS L1 as the security baseline with a high-severity blocking threshold. Any implementation that introduces a high-severity ASVS L1 issue in input validation, evidence state integrity, route policy, or support-truth disclosure must stop execution and revise before the plan can be marked complete.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-150-22 | Information Disclosure | Fieldserv pages | mitigate | Render only fictional fixture data and support refs; avoid real PII, tokens, session refs, or provider payloads. |
| T-150-23 | Spoofing | posture badges | mitigate | Badges consume diagnostics rows derived from router metadata, not client-provided labels. |
| T-150-24 | Tampering | `InspectionLive.handle_event/3` | mitigate | Route inspection state changes through `FieldService.Evidence`, not direct Repo writes or client-supplied status promotion. |
| T-150-25 | Repudiation | inspection events | mitigate | Persist inspection event metadata with route ID, support ref, technician/job IDs, and occurred_at. |
| T-150-26 | Denial of Service | dense responsive UI | mitigate | Use stacked mobile layout, wrapping text, and no horizontal overflow patterns in `.fieldserv-*` CSS. |
</threat_model>
