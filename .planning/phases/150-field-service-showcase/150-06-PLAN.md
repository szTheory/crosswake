<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser route -> native-screen fallback | Browser-visible capture page represents a route whose primary owner is native runtime. |
| Browser click -> evidence context | Evidence review actions request server-side state transitions. |
| Evidence state -> user copy | Persisted device/backend statuses become support and availability claims. |

## Security Gate

Phase 150 uses ASVS L1 as the security baseline with a high-severity blocking threshold. Any implementation that introduces a high-severity ASVS L1 issue in route policy, input validation, evidence state integrity, permission/capability support truth, or data protection must stop execution and revise before the plan can be marked complete.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-150-27 | Spoofing | `CaptureLive` route ownership | mitigate | Render native-screen and camera capability posture from diagnostics; do not present capture as browser-owned. |
| T-150-28 | Spoofing | scanner/permission support | mitigate | Label scanner/document scan/permission support as native-runtime or future pressure, not shipped bridge support. |
| T-150-29 | Tampering | `EvidenceReviewLive.handle_event/3` | mitigate | Call `FieldService.Evidence` context functions and ignore client-supplied final status authority. |
| T-150-30 | Repudiation | evidence review transitions | mitigate | Persist transitions as evidence events with route ID, support ref, actor/technician/job IDs, and occurred_at. |
| T-150-31 | Information Disclosure | evidence review metadata | mitigate | Render fictional fixture IDs/statuses and sanitized metadata only; avoid raw media, tokens, sessions, provider payloads, and real PII. |
</threat_model>
