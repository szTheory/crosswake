<objective>
Give the checked-in iOS host an additive Dev scheme backed by a new Debug-Dev build
configuration that uses Info-Dev.plist (localhost cleartext ATS exception) and a Run
Script copy phase that swaps in the dev fixture at build time (D-01..D-05). The prod
target stays byte-identical; the proof Info.plist and prod fixture are never mutated.

Purpose: ATS / WKAppBoundDomains are plist keys, not Swift, so a code-level if-DEBUG
cannot conditionalize cleartext — a parallel Debug-Dev config + dev plist is the
structurally-correct overlay (Flutter-flavors idiom), with the prod build untouched
(NDEV-01 hard invariant).

Output: Info-Dev.plist; Debug-Dev project + target XCBuildConfigurations; a guarded
Run Script copy phase; a shared Dev.xcscheme.
</objective>

| Debug-Dev config → prod (Debug/Release) posture | The cleartext exception must never leak into the prod build's ATS posture |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-126-01 | Information disclosure | dev cleartext ATS leaking to prod posture | mitigate | Cleartext is scoped to Info-Dev.plist (used only by Debug-Dev); the exception is host-pinned to localhost (no NSAllowsArbitraryLoads); prod Info.plist is byte-untouched (Task 1 verify) and the Plan 04 guard asserts prod plist contains none of the dev ATS keys |
| T-126-03 | Tampering | dev fixture leaking into prod app bundle | mitigate | The dev fixture is NOT added to the prod Resources phase; the Run Script copy is guarded on CONFIGURATION == Debug-Dev so prod (Debug/Release) bundles are unaffected |
| T-126-SC | Tampering | npm/pip/cargo installs | accept | No package-manager installs in this plan — only pbxproj/plist/scheme edits |
</threat_model>
