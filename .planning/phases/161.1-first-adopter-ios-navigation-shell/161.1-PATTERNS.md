## Scope Guardrails

- Compile only sanitized, validated route rows. An empty or incomplete inventory stays `unknown_blocking`; tests use opaque synthetic IDs only.
- Phoenix/manifest truth authorizes every destination; UIKit owns only ephemeral selected-tab and stack state. Browser history and a generic WebView fallback are not navigation authority.
- The transition seam is a new typed, versioned low-frequency contract, separate from `BridgeCommand`; it must carry only opaque route/restoration references and a transition ID.
- iOS host code owns labels, symbols, learner copy, accessibility identifiers, and UIKit presentation. Crosswake core owns topology validation, authorization, compatibility, and stable denials.
- Android is out of scope: do not change Android sources, templates, tests, proof, parity wording, or release requirements. Simulator/XCUITest evidence remains advisory; Phase 162 alone owns physical-iPhone promotion.

```elixir
  @moduledoc """
  Closed, sanitized route-row validation for first-adopter planning inputs.
  ... never supplies route-local safety values from product-surface defaults.

  @route_id_pattern ~r/^route-[0-9a-f]{16}$/

                     :credentials, :account_id, :device_id, :token, :url, ...]
```

**Closed validation pipeline** (lines 88-119):

```elixir
def validate(input) do
  with {:ok, options} <- normalize_input(input),
       :ok <- reject_duplicate_fields(options),
       :ok <- reject_forbidden_fields(options),
       :ok <- reject_unknown_fields(options),
       {:ok, validated} <- NimbleOptions.validate(options, @schema),
       {:ok, route_id} <- validate_route_id(validated[:route_id]),
       :ok <- validate_route_invariants(postures, route_id) do
    {:ok, struct!(__MODULE__, [route_id: route_id, path_pattern: path_pattern] ++ postures)}
  end
end

def promotion_status([]), do: {:blocked, %{reason: :empty_inventory, fields: []}}
```

Use the same non-echoing `ValidationError` style for topology-specific stable errors. The compiler must consume `RouteInventory.validate_inventory/1` and `promotion_status/1`, return `unknown_blocking` for absent/ineligible rows, and never introduce real paths/tab names in source or fixtures.

```swift
public final class ActivationCoordinator: ObservableObject {

    ...

        do {
            let manifest = try loadManifest()
            lastRequest = request
            presentation = resolve(request: request, manifest: manifest)
```

## Shared Patterns

### Authorization and explicit denial

**Source:** `packages/crosswake-shell-core-ios/Sources/CrosswakeShellCore/ActivationCoordinator.swift` lines 358-467

Every destination goes through `resolve(request:manifest:)`, which checks compatibility, active route, external-entry policy, required packs, runtime, and allowlisted origin before yielding a leaf presentation. Route denials are `ShellPresentation.denied`; do not substitute generic WebView navigation or silently preserve an unauthorized candidate.

### Typed/versioned contract and serialization safety

**Sources:** `BridgeChannel.swift` lines 43-106 and `CrosswakeShell.swift` lines 24-82

New protocol structs are `Codable`/`Equatable`, use explicit snake_case `CodingKeys`, compatible version gates, and safe JSON serialization. Host-influenced values never interpolate into JavaScript source.

### Main-actor mutation discipline

**Sources:** `ActivationCoordinator.swift` line 224 and `CrosswakeShell.swift` lines 117-125

UI state is main-actor owned; asynchronous callbacks return through `Task { @MainActor in ... }`. The new coordinator is the sole mutator of selected tab/stack state and must reject stale/duplicate transitions with no active-route change.

### Privacy-safe, deterministic proof

**Sources:** `RouteInventory` lines 45-60; `ProofLane.Evidence` lines 120-139; `IosVerifierTest` lines 44-51

Use opaque IDs and fixed rule IDs. Evidence promotion validates canonical bytes/sources and accepts only the existing closed evidence schema. No sensitive field, URL, raw payload, identity, transcript, or device data belongs in fixtures, assertions, diagnostics, proof output, or support rendering.
