## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Compiled bounded topology

- **D-01:** Compile a versioned `NavigationTopology` with the route manifest from validated sanitized
  route rows only. Entries contain stable opaque `route_id`, `root_tab_id`, closed `root` or `push`
  presentation, optional `parent_route_id`, and closed deep-link/restoration posture. Do not add host
  Swift topology configuration as a second source of route truth. — **Reversibility:** costly — a
  published manifest/topology schema requires a compatibility migration across generated shells and
  host fixtures.
- **D-02:** Fail closed on unknown routes, duplicate roots, cross-tab parents, invalid or cyclic parent
  graphs, unsupported runtime/presentation combinations, and topology/manifest version mismatch. If
  TODO-002 does not validate the needed rows, retain `unknown_blocking` rather than fabricating a
  navigation graph.
- **D-03:** Let iOS own live selected-tab and stack state, while reconstructing deep links or restoration
  only by reauthorizing each destination through the existing activation coordinator and route resolver.
  Invalid reconstruction retains the current safe route or presents the existing explicit denial surface;
  it never falls back to generic WebView navigation.

#### Typed stack synchronization

- **D-04:** Use one low-frequency, typed, versioned web/native transition envelope with a transition ID,
  closed kind (`push_patch` or `push_navigate`), destination route reference, and only an opaque safe
  restoration reference where needed. Dedupe/replay handling keys on the transition ID; no route
  payload, account, device, token, or browser-history state crosses the seam. — **Reversibility:**
  costly — the protocol is consumed by the Phoenix/web client, iOS shell, generated vectors, and host
  proof adapter.
- **D-05:** `push_patch` changes the current web route in its existing container and never grows native
  stack depth. `push_navigate` authorizes the target then creates exactly one native push. Native tab
  selections, native back/edge-swipe pops, deep links, and restoration all use the same coordinator;
  browser history is not native navigation authority.
- **D-06:** Serialize native mutations on the UI/main-actor boundary, reject stale/duplicate/invalid
  transitions without changing the active route, and expose the existing calm, explicit denial rather
  than silently degrading. Phoenix-owned confirmation remains the required fallback; no native
  alert/confirm capability is introduced.

#### Native shell and layout experience

- **D-07:** Implement the bounded graph with a UIKit `UITabBarController` and one
  `UINavigationController` per compiled root tab, wrapped by the existing SwiftUI composition. Lazily
  retain one route container per active stack entry so normal tab return behavior does not lose the
  active web/offline state. The host owns tab labels, SF Symbols, learner copy, and presentation polish;
  Crosswake owns topology, synchronization semantics, and denials.
- **D-08:** At document start, install a non-identifying declarative native-shell marker and safe default
  CSS values before app CSS evaluates. Publish `--cw-safe-area-top`, `--cw-safe-area-right`,
  `--cw-safe-area-bottom`, and `--cw-safe-area-left` independently of
  `--cw-keyboard-inset-bottom`; coalesce layout updates. Never use a custom user agent or expose account,
  route payload, device, or stable identity data.
- **D-09:** Use system tab/navigation appearance, Dynamic Type, 44pt targets, text plus icon/status,
  platform push/pop motion with Reduce Motion respected, and standard light/dark/system behavior. After
  completed navigation use one semantic accessibility focus handoff; do not announce focus or state
  changes merely because insets changed. Host UI keeps learner copy task-oriented and hides shell/backend
  mechanics unless an explicit recovery action needs them.

#### Proof, support truth, and developer experience

- **D-10:** Extend the Phase 159 generated, host-owned proof lane rather than create a demo app or
  parallel navigation harness. Deterministic graph and contract vectors cover topology validation,
  compatibility, restoration input, deduplication, and patch-no-stack-growth. The narrow generated iOS
  host adapter owns XCUITest flows for tabs, navigate/back including edge-swipe, shell marker, insets,
  and accessibility focus.
- **D-11:** Keep simulator/XCUITest results advisory and retained evidence limited to closed assertion IDs
  and outcomes under the existing privacy allowlist. Do not retain URLs, route payloads, navigation
  history, screenshots, device identifiers, transcripts, or raw test output. Phase 162 reuses this
  vocabulary for its dated physical-iPhone evidence; this phase adds no device farm or permanent device
  CI lane.
- **D-12:** Update canonical and generated support truth to state bounded iOS-only shell verification,
  frozen Android posture, and Phoenix-owned confirm/alert fallback with its reversible future condition.
  Developer ergonomics are one Phoenix declaration/compiled artifact, one typed iOS adapter, clear
  stable denials, exhaustive graph vectors, and generated host proof—not a provider-shaped navigation API.

## Summary

Build one contract-driven iOS shell, not a navigation framework: compile `NavigationTopology` beside the Phoenix manifest only from validated TODO-002 rows, validate it before mount, then let a main-actor iOS coordinator materialize the compiled roots as a `UITabBarController` containing one `UINavigationController` per tab. Every root selection, push, interactive pop, deep link, and restoration candidate must enter the existing `ActivationCoordinator`/route resolver before a leaf controller is created or retained. [VERIFIED: 161.1-CONTEXT.md; VERIFIED: packages/crosswake-shell-core-ios/Sources/CrosswakeShellCore/ActivationCoordinator.swift]

The present code has the necessary seams: `CrosswakeShell` owns activation and bridge construction; `ActivationCoordinator.resolve` denies inactive, incompatible, unallowlisted, unsupported, and missing-pack routes before returning a leaf presentation; `LiveViewContainerViewController` already has a same-origin `WKWebView`, document-start scripts, and injection-safe native-to-web reply precedent. The implementation should extend these, keeping a retained leaf container per native stack entry and refusing unknown topology/synchronization input without changing the safe visible route. [VERIFIED: packages/crosswake-shell-core-ios/Sources/CrosswakeShellCore/CrosswakeShell.swift; VERIFIED: packages/crosswake-shell-core-ios/Sources/CrosswakeShellCore/ActivationCoordinator.swift; VERIFIED: examples/ios_shell_host/CrosswakeShell/LiveViewContainerViewController.swift]

**Primary recommendation:** Add a versioned compiled topology plus a narrow main-actor `NavigationCoordinator` in `CrosswakeShellCore`, mount only the resulting bounded UIKit graph in the existing host SwiftUI scene, and extend the Phase 159 generated proof lane with deterministic vectors and advisory XCUITest—not a second Swift configuration model or browser-history-driven navigation. [VERIFIED: 161.1-CONTEXT.md]

### Pattern 1: Compile topology and validate before any UIKit construction

**What:** Decode a topology with a schema/version binding to the compiled manifest; validate every root, push parent, and restoration rule as a closed graph before it can produce a view controller. [VERIFIED: 161.1-CONTEXT.md]

**When to use:** At manifest generation and again at iOS artifact decode; use negative vectors for duplicate roots, cross-tab/cyclic parentage, unknown routes, version mismatch, and unsupported runtime/presentation pairs. [VERIFIED: 161.1-CONTEXT.md]

```swift
// Pattern source: existing ActivationCoordinator.resolve + locked D-01/D-02.
// Do not mount any leaf unless both manifest and topology authorize it.
func loadTopology(_ topology: NavigationTopology, manifest: ShellManifest) throws {
  try topology.validate(against: manifest)
}
```

### Pattern 2: One main-actor transition funnel

**What:** Funnel web transition, tab selection, `UINavigationController` pop, deep link, and restoration through one main-actor coordinator; only the coordinator mutates `selectedIndex` and `viewControllers`. [VERIFIED: 161.1-CONTEXT.md]

**When to use:** Every state-changing input, including interactive-pop completion. Use the container APIs rather than modifying child views directly. [CITED: https://developer.apple.com/documentation/uikit/showing-and-hiding-view-controllers]

```swift
@MainActor
func apply(_ envelope: NavigationTransition) {
  guard protocolIsCompatible(envelope), seenTransitionIDs.insert(envelope.id).inserted else {
    return presentExplicitDenialWithoutStateChange()
  }
  switch envelope.kind {
  case .pushPatch: patchCurrentLeaf(envelope.destination) // no stack mutation
  case .pushNavigate: authorizeThenPushExactlyOnce(envelope.destination)
  }
}
```

### Pattern 3: Document-start stable facts; coalesced live layout updates

**What:** Install the marker and zero/safe default values via a main-frame `WKUserScript` at document start; then publish only numeric insets by safe JSON serialization when `viewSafeAreaInsetsDidChange` or keyboard-frame changes occur. [CITED: https://developer.apple.com/documentation/webkit/wkuserscriptinjectiontime/atdocumentstart; CITED: https://developer.apple.com/documentation/uikit/uiviewcontroller/viewsafeareainsetsdidchange%28%29]

**When to use:** Marker/default properties once per WebKit configuration; layout values when the leaf is visible. Coalesce to the next main-loop turn and drop equal values, so rotation/keyboard animation does not create an event stream. [VERIFIED: 161.1-CONTEXT.md]

```swift
// Safe declarative bootstrap: no UA mutation and no identity facts.
const script = `document.documentElement.dataset.cwNativeShell = "ios";`
let userScript = WKUserScript(source: script, injectionTime: .atDocumentStart,
                              forMainFrameOnly: true)
```

### Pattern 4: Retain a leaf container per stack entry

**What:** Cache a `UIViewController` keyed by the native stack entry, not by mutable path/history, so tab changes preserve current LiveView/offline state while the bounded stack exists. [VERIFIED: 161.1-CONTEXT.md]

**When to use:** After activation succeeds and before native push; release when the entry is actually popped or topology invalidates it. Do not reuse a container across distinct route entries or accounts. [VERIFIED: 161.1-CONTEXT.md]

### Anti-Patterns to Avoid

- **Second topology authority:** Never encode app-specific tabs or paths in host Swift; it defeats manifest compatibility and TODO-002 gating. [VERIFIED: 161.1-CONTEXT.md]
- **WebView/history navigation as native state:** `WKWebView.allowsBackForwardNavigationGestures` is currently disabled; do not turn it into route-stack authority. [VERIFIED: examples/ios_shell_host/CrosswakeShell/LiveViewContainerViewController.swift]
- **In-flight transition optimism:** Do not mark a route active before resolver authorization; duplicates/stale IDs must be explicit no-ops/denials with no route change. [VERIFIED: 161.1-CONTEXT.md]
- **Per-inset accessibility announcements:** Insets are layout facts, not semantic navigation. [VERIFIED: 161.1-CONTEXT.md]
- **Screenshots/raw output as retained proof:** retain only closed assertion IDs/outcomes through the existing privacy-safe evidence lane. [VERIFIED: 161.1-CONTEXT.md]

## Common Pitfalls

### Pitfall 1: Making a topology look complete while TODO-002 remains blocked

**What goes wrong:** Example routes become accidental product truth or host proof activates a fabricated tab graph. [VERIFIED: FIRST-B2C-ADOPTER-ROUTE-POLICY-MAP.md]

**How to avoid:** Ship compiler/validator/schema/vectors that represent missing rows as `unknown_blocking`; use only opaque fixture IDs in tests and do not add concrete route/path facts. [VERIFIED: 161.1-CONTEXT.md]

### Pitfall 2: `push_patch` accidentally creating native history

**What goes wrong:** An in-frame LiveView patch and a native push both occur, making back behavior misleading and state retention incorrect. [VERIFIED: 161.1-CONTEXT.md]

**How to avoid:** Test stack depth before/after every patch vector and expose a coordinator-only method that never touches `UINavigationController.viewControllers` for `.pushPatch`. [VERIFIED: 161.1-CONTEXT.md]

### Pitfall 3: Interactive-pop state drift

**What goes wrong:** The edge-swipe starts, cancels, or completes without updating coordinator state consistently. [ASSUMED]

**How to avoid:** Observe navigation-controller completion, commit active-route change only on completed pop, and test completed edge-swipe separately from canceled gestures. The precise delegate callback/interaction-coordinator mechanics require implementation-time validation against the selected iOS deployment target. [ASSUMED]

### Pitfall 4: Marker/layout timing and unsafe scripts

**What goes wrong:** Marker or default CSS arrives after app CSS; dynamic values use interpolation and admit script injection or identity leakage. [VERIFIED: 161.1-CONTEXT.md]

**How to avoid:** Use `WKUserScript` at document start for fixed source, main-frame-only marker/defaults; pass later numeric insets through the existing JSON serialization boundary. [CITED: https://developer.apple.com/documentation/webkit/wkuserscriptinjectiontime/atdocumentstart; VERIFIED: packages/crosswake-shell-core-ios/Sources/CrosswakeShellCore/CrosswakeShell.swift]

### Pitfall 5: Promoting simulator output to device proof

**What goes wrong:** Successful XCUITest is described as physical-iPhone validation. [VERIFIED: 161.1-CONTEXT.md]

**How to avoid:** Make generated verifier output explicitly advisory, retain only closed assertion IDs/outcomes, and leave physical-device promotion/evidence for Phase 162. [VERIFIED: 161.1-CONTEXT.md]
