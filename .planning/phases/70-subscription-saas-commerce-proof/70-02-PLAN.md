| Provider facade -> reconciliation inbox | Provider-specific evidence enters provider-neutral reconciliation and identity helpers. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-70-05 | Elevation of Privilege | Mock backend verifier | high | mitigate | Verifier is example-host/proof-only, deterministic, and tests assert grant only after `project_snapshot/2` accepts a verified snapshot. |
| T-70-06 | Tampering | Replay/idempotency | medium | mitigate | Replay tests vary correlation ID while preserving provider event identity and assert replay does not create authority. |
| T-70-07 | Information Disclosure | Provider evidence metadata | low | mitigate | Tests use fixed fake IDs and no tokens, receipts, PII, provider payloads, or network calls. |

Do not accept any implementation where `ReconciliationInbox.ingest_evidence/2`, `ProviderAdapterStorefront`, or LiveView callbacks can mutate entitlement authority without `EntitlementProjection.project_snapshot/2` accepting a backend-verified snapshot.
