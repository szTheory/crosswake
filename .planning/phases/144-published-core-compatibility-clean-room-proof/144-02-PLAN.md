## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI argument to Mix task | `--router` names host code loaded by the doctor task. |
| Host source tree to doctor task | Freshly compiled host modules cross into Crosswake diagnostics. |
| Clean-room script to doctor proof | Script setup must not mask whether doctor can load the router itself. |
| Doctor diagnostics to operator | Error copy tells maintainers whether a module is missing or not a router. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-144-06 | Spoofing | `--router` argument | mitigate | Load/compile the requested module and require Phoenix router shape via `__routes__/0` before diagnostics. |
| T-144-07 | Denial of Service | Doctor task requirements | mitigate | Use `app.config`, not `app.start`, so diagnostics do not boot endpoint/database/supervision per D-06. |
| T-144-08 | Tampering | Clean-room script proof order | mitigate | Remove external router preload and add scanner negative fixture for proof masking per D-07. |
| T-144-09 | Repudiation | Router failure diagnostics | mitigate | Emit distinct Mix errors for unavailable module and loaded non-router module per D-09. |
| T-144-10 | Information Disclosure | Doctor output | accept | No secrets are introduced; diagnostic copy names module and readiness state only. |
| T-144-SC | Tampering | package-manager installs | accept | No npm/pip/cargo package installs are added; tests use existing Mix/Phoenix dependencies. |
</threat_model>
