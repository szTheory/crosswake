<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Release Please version output to clean-room script | Package/version input controls registry URL and generated dependency entries. |
| Hex.pm registry to clean-room dependency authority | Registry metadata determines the core floor used by the proof. |
| Hex resolver to proof result | `mix.lock` selected versions determine whether the proof actually installed the intended artifacts. |
| CI logs to operator | Logs communicate package/version/floor state and must not leak secrets or obscure failure states. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-144-01 | Tampering | `script/verify_companion_cleanroom.sh` package/version inputs | mitigate | Allowlist package names and validate semver before URL construction or generated file interpolation per D-03. |
| T-144-02 | Tampering | Hex release metadata | mitigate | Parse JSON structurally and fail closed on 404, version mismatch, retired/unusable state, missing requirement, or malformed metadata per D-01 and D-03. |
| T-144-03 | Spoofing | Hex dependency resolver output | mitigate | Assert `mix.lock` selected exact companion version and selected `crosswake` satisfies the derived floor per D-04. |
| T-144-04 | Information Disclosure | clean-room logs | mitigate | Keep `[crosswake]` output to package, version, floor, selected core, state, and next action; never print registry tokens or secrets per D-19 and D-20. |
| T-144-05 | Denial of Service | missing live packages | mitigate | Fail closed with package/version-specific copy rather than skipping package-family coverage per D-03 and D-15. |
| T-144-SC | Tampering | package-manager installs | accept | No npm/pip/cargo install tasks are introduced; the script uses existing Bash, curl, Mix, Hex, and Python stdlib tooling. |
</threat_model>
