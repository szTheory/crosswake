<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| universal links and app entry -> iOS activation pipeline | Untrusted URLs cross into native routing and WebKit mounting decisions |
| allowed route decisions -> `WKWebView` container | If same-origin checks drift, web content can gain broader authority than declared |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-09 | S | `ActivationCoordinator.swift.eex` | mitigate | Normalize cold start and universal links into typed activation requests before creating a web container |
| T-03-10 | T | `LiveViewContainerViewController.swift.eex` | mitigate | Gate `WKWebView` navigation to allowlisted same-origin routes and mount only after native approval |
| T-03-11 | D | `RouteUnavailableView.swift.eex` | mitigate | Use explicit denial UI and safe recovery actions so blocked routes do not trigger partial or looping boot behavior |
| T-03-12 | E | iOS route activation flow | mitigate | Keep route ownership in the manifest-driven native coordinator rather than page JavaScript or a second path-rule system |
</threat_model>
