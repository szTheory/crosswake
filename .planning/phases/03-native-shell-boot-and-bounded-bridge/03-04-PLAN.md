<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| launcher intents and App Links -> Android activation pipeline | Untrusted URLs cross into native route resolution and WebView decisions |
| allowed route decisions -> Android WebView | If origin or active-route checks drift, web content can obtain broader access than declared |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-13 | S | `ActivationCoordinator.kt.eex` | mitigate | Normalize all app entry intents into typed activation requests before any `WebView` work begins |
| T-03-14 | T | `LiveViewFragment.kt.eex` | mitigate | Gate `WebView` setup to allowed routes and allowlisted origins only, never generic page-driven routing |
| T-03-15 | D | Android denial UI | mitigate | Keep blocked routes on a Crosswake-owned interruption surface with safe recovery actions instead of retry loops or partial loads |
| T-03-16 | R | Android proof claims | mitigate | Require the generated-project verification hook to provision or find the Android toolchain and fail if runtime proof cannot complete so the repo never ships an unproven Android boot claim |
</threat_model>
