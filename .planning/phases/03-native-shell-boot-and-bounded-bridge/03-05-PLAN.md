<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| web content -> native bridge channel | Untrusted page messages cross from web content into native capability execution |
| manifest registry -> platform bridge adapters | If native adapters bypass manifest truth, undeclared capabilities can execute |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-17 | S | `lib/crosswake/bridge/contract.ex` | mitigate | Require explicit route, origin, capability, version, and correlation fields in every request so callers cannot spoof context-free capability access |
| T-03-18 | E | `lib/crosswake/bridge/registry.ex` | mitigate | Derive allowlists from manifest registry plus route declarations per D-16 instead of native-only registration |
| T-03-19 | T | platform bridge-channel templates | mitigate | Limit channels to the three Phase 3 commands and request or reply semantics so they cannot expand into a generic message bus |
| T-03-20 | D | bridge denial path | mitigate | Return typed denials and block side effects on any failed check so blocked requests cannot partially execute native behavior |
</threat_model>
