Status: proposed; no requirement is completed and no implementation phase is active. [SUMMARY.md](SUMMARY.md) owns the coherent selected direction. The earlier private proposal's research-skip choice is superseded by the user's explicit research-first request.

## IOS: host setup without hand patches

- [ ] **IOS-01:** Maintainer can declare iOS host build inputs once through ordinary Phoenix/Mix configuration, generate/regenerate supported outputs without unrelated runtime-server credentials, and retain host-owned native edits. Nonwriting check/diff identifies stale output and ownership conflicts without exposing private values.
- [ ] **IOS-02:** Maintainer can generate app and proof-test identity/signing projections and verify their effective Xcode settings in simulator/device modes without editing project internals. Simulator checks need no Apple credentials; device settings inspection does not claim signed-device installation.
- [ ] **IOS-03:** Maintainer can bundle the selected host route declarations, entry route and primary origin through the canonical manifest/static-activation path; missing/example production origin, invalid route/input or interrupted generation fails closed. Generated activation grants no session, scope or replay authority.

## TWIN: bounded reference demonstration

- [ ] **TWIN-01:** Maintainer can run one documented automated reference demonstration that binds the actual generated candidate, visible study WebView/bridge, selected dependency/assets and owned Phoenix backend to the expected source/run. Browser-only, contract-only and generated-iOS observations remain distinguishable.
- [ ] **TWIN-02:** Maintainer can observe verified installed media playback initiated by the actual visible offline-island action through the host-owned native adapter, selected/free-form offline persistence and true app terminate/relaunch without resetting storage. Network denial is verified at the tested target.
- [ ] **TWIN-03:** Maintainer can observe the normal app's authorized reference replay, actual Ecto effect idempotency under duplicate delivery and empty outbox. Synthetic fixture authority is explicit and grants no real-adopter identity claim.
- [ ] **TWIN-04:** Maintainer can demonstrate real server-backed rejection/conflict recovery, logout/account-switch replay fencing, entry/replay disablement with retained work and missing/corrupt-media denials through controlled run-owned fault cases. Learner-visible status/recovery reflects the actual durable state.
- [ ] **TWIN-05:** Maintainer can inspect a closed, source-bound, privacy-safe twin receipt covering the complete required scenario/observation roster, retaining actual failure/unavailable causes; fabricated, missing, stale, sensitive or mismatched observations cannot pass or promote physical/adopter claims.
- [ ] **TWIN-06:** Maintainer can see all ten bounded scenario-group outcomes, fidelity limits, failed/blocked work and residual external gates in one handoff. Work stops at the declared boundary; required virtual checks must pass for completion and broader core/runtime work is not silently added.

## Design acceptance constraints

The canonical T01–T10 roster is in SUMMARY.md. Cold boot/origin/source/visible-WebView checks are preconditions, not an extra scenario. Per-case required observation ownership is fixed before execution; no case can inherit a pass from a different runtime. Native audio ownership follows MEDIA-OWNERSHIP-RESOLUTION.md; build config loading follows CONFIG-LOADING-RESOLUTION.md.

Reuse current browser fixtures and existing example database engine; the new run owns its own DB/server/port/files. No lifecycle reset between offline writes, app termination and replay. Stable new generation/receipt regressions belong in existing relevant CI lanes; a full recurring simulator workflow is not selected.

Accessibility and current-brand copy are acceptance properties of necessary study/recovery states: semantic controls/status text, visible focus, adequate touch targets, usable system themes/reflow and reduced motion. They do not authorize a design-system or showcase sprint.
