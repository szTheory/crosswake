# Feature Research

**Domain:** Honest offline-sync E2E testing — CI Honesty / Real-E2E Sweep (v12.0)
**Researched:** 2026-06-17
**Confidence:** HIGH (code read directly; patterns verified against Playwright docs and IndexedDB sync literature)

---

## Background: What "Honest" Means Here

The existing `offline_sync.spec.ts` is structurally dishonest in two ways:

1. **The mutation bypass.** It injects into `window['crosswake_offline_mutations']` — an array the app code never reads or writes. The real app code path is `offline_study.js` → `queueMutation()` → IndexedDB `mutations` store. Nothing in the test touches that path.

2. **The flush bypass.** It manually calls `fetch('/study/sync', ...)` from `page.evaluate`. The real outbox consumer does not exist yet in JS: `offline_study.js` has `queueMutation()` but no reconnect listener and no flush loop. `StudySessionLive` line 31 says "here we mock it" — its `sync_outbox` handler constructs a payload from LiveView socket assigns, which are not the IndexedDB mutations the user created.

A test is **honest** when every step of the system-under-test (SUT) chain is exercised by real code, not test scaffolding. The distinction between legitimate and illegitimate stubs is:

- **Legitimate stub:** replaces an *external dependency* that cannot run in the test environment. The `IDBObjectStore.prototype.add` override to force `QuotaExceededError` in `offline_storage.spec.ts` is legitimate — you cannot trigger that condition in a real browser without filling actual disk, and the SUT code (`queueMutation` error path) is fully exercised.
- **Illegitimate bypass:** replaces a *step in the SUT* so that the test passes even if that step is broken or absent. Writing to `window['crosswake_offline_mutations']` and manually calling `fetch` are illegitimate because if `offline_study.js`'s `queueMutation` broke, the test would still pass.

## Feature Landscape

### Table Stakes (Must Have for an Honest E2E)

| Feature | Why Required | Complexity | Notes |
|---------|--------------|------------|-------|
| **Real app-code mutation path** | Test must prove IndexedDB `mutations` store receives the write via `queueMutation()` in `offline_study.js` — not via injected JS | MEDIUM | Requires clicking a real UI button (`#btn-flip`, `#btn-pass`) while `context.setOffline(true)`; this triggers `handleReview()` which calls `queueMutation()` |
| **IndexedDB intermediate assertion** | After the click but before reconnect, assert the mutation is in the `mutations` store — proves the SUT persisted it, not the test | MEDIUM | Use `page.evaluate` wrapping a Promise around `IDBObjectStore.getAll()` with `tx.oncomplete`; this is a legitimate use of `page.evaluate` because it is *reading* the SUT's own storage, not *writing* to it |
| **Real reconnect-driven flush handler in `offline_study.js`** | The app must contain JS that reads from the real IndexedDB store and POSTs to `/study/sync` when connectivity returns — this code does not exist today | HIGH | This is the required app change. Options: (a) `window.addEventListener('online', flushOutbox)` in `offline_study.js`, (b) LiveView Hook `reconnected()` callback. The Hook is the preferred primary because it fires after the Phoenix socket reconnects, not just after the network returns. Both should be implemented. |
| **No test-injected flush trigger** | `context.setOffline(false)` is the only reconnect signal the test sends; the app's own JS listener must observe it and trigger the flush | LOW | Playwright's `context.setOffline(false)` sets `navigator.onLine = true` and fires the `online` event in the page — the SUT listener will see it |
| **Backend Ecto assertion via `/_e2e/sync-state/:id`** | Proves the full loop closed: mutation in → IndexedDB → app flush → `/study/sync` → Ecto | LOW | Endpoint already exists; `expect.poll` pattern in the current test is already correct |
| **`client_mutation_id` read from SUT, not generated by test** | The idempotency key must be the UUID generated by `offline_study.js` at `queueMutation` time — if the test generates it, a broken UUID format in the SUT goes undetected | LOW | After the IndexedDB intermediate assertion, read the UUID from the returned record; use that UUID for the `/_e2e/sync-state/` lookup |
| **Remove `window['crosswake_offline_mutations']`** | The array is never used by the app; its presence makes the test's intent ambiguous and is actively misleading | LOW | Delete from the spec; no app code references it so no app changes required |
| **Remove test-initiated `fetch` call** | The `page.evaluate(fetch('/study/sync', ...))` bypass is the illegitimate flush trigger | LOW | Delete from the spec; replace with `context.setOffline(false)` only |

### Differentiators (Valuable Once Table Stakes Are Met)

| Feature | Value Proposition | Complexity | Notes |
|---------|-------------------|------------|-------|
| **Outbox-cleared-after-sync assertion** | After the flush, assert IndexedDB `mutations` store is empty — proves the app cleans up after success | LOW | A `page.evaluate` read after the `/_e2e/sync-state/` poll passes; natural extension of the intermediate assertion |
| **Duplicate-flush idempotency test** | POST the same `client_mutation_id` twice; assert Ecto row count is 1, not 2 — validates `ON CONFLICT DO NOTHING` on the sync controller | MEDIUM | Requires the sync controller to already implement idempotency (`on_conflict: :nothing`); surfaces this as a verified guarantee not just an assumption |
| **LEDG-01 closeout gate tightening** | The carried Nyquist debt from v8.0; tighten the validation-ledger closeout gate to reject plans that haven't validated E2E requirements | MEDIUM | Tracked since v8.0; natural to ship alongside CI honesty work; independent of the sync loop |
| **Double-flush race assertion** | Trigger two rapid reconnects and assert only one sync POST fires (or both fire but Ecto count remains 1) — guards against retry storms | HIGH | Requires an in-flight guard in the flush handler; defer unless the duplicate test surfaces actual races |
| **Offline-while-flushing resilience** | Go offline mid-flush; assert the mutation is NOT removed from IndexedDB and is retried on next reconnect — models the `IN_FLIGHT → RETRYABLE_ERROR` state | HIGH | This state machine has real-world value but is a separate concern from proving the happy path; defer to v13 |

### Anti-Features (Explicitly Exclude)

| Feature | Why Requested | Why It Stays Out | Correct Alternative |
|---------|---------------|------------------|--------------------|
| **Mock the fetch POST in the flush test** | Avoids depending on a running Phoenix server | Makes the test prove nothing about the backend path — the point is the full loop | Use `mix phx.server` in CI; the example host already runs in existing E2E lanes |
| **Test-injected `client_mutation_id`** | Gives test control over the ID to look up | Bypasses SUT ID generation; a broken UUID format in `offline_study.js` goes undetected | Read the UUID from IndexedDB after the click using `page.evaluate` |
| **`window['crosswake_offline_mutations']` array** | Simple way to simulate mutations | App never uses this array; it is a fake parallel system that proves nothing about the SUT | Delete entirely; use `page.evaluate` reads of the real IndexedDB `mutations` store |
| **Manual `fetch` from `page.evaluate` as flush trigger** | Proves the backend sync endpoint is reachable | Bypasses the app's reconnect handler — if that handler is broken or absent, the test passes anyway | Delete it; `context.setOffline(false)` + the SUT's `online` event listener / LiveView Hook must be the only trigger |
| **Service Worker Background Sync API** | Web standard for offline queue flush | Not reliably controllable via Playwright CDP for sync-triggered testing; adds build complexity with no benefit over the `online` event pattern | Use `window.addEventListener('online', flushOutbox)` + LiveView Hook `reconnected()` |
| **Generic sync framework (PouchDB, RxDB, etc.)** | Reduces implementation effort | Crosswake's anti-scope is "magical offline guarantees"; importing a sync library contradicts the explicit-contract thesis | Keep the IndexedDB outbox + `/study/sync` endpoint pattern already in place |

## Legitimate vs Illegitimate Stub Taxonomy

This is the decision rule for every E2E test in this codebase going forward.

### Legitimate (Keep or Add)

| Stub | What It Replaces | Why Legitimate |
|------|-----------------|---------------|
| `IDBObjectStore.prototype.add` override to force `QuotaExceededError` | Disk quota exhaustion | Cannot exhaust real disk in CI; SUT error-handling code path is fully exercised |
| `navigator.storage.estimate()` override to return low bytes | Storage estimate API | Simulates OS-reported quota; SUT budget-check logic is fully exercised |
| `page.evaluate(indexedDB.open(...).getAll(...))` to read mutations | None — this is inspection | Reading SUT's own IndexedDB state is observation, not injection; equivalent to `Repo.get` in a unit test |
| `expect.poll(/_e2e/sync-state/:id)` | None — this is assertion | Polling a backend verification endpoint is a test assertion, not a stub |

### Illegitimate (Remove)

| Stub | What It Bypasses | Why Illegitimate |
|------|-----------------|-----------------|
| `window['crosswake_offline_mutations'] = [...]` injection | `offline_study.js` `queueMutation()` → IndexedDB write path | App never reads this array; SUT mutation path is never exercised |
| `page.evaluate(fetch('/study/sync', ...))` | App's reconnect flush handler | If the flush handler is broken or absent, the test still passes |
| Test-generated `mutationId` used directly in `/_e2e/sync-state/` lookup | SUT `client_mutation_id` generation | If `offline_study.js` generates a malformed UUID, test still passes because it never checks the SUT's output |

## Reconciliation Loop Completeness Checklist

A test that asserts all of these gates a complete, honest reconciliation loop:

1. **Offline confirmed:** `context.setOffline(true)` before user action; `navigator.onLine` is `false`
2. **SUT mutation path exercised:** User clicks `#btn-flip` then `#btn-pass`; `handleReview()` in `offline_study.js` runs, calling `queueMutation()`
3. **IndexedDB write confirmed:** `page.evaluate` reads `mutations` store and finds exactly one record; `client_mutation_id` UUID is extracted from that record
4. **Reconnect triggered by test only:** `context.setOffline(false)` — no other trigger from the test
5. **SUT flush handler fires:** App JS `online` listener or LiveView Hook `reconnected()` reads IndexedDB and POSTs to `/study/sync` — no test-initiated `fetch`
6. **Backend reflects the mutation:** `expect.poll(/_e2e/sync-state/:extractedId)` returns `{synced: true}` within timeout
7. **(Differentiator) Outbox cleared:** `page.evaluate` reads `mutations` store and finds zero records

## Required Application Changes

These changes are **required** before an honest test can be written. The test as rewritten will fail without them.

### 1. Add `flushOutbox()` to `offline_study.js`

A function that reads all records from the IndexedDB `mutations` store, POSTs them to `/study/sync`, and on success deletes them from the store. The function must be registered on the `online` event:

```javascript
window.addEventListener('online', flushOutbox);
```

This function does not exist today. Both `page.evaluate(fetch(...))` in the test and `StudySessionLive.sync_outbox` were papering over its absence.

### 2. Add a LiveView Hook `reconnected()` callback

Wire a Hook to the offline study island container element. In `reconnected()`, call `flushOutbox()`. This fires after the Phoenix socket reconnects — the correct primary flush point because the server is confirmed reachable at that moment:

```javascript
Hooks.OfflineIsland = {
  reconnected() { flushOutbox(); }
};
```

The `online` event is a secondary trigger. The Hook is primary because it fires after socket reconnect, not just after network return. The `_phx_hook="OfflineIsland"` attribute needs to be added to the offline island container in the relevant template.

### 3. Remove or isolate `StudySessionLive.sync_outbox`

The `sync_outbox` event handler in `study_session_live.ex` reads from the LiveView socket assigns (an in-memory list), not from IndexedDB. It was always a mock. Once the JS flush handler is real, either delete this handler or clearly scope it as a demo-only UI convenience that does not interfere with the real offline test. It must not be the flush mechanism the test relies on.

### 4. Confirm sync controller idempotency

The `/study/sync` controller must use `on_conflict: :nothing` (or equivalent `ON CONFLICT (client_mutation_id) DO NOTHING`) when inserting events into Ecto. Without this, the duplicate-flush differentiator test will surface silent data doubling. This may already be in place — verify before writing the idempotency test.

## Feature Dependencies

```
[Real reconnect flush handler in offline_study.js]
    └──required-by──> [No test-injected flush trigger]
                          └──required-by──> [Honest E2E sync test]

[IndexedDB intermediate assertion]
    └──required-by──> [Read client_mutation_id from SUT, not from test]
                          └──required-by──> [Honest E2E sync test]

[Honest E2E sync test]
    └──required-by──> [Backend Ecto assertion via /_e2e/sync-state/]

[Merge-blocking CI gate]
    └──required-by──> [Honest E2E sync test passes in CI]

[Duplicate-flush idempotency test]
    └──requires──> [Honest E2E sync test passes first]
    └──requires──> [Sync controller on_conflict: :nothing confirmed]

[Outbox-cleared-after-sync assertion]
    └──requires──> [Honest E2E sync test passes first]

[LEDG-01 closeout gate tightening]
    └──independent — parallel deliverable, no sync dependency]
```

### Dependency Notes

- **Real reconnect flush handler must exist before the test is rewritten.** The test rewrite and the app change are not independent — write `flushOutbox()` first, verify it works manually, then rewrite the test against it.
- **`client_mutation_id` read from IndexedDB depends on the intermediate assertion existing.** The same `page.evaluate` call that proves the write happened also extracts the UUID for the backend assertion.
- **Sync controller idempotency is required for the duplicate-flush test but not for the basic honest test.** The basic test does not re-POST; idempotency becomes important only when retry behavior is tested.

## MVP Definition

### Launch With (v12.0 — Required for CI Honesty Gate)

- [ ] **Real reconnect flush handler in `offline_study.js`** — `flushOutbox()` triggered by `window.addEventListener('online', ...)` and LiveView Hook `reconnected()` callback
- [ ] **Remove `StudySessionLive.sync_outbox` mock** — delete or clearly isolate; not the flush mechanism
- [ ] **Rewrite `offline_sync.spec.ts`** — delete all `window['crosswake_offline_mutations']` injection; delete manual `fetch` from `page.evaluate`; click real UI buttons while offline; assert IndexedDB write; assert `/_e2e/sync-state/:id` after reconnect
- [ ] **`client_mutation_id` read from IndexedDB after click** — not generated by the test
- [ ] **Merge-blocking CI gate** — rewritten spec runs in required CI lane; blocks merge on failure

### Add After Validation (v12.x)

- [ ] **Outbox-cleared-after-sync assertion** — assert `mutations` store is empty after flush; low complexity followup
- [ ] **Duplicate-flush idempotency test** — POST same payload twice; assert Ecto row count is 1; verify `on_conflict: :nothing` is actually in place
- [ ] **LEDG-01 closeout gate tightening** — tighten validation-ledger closeout gate; independent of sync test; carried from v8.0

### Future Consideration (v13+)

- [ ] **Offline-while-flushing resilience test** — interrupts flush mid-POST; verifies mutation stays in IndexedDB for retry; high complexity
- [ ] **Double-flush race assertion** — two rapid reconnects; guards retry storm; high complexity
- [ ] **NTV-01 native disk-space budgets** — native iOS/Android bridge commands for physical disk space; carried from v8.0
