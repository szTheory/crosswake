# v3.5 First-Party Companions — Research Summary

> Milestone-scoped research synthesis for v3.5. Consumed by the roadmapper and phase planners. Companion full plan: `~/.claude/plans/candidate-v3-5-first-party-companions-glimmering-kite.md`.
> Scope decided: **Wedge + first generalization** (rulestead full seam + rindle full seam + sigra contract-only), **in-tree first, extract later**.

## Thesis

v3.5 builds explicit, bounded **integration seams** between Crosswake and existing szTheory Elixir libraries — not features from scratch. The five candidates: `rulestead` (flags/rollout/kill-switches), `sigra` (auth), `rindle` (media), `chimeway` (notifications), `threadline` (audit). v3.5 locks a reusable companion-seam pattern across two real companions and ships the auth-context contract that unblocks the rest.

## The single biggest finding: the companion seam IS the commerce seam, generalized

`Crosswake.Commerce` is already a 4-callback **behaviour** over typed contract structs with closed atom vocabularies and `validate_*/1 :: :ok | {:error, kw}` validators. `RouteGate.evaluate/4` already turns layered findings into `Denial`s (`status = if(denials == [], :allow, :deny)`) with a `prepend_commerce_corridor_findings/3` short-circuit hook. `SupportMatrix` already declares a `:companion` release boundary. **~80% of the companion architecture is pre-committed by the commerce precedent** — which is exactly why rulestead can lock the reusable pattern under low risk.

## Recommended companion-seam architecture (idiomatic Elixir, grounded)

- **A `Crosswake.Companion` behaviour** generalized from `Crosswake.Commerce`. Behaviour — NOT a Protocol (protocols dispatch on data type; a companion is a named one-impl-per-host integration), NOT telemetry-as-seam (can't return a denial → silent fail-open). Precedent: Ecto adapters, Swoosh/Bamboo, Oban engines, Tesla middleware, Logger backends, Plug.
  - Callbacks: `companion_id/0`, `enabled?/1`, `route_gated?/2`, `kill_switch_active?/1`, `validate_dependency/0 :: :ok | {:error, [module]}` (Swoosh precedent), `report_state/0` (typed struct for doctor + support matrix).
- **Optional-dependency handling, 3 layers:** `optional: true` dep + compile-time `Code.ensure_loaded?/1` gate around the **module body** (NOT around `use` — elixir-lang#8970) + runtime `validate_dependency/0`. Enabled-but-missing must fail **closed** with a doctor `:error` finding, never a silent no-op. Footgun: `optional: true` is not transitive — the top-level host must add the real dep; doctor must say so plainly.
- **Packaging:** idiomatic end-state is a separate hex package per companion (ecto/phoenix/oban precedent; matches the pre-declared `:companion` release boundary). **v3.5: in-tree first** under `lib/crosswake/companions/<name>/` to avoid multi-package release plumbing while the pattern stabilizes; extraction deferred. The external `rulestead`/`rindle`/`sigra` libs are the `optional: true` deps regardless of in-tree vs extracted.
- **Config in the host app, pointed at a host impl module** (Repo/Mailer/Oban pattern). Route opt-in flows through the **existing route-policy DSL**, never a parallel mechanism — preserving "per-route ownership stays authoritative; a companion can gate but never override."
- **All failure modes surface as fail-closed `Crosswake.Doctor.Check` findings + support-matrix rows, enforced by docs-contract tests** (template: `test/crosswake/guides/commerce_test.exs`). Telemetry: `[:crosswake, :companion, …]` spans from core, static event names, differentiate via `companion_id` metadata (Keathley conventions).

## Rulestead seam — the deliberate low-risk wedge

- **The flag is an INPUT to gating, never the authority.** rulestead contributes one more class of **denial finding** (`:gate_denied`, `:kill_switch_active`) into the existing `RouteGate` pipeline. A gate can only *further restrict*, never open a capability route policy already denied. (Mirrors LaunchDarkly's prerequisite-as-input model.)
- **Two-layer evaluation (the crux of mobile reality):** the *binding* is build-time (`gated_by` on `RouteEntry` in the manifest — auditable, offline-verifiable); the *value* is runtime (local ETS-style snapshot, FunWithFlags pattern — no network in the hot path). Honest answer to "kill a capability without a native rebuild": manifest records the binding, live value flips server-side.
- **Fail-closed default** (`on_unavailable: :deny`), mandatory for kill switches and `security: :sensitive` routes. One explicit, opt-in, doctor-audited carve-out: `on_unavailable: :fallback_phoenix` when the fallback is a fully-owned Phoenix route. Kill switches always fail-closed and **short-circuit first** (prepend, like commerce corridors).
- **Explainability:** adopt OpenFeature's evaluation-details vocabulary (`reason` ∈ STATIC/DEFAULT/TARGETING_MATCH/SPLIT/DISABLED/STALE/ERROR, `variant`, `flag_key`, `evaluated_at`) inside `Denial.details` + a new doctor category — answering "why was this gated?" at shell-time and CI-time. **rulestead-direct evaluation + OpenFeature-shaped data** (don't hard-depend on the `0.x` OpenFeature Elixir SDK; keep the data contract portable so a future `crosswake_openfeature` slots into the same behaviour).
- **Support-matrix honesty:** runtime gate-state dimension (`gated` / `rolling_out (N%)` / `killed`) labeled runtime-distinct-from-build-proof; never conflate "10% rollout" with "supported."

### Cross-ecosystem Right / Wrong / Footguns (flags)
- LaunchDarkly: ✓ evaluation reasons, prerequisite-as-input; ✗ flag tech debt at scale.
- OpenFeature (CNCF): ✓ vendor-neutral `EvaluationDetails`; ✗ Elixir SDK is `0.x` (too early to hard-depend for the first seam).
- Unleash: ✓ local eval + bootstrap from cache (no startup network); ✗ client `localStorage` staleness; needs stable bucketing key.
- Statsig: ✓ deterministic in-app hashing; ✗ auto-exposure-logging hot-path cost (make telemetry opt-in/async).
- FunWithFlags (Elixir incumbent): ✓ ETS cache + persistence + PubSub invalidation + deterministic %-of-actors (the exact local-snapshot architecture); ✗ no built-in evaluation-reason output (Crosswake must add explainability).
- Industry: ✗ network in hot path; ✗ fail-OPEN defaults causing incidents; ✗ flag spaghetti / stale flags / type-unsafe flags.

## Rindle media seam — the generalization proof

- **Seam shape:** `UploadGrant` (presigned target, expiry, max_bytes, accepted_types, key_prefix, idempotency_key) + `CaptureEvidence` (device-reported hash/size/mime — **evidence only**) + `MediaObject` lane (`:queued|:uploaded|:scanning|:available|:rejected`). Backend-owned non-authoritative **reconciliation vocabulary mirroring `Crosswake.Commerce.Reconciliation`** — device "uploaded" is evidence; backend verify (scan/variant/hash) → `:available`. **This is why rindle is the cleanest generalization proof: it's near-isomorphic to the proven commerce reconciliation flow.**
- **Bridge carries grant request + state transitions only — NOT chunk-by-chunk progress** (progress stays native-local; honors "not high-frequency messaging").
- **Offline** modeled only as `:queued` evidence with a narrow typed promise; never present queued media as committed (cached-read ≠ local-first mutation).
- Cross-ecosystem: ✓ tus resumable + S3 multipart (flaky mobile networks), presign bound to content-type/size/prefix + re-signed right before upload (Uppy #1724 expiry footgun), scan-before-publish gating, strip EXIF/PII. ✗ unauthenticated/over-broad presigns, no idempotency → duplicate objects on mobile retry storms, server proxying bytes (memory). Sources: Uppy/tus, ActiveStorage, Waffle, Phoenix LiveView external uploads, ClamAV gating.

## Sigra auth seam — contract-only slice (v3.5), machinery deferred

- **v3.5 ships contract + route gate ONLY:** `AuthContext` (actor_id/org_id/mfa_level/auth_age) + `SessionAuthorityLane` (backend-set only) + `StepUpChallenge` type + route auth predicates (`auth_min_level`/`requires_recent_auth`) wired into `RouteGate` as fail-closed `:step_up_required` denials. **NO handoff tickets, step-up ceremony, or passkey machinery — deferred to v3.6 with dedicated security attention.** Rationale: auth is the highest-blast-radius surface (security-incident class); the contract is cheap and unblocks chimeway/threadline, but the machinery must not be built inside a pattern-proving milestone.
- Cross-ecosystem (informs the deferred machinery): OAuth Auth-Code + PKCE for native; single-use short-TTL session-handoff tickets (never share tokens into WebView localStorage); native passkey APIs over WebView; refresh-rotation needs a ~30s grace window or it false-positives on mobile background/resume (Auth0/Lucid). Sources: phx.gen.auth, Pow, Guardian, Assent/Ueberauth, Curity/Ping handoff, Corbado passkeys.

## Deferred to v3.6+ (recorded as sequencing, not built in v3.5)

- **chimeway** — seam-only (push-token + deep-link-to-route resolver), NOT first-party delivery (delivery is commoditized — Knock/Courier/Novu/Pigeon — and imports provider lock-in). Footgun to invert: deep links that silently fall to home / bypass auth on route mismatch (FlutterFlow). Hard-depends on sigra `AuthContext`.
- **sigra machinery** — handoff tickets, step-up, passkey escape hatch.
- **threadline** — capstone audit seam: route/runtime **decision** observability + `ProvenanceLane` (device_claimed evidence vs backend_accepted authority) for offline-replay attribution. Footguns: PII in append-only logs (GDPR), `Ecto.Multi` atomicity, hash-chaining detects ≠ prevents tamper. Consumes the other three's contracts → build last.

## Cross-dependency DAG
`sigra-contract` unblocks everything → `rindle` is independent enough to lead the generalization proof → `chimeway-seam` needs `sigra-contract` → `threadline` needs all three. Dependency order and risk gradient agree.

## Watch out for
- Silent fail-open when a companion is enabled-but-missing (the single most dangerous outcome) — mandate `validate_dependency/0` → doctor `:error`; test the absence path in a hermetic no-dep CI lane.
- Wrapping `use`/macros in `Code.ensure_loaded?` (elixir-lang#8970) — gate module **bodies** instead.
- `optional: true` non-transitivity — host app must add the real dep; doctor says so.
- Letting a companion override route ownership — `route_gated?/2` returns evidence the policy compiler consumes; ownership stays authoritative.
- Config-key / denial-code drift across guide ↔ doctor ↔ support matrix — enforce parity with docs-contract tests.
- Building threadline/chimeway against moving contracts — sequence them after their dependencies are stable.
