## Tech Debt (post-audit follow-up, 2026-06-30)

The audit's "minor flaky test" turned out to be the **CI blocker** on PR #40 — its first real CI run reddened the merge-blocking lanes. Two real fixes shipped; two items assessed and deliberately left.

1. **RESOLVED — `File.cd!` race (was the CI blocker, not minor)** (134). `crosswake_shell_status_test.exs` `File.cd!` under `async:true` raced with the concurrent `crosswake_gen_shell_test.exs` (CWD-relative `_build` template path), reliably reddening every broad-`mix test` lane (core/rindle/rulestead/commerce/gating) as a misattributed parallel-compile error. Fixed → `async:false`. Repro: CI command 3/3 fail before, 0/3 after.
2. **RESOLVED — android lane missing `mix deps.get`** (134). `android-generated-shell-unit`'s first-ever real run failed with `Can't continue due to errors on dependencies` (verify script calls `mix crosswake.gen.shell` with no deps fetched on a fresh checkout). Added the `mix deps.get` step. The shift-left automation caught a real setup bug, exactly as intended.
3. **ASSESSED, DEFERRED — TELEM-04 Side B vacuity** (133). Robust fix is fragile (computed event names, no `:telemetry` wildcard) and the declared set is built from the same source emitters use → divergence structurally near-impossible (0 undeclared events confirmed). Not worth a fragile test on a green merge-blocking lane. Revisit only if emission ever bypasses `event_names/0`.
4. **ASSESSED, NOT A BUG — compat prose** (132). `companion_compatibility.md:51-54` describes real engine-pin friction (engine 1.0.0 vs requirement `~> 0.1`), not a contradiction with the requirement cell. No correct edit; drift test unaffected. Left as-is.

(Also de-noised: the `aggregator-negative-control` workflow was redesigned from 7 jobs with intentionally-red helpers — which turned the whole run red and cluttered the PR check list every PR — to one clean green job proving the same alls-green fail-on-failed/skipped semantics.)
